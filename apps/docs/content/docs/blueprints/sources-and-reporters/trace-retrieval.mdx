## Capability Summary

Retrievers let a configured Trace Destination expose remote trace search through the CLI.

## Architecture Decision Records

### ADR-001: Keep portable search in the CLI

**Decision:** `agentscope traces search --destination <name>` always names exactly one configured Trace Destination. The CLI owns portable filters and presentation; the retriever maps those filters to destination APIs and declares unsupported filters.

**Context:** Users and coding agents need explicit, deterministic semantics while providers differ in query vocabulary, identity, and pagination. Implicit defaults or silent fan-out would make an investigation query ambiguous.

**Consequences:** There is no default retrieval destination and no implicit multi-destination search. Any aggregate search requires its own deduplication, ordering, pagination, and partial-failure contract.

### ADR-002: Do not emulate unsupported retrieval

**Decision:** A Trace Destination without a retriever returns an explicit capability error rather than presenting local diagnostics as destination history.

### ADR-003: Treat retrieved data as untrusted input

**Decision:** Retriever packages return bounded untrusted provider DTOs. Core validates schema and size, normalizes a portable summary, reapplies the active redaction policy and summary-field allowlist, and constructs a branded safe retrieval result. CLI presentation accepts only that safe type and escapes terminal-control content.

**Context:** A destination can return historical traces from another producer, an older policy, or malformed/hostile content.

**Consequences:** Retrievers cannot return presentation-ready strings. Provider-native bodies never enter output or retained diagnostics. Tests cover oversized, malformed, legacy, sensitive, and control-character responses; structured output is versioned from the safe portable DTO.
