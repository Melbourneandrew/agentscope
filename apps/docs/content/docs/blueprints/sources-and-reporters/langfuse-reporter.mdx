## Capability Summary

Langfuse is a first-party Trace Destination using OTLP delivery.

## Architecture Decision Records

### ADR-001: Use OTLP delivery

**Decision:** The Langfuse reporter sends the OpenInference-compatible canonical OTLP graph to a configured endpoint and adds only documented `langfuse.*` overlays needed for Langfuse filtering and presentation.

**Context:** Langfuse accepts OTLP, while its first-class trace metadata and filtering can require Langfuse-specific attributes beyond generic OpenTelemetry/OpenInference fields.

**Consequences:** Contract tests prove which OpenInference fields Langfuse renders directly and which Agentscope fields require an explicit `langfuse.*` mapping; unmapped `agentscope.*` attributes remain namespaced metadata rather than silently becoming product fields.

**Required flow:** The reporter accepts only the redacted canonical OTLP/OpenInference graph. It preserves OpenInference and `agentscope.*` fields, adds the narrow tested `langfuse.*` overlay, and serializes an OTLP payload. It does not read a harness transcript or construct a separate Langfuse-native trace model.

### ADR-002: Avoid overlapping vendor hooks

**Decision:** Installation detects Langfuse's official harness integration and requires explicit migration before an Agentscope hook takes ownership.
