## Capability Summary

Langfuse is the initial first-party destination and validates the Trace Destination abstraction.

## Architecture Decision Records

### ADR-001: Start with OTLP delivery

**Decision:** The initial Langfuse reporter sends the OpenInference-compatible canonical OTLP graph to a configured endpoint and adds only documented `langfuse.*` overlays needed for Langfuse filtering and presentation.

**Context:** Langfuse accepts OTLP, while its first-class trace metadata and filtering can require Langfuse-specific attributes beyond generic OpenTelemetry/OpenInference fields.

**Consequences:** Contract tests prove which OpenInference fields Langfuse renders directly and which Agentscope fields require an explicit `langfuse.*` mapping; unmapped `agentscope.*` attributes remain namespaced metadata rather than silently becoming product fields.

### ADR-002: Allow a direct Langfuse path later

**Decision:** A direct Langfuse ingestion implementation may be added as another reporter behind the same Trace Destination contract.

**Context:** It may represent Langfuse-specific capabilities more faithfully without forcing harnesses to choose transport.

### ADR-003: Avoid overlapping vendor hooks

**Decision:** Installation detects Langfuse's official harness integration and requires explicit migration before an Agentscope hook takes ownership.
