## Capability Summary

The `agentscope` command must be easy to install, stable for hooks, and publishable to npm.

## Architecture Decision Records

### ADR-001: Publish a dedicated CLI package

**Decision:** Publish `@agentscope/cli` from `apps/cli` with an unhyphenated `agentscope` bin entry. No library or SDK package is a supported public product.

**Context:** Hooks need one stable executable. Publishing internal packages before a concrete external-library use case would create accidental compatibility promises.

### ADR-002: Hook config calls an owned launcher, not embedded implementation

**Decision:** Generated harness configuration invokes an absolute Agentscope-owned launcher or verified shim with a versioned stable hook subcommand and separately encoded arguments.

**Context:** Upgrades should replace one launcher rather than rewrite bespoke code into every harness config, while avoiding hook-time `PATH` lookup or shell interpretation.

### ADR-003: Make platform support a release-gated manifest

**Decision:** The CLI owns a machine-readable support manifest covering Node versions, operating systems, architectures, credential backends, required filesystem semantics, native dependencies, and the applicable evidence policy.

**Context:** Linux containers cannot prove Windows path/rename behavior, macOS or Windows credential access, GUI hook execution, or native dependency availability.

**Consequences:** A platform/runtime combination is supported only when install, configuration, credential, hook invocation, Doctor, upgrade, and uninstall checks pass on an appropriate native runner. Unsupported combinations fail with stable diagnostics; documentation derives claims from the manifest and current evidence.
