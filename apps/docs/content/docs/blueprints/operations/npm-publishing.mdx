## Capability Summary

NPM releases must be attributable, reproducible, and limited to intentionally public packages without long-lived repository secrets.

## Architecture Decision Records

### ADR-001: Use npm trusted publishing from a tag-only workflow

**Decision:** Public packages publish only from a dedicated GitHub Actions workflow triggered by an approved semantic version tag, using npm trusted publishing and provenance rather than a long-lived `NPM_TOKEN`.

**Context:** A tag gate separates normal pull-request/main validation from a security-sensitive release action and permits npm to verify the GitHub workflow identity.

**Consequences:** Maintainers configure each public package's trusted publisher on npmjs.com for `Melbourneandrew/agentscope`, the release workflow filename, and the `npm publish` action. The repository remains public and the release workflow has the required `id-token: write` permission. Normal merges to `main` never publish.

### ADR-002: Publish only real executable or library contracts

**Decision:** `@agentscope/cli` becomes public only once `apps/cli` produces the tested `agentscope` executable. Core or protocol-facing libraries become public only after their supported API and compatibility policy are explicitly documented; first-party harness and destination packages remain internal until a concrete external library use case exists.

**Context:** Publishing scaffolding turns internal folder layouts into an accidental long-term compatibility promise.

**Consequences:** Release automation selects only explicitly public workspace packages. The published artifact and packed CLI are validated by the hermetic integration lane before a release tag is created.
