## Capability Summary

CI protects the repository from quality, package, documentation, and harness-compatibility regressions while separating privileged deployment and release work from pull requests.

## Architecture Decision Records

### ADR-001: Make quality, unit, docs, and integration independent required checks

**Decision:** Pull requests run independently visible `quality`, `unit`, `docs`, and hermetic `integration` checks. The quality lane enforces the shared ESLint, Prettier, and strict TypeScript policy defined in [Code Quality and CI](/docs/blueprints/operations/code-quality-and-ci); unit and integration lanes follow the [Test Strategy](/docs/blueprints/testing/test-strategy).

**Context:** A single monolithic job hides the class of failure and makes expensive harness testing block basic feedback.

**Consequences:** Protected `main` requires the named checks and squash merges. The merge workflow has no npm publishing authority; documentation deployment and tagged CLI release are separate workflows.

### ADR-002: Separate untrusted PR work from privileged main work

**Decision:** PR workflows receive no production destination credentials, npm publishing identity, or GitHub Pages deployment authority. Main-only workflows deploy docs; protected scheduled/manual workflows may run live integration checks with protected secrets.

**Context:** A pull request can change test code and must not be able to exfiltrate a privileged token through logs or network traffic.

**Consequences:** CI uploads only sanitized test logs and ledgers. Publishing follows [NPM Publishing](/docs/blueprints/operations/npm-publishing), and Pages follows [Documentation Site](/docs/blueprints/operations/documentation-site).
