## Capability Summary

Agentscope needs a durable internal trace format that reuses open telemetry standards while carrying coding-agent evidence those standards do not yet cover.

## Architecture Decision Records

### ADR-001: Use OTLP with OpenInference semantics as the canonical model

**Decision:** This Blueprint solely owns canonical semantics: an OTLP `ResourceSpans`-shaped graph whose standard attributes follow the exact OpenTelemetry semantic-convention and OpenInference baselines named in Protocol's machine-readable manifest. OpenInference's `openinference.span.kind` is an AI-operation classification distinct from OTLP's numeric `Span.kind`. The same manifest owns the `agentscope.*` extension registry, identity rules, and redaction-state contract. `CanonicalTraceEnvelope` is only a small Agentscope lifecycle wrapper around that standard graph, not a second trace schema.

**Context:** OpenTelemetry supplies the graph, timing, status, exception, and transport semantics. OpenInference supplies an evolving AI attribute vocabulary for LLM, agent, tool, retrieval, message, and token concepts, but it does not define a normative schema URL, graph topology, or compatibility policy. Recreating either vocabulary would create needless translation and interoperability drift. Coding harnesses additionally expose installation ownership, harness identity, Git/worktree context, native artifact provenance, and unavailable-value reasons.

**Consequences:** Agentscope never duplicates OpenInference `AGENT`, `LLM`, `TOOL`, model, message, or token fields, and never dual-emits overlapping OTel `gen_ai.*` attributes. `AGENT` describes an orchestration or reasoning operation; it does not identify Claude Code, Codex, or another harness. Harness identity remains in registered `agentscope.harness.*` attributes. Standard OTel VCS resource attributes carry head name, revision, ref type, and credential-free repository identity; `agentscope.*` is reserved for genuinely local workspace/worktree paths, harness identity, mapping evidence, and redaction identity. Every extension registry entry declares its key, OTLP value type, applicability, sensitivity/redaction class, requirement level, and provenance rule. Contract tests assert the exact manifest baseline and serialization; values that could disclose local paths remain subject to redaction.

### ADR-002: Make redaction an enforceable lifecycle boundary

**Decision:** Harness adapters return a transient, structurally validated but non-exportable `CapturedTrace`. Core alone resolves policy and applies redaction, then uses Protocol to construct a branded `RedactedCanonicalTrace`. Protocol's manifest-pinned semantic descriptor is the sole vocabulary for classifying every accepted attribute and OTLP structural leaf and for selecting its immutable minimum transform route. Unknown or unclassified values cannot be branded. Only the branded post-redaction value may enter routing, diagnostics, persistence, retrieval presentation, or reporter code.

**Context:** “Lossless” must preserve observability semantics, not retain secrets. Requirements prohibit sensitive data from reaching persistence or destinations.

**Consequences:** `CapturedTrace` values remain confined to the adapter/Core call lifetime and are never logged or persisted. The descriptor distinguishes structural, telemetry, identifier, path, content, structured-content, URI/media, opaque-provider-artifact, and embedding-vector classes. Its ordered routes always apply bounded validation plus baseline secret/path handling before any class-specific action; user policy may only strengthen those routes. Opaque signatures, ciphertext, replay data, and embedding vectors default to omission rather than type-changing placeholders. Reporter and destination contracts accept only `RedactedCanonicalTrace`; a raw pointer is a sanitized identity/reference, never an address to unredacted retained content. Seam tests prove every durable and outbound path requires the branded type and records the applied policy identifier.

Core resolves one closed, immutable effective policy before capture. The built-in baseline always performs the complete bounded secret, absolute-path, structured-content, and URI transforms; baseline retains ordinary safe identifier, path, content, structured-content, and permitted URI values after those transforms. Strict mode further omits every descriptor-optional potentially sensitive value. Opaque provider artifacts, replay material, ciphertext, and embedding vectors are omitted in every mode, while a required structural name uses only its descriptor-approved fixed non-content replacement or suppresses the trace. Expanding any built-in retained category is an explicit policy migration.

Additional user rules use one versioned Core-owned declarative grammar. A rule selects an exact manifest semantic key or indexed-template identity, optionally narrows it by OpenInference span kind, and has only the action `omit`; it cannot match arbitrary value content, replace a value, change provenance, add metadata, select a destination, or invoke executable code. Core canonicalizes and de-duplicates a bounded rule list, resolves selectors against the current Protocol descriptor, and composes descriptor minimums, the selected built-in mode, and all matching rules as an order-independent disclosure meet. Unknown selectors, unsupported versions/actions, duplicate contradictions, malformed or over-budget policy input, and unavailable referenced policy material make policy resolution fail closed. The effective identity fingerprints the consumed baseline profile, built-in mode, canonical rule set, and effective lower retention limits.

The policy identity includes a golden SHA-256 fingerprint over detector grammar, normalization and bounded decode rules, path grammar, URI allowlists, route-by-mode terminal outcomes, user-rule grammar, and every immutable safety ceiling; changing any of them is an explicit policy migration. Capture, structured parsing, scanning, and evidence-ledger ceilings are non-configurable and are enforced before any user-requested omission can avoid work. User policy may lower retained-value or rule-count limits but can never raise a safety ceiling, truncate before mandatory scanning, or turn suppression into retention. Core executes every descriptor transform in order through an exhaustive handler inventory and constructs fresh output; unknown routes, invalid outcomes, malformed structured values, over-budget ledgers, or final canonical rejection suppress the whole trace with one content-free error. A byte-semantically unchanged retained value keeps its observed source, a transformed emitted value records exact `derived` provenance, and an omitted observed value keeps its original source plus exact `redacted` / `policy-redacted` evidence. Policy omission does not alter native dropped-count telemetry or compact flattened semantic indices.

The owned launcher supplies one immutable hard bootstrap duration and Core creates its branded same-process monotonic absolute deadline at hook entry, before configuration or policy reads. After configuration resolves, Core computes the effective deadline as the earlier of that bootstrap deadline and routing policy version 1's configured integer hook duration measured from the original entry instant; configuration may shorten but never extend bootstrap authority. The complete snapshot records only the closed bootstrap/configured/effective deadline-policy provenance, not a mutable wall-clock value. Every initialization, context projection, Git, capture, redaction, routing, and reporting stage receives the same cancellation authority and may consume no more than the lesser of its immutable stage cap and the remaining hook budget. Exhaustion of the global deadline always wins over a simultaneous stage timeout, returns the fixed hook deadline result, requests cooperative cancellation, and prevents later stages from starting. A stage cap reached while global time remains maps to that stage's fixed unavailable or suppression result and never extends the hook deadline. Owned synchronous stages are strictly bounded and place deterministic cancellation checks before and after their work; asynchronous stages own and close or unref their handles. An uncooperative first-party callback or transport is a contract defect, and Core never claims that `AbortSignal` preempted it after release.

The owned hook launcher supplies the exact first-party harness registry identity, entry process directory, and one already bounded context-evidence input at hook entry; ambient discovery cannot choose or replace that identity. Core first freezes the configuration and effective policy portion of the snapshot, then looks up that exact registered adapter's pure context projection, resolves workspace and repository paths in one short-lived child process per bounded path stage, runs Git in the already bounded parent-owned subprocess stage, and freezes the complete invocation context before capture. The parent caps IPC, kills the path child on abort or expiry, and joins its exit before the stage completes; timeout, crash, malformed output, or overflow yields fixed unavailable context, while global expiry still wins. The resulting single-use harness capture factory is bound to the exact configuration generation and identity, effective policy and identity, effective workspace selection, complete observed-or-unavailable Git field closure, first-party harness registry identity, observed-or-unavailable executable version evidence, operation-ID scope, process observation time, deadline identity, and attempt nonce. Later ambient configuration, process-cwd, filesystem, or Git changes do not alter the invocation. Harness input cannot override any of those values or claim Core-owned Git/process/configuration/derived provenance. The factory is available only inside the adapter callback, is revoked in `finally`, and rejects both a second successful capture and any late use. The opaque `CapturedTrace` keeps reconstructed frozen candidates in private runtime storage; JSON, string, spread, descriptor, structured-clone, and inspection surfaces expose only a fixed non-content lifecycle marker.

Fixed lifecycle diagnostics are a separate pre-brand operational channel, not trace diagnostics. Every policy/configuration/Git resolution, deadline, or redaction failure produces one frozen closed lifecycle result without I/O; that result is the required sanitized diagnostic even when durable Operational State is unavailable. The same-process hook performs no Operational State filesystem call. A launcher-owned isolated child preloads one bounded snapshot before capture and may commit one bounded evidence generation after routing; Core kills and joins that child on abort, timeout, crash, malformed output, or overflow, and claims `recorded` only after observing its exact success response. Accepted boundaries remain replayable with fixed `checkpoint-unavailable` evidence whenever preload or commit is uncertain. [Operational State](/docs/blueprints/operations/operational-state) owns atomic replacement, acknowledgement-loss reconciliation, and proof-bound stranded-lock recovery. No trace or delivery identity, policy reference, selector, path, repository value, error/message/stack, matched content, or native value is permitted. This exception does not permit `CapturedTrace` or any field derived from it to enter diagnostics, and persistence/export remains suppressed while the harness fails open.

### ADR-003: Export OpenInference-compatible OTLP with destination overlays

**Decision:** Reporters serialize the canonical graph as version-pinned OpenInference-compatible OTLP, then add destination-specific overlays only where required.

**Context:** The canonical graph is already OpenInference-shaped. OTLP remains the transport, while individual destinations can require additional namespaced attributes for first-class presentation and retrieval.

**Consequences:** The Langfuse reporter maps only the small overlay (for example filterable trace metadata) rather than translating a second, duplicated agent model. Contract tests distinguish OpenInference/OTLP fields, `agentscope.*` fields, and each destination overlay.

### ADR-004: Preserve one standards-first trace pipeline

**Decision:** Every supported integration follows one unidirectional pipeline: **harness-native artifact → transient `CapturedTrace` → Core redaction → branded OTLP/OpenInference `RedactedCanonicalTrace` with `agentscope.*` context → destination reporter → destination transport**. The Langfuse transport is OTLP plus a minimal `langfuse.*` overlay.

**Context:** A separate per-destination canonical model would make harness behavior, privacy controls, and trace meaning diverge.

**Consequences:** Adapters never emit Langfuse-specific fields. Reporters never reinterpret native harness transcripts. A new destination consumes the same canonical graph and may add only its documented transport overlay; it cannot alter the OpenInference or `agentscope.*` semantic contract.

Core exposes one resolved fail-open hook lifecycle, not a public capture/redaction/sink assembly API. It opens and revokes the snapshot-bound capture invocation, requires the adapter to return the exact trace minted by that invocation, performs redaction and finalization, then passes the original branded envelope reference directly into the selected Reporter attempts owned by [Reporter Abstraction ADR-006](/docs/blueprints/destinations/reporters/reporter-abstraction). The earlier provisional synchronous destination-sink subpath is removed at this cutover. The lifecycle applies the same composed monotonic deadline before capture, after each synchronous stage, throughout connection setup, and at Reporter settlement. Each trusted first-party synchronous callback is contractually bounded; blocking the JavaScript thread beyond that bound is an implementation defect that same-thread code cannot preempt. Arbitrary thrown values and ordinary accidental runtime-cast Promise or thenable misuse are absorbed into fixed content-free results without stack, identity, or payload exposure. Core creates no serialized fanout copy, spool, retry, or detached delivery work.

### ADR-005: Treat SF Platform as a reference, not a compatibility target

**Decision:** Agentscope has no requirement to preserve the SF Platform trace schema, APIs, storage format, or hook behavior. The existing implementation is used only to discover use cases, native artifacts, and regression scenarios.

**Context:** The standalone product can choose a simpler, standards-aligned design without carrying internal platform constraints forward.

**Consequences:** Compatibility decisions are driven by OTLP, OpenInference, supported harness behavior, and destination contracts. Migration work applies only to Agentscope's own published formats after they exist.

### ADR-006: Give equivalent capture boundaries stable identity

**Decision:** Protocol derives session, trace, span, capture-boundary, and per-item delivery identities with SHA-256 over a manifest-bound, domain-separated `ASID` binary TLV profile. Stable TraceId derives only from session identity; boundary generation and exclusive end affect boundary and delivery identity, never the session TraceId or existing SpanIds. Core alone applies the primitives and passes one logical item's delivery identity unchanged through routing and batching.

**Context:** Repeated hooks, process restarts, transcript rereads, and lost acknowledgements can otherwise create incompatible or duplicate logical traces.

**Consequences:** Session-global operation IDs exclude parent identity; parent-scoped IDs include the parent full digest; fallback identity explicitly declares `session-stable`, `boundary-scoped-at-least-once`, or `attempt-scoped-at-least-once`. Content, paths, Git/model, policy/config, destination, time, deadline, batch shape, and outcomes never enter stable tuples. Identity enables destination deduplication but never promises exactly-once delivery.

### ADR-007: Bind the complete producer profile to one manifest identity

**Decision:** The Protocol manifest identity includes collision-resistant fingerprints for the curated OpenInference/OTel producer profile, the ASID identity profile, and the governed `agentscope.*` extension registry, in addition to explicit upstream and contract versions.

**Context:** Binding only upstream package versions would allow terminal grammar, type, applicability, graph, evidence-accounting, or extension semantics to drift under an unchanged compatibility identity. Redaction routing additionally requires a sensitivity-aware semantic descriptor before captured values can cross the canonical boundary.

**Consequences:** Protocol compiles canonical validation and Core-facing lookup metadata from committed, strict, recursively frozen semantic, timing, and identity descriptors. The semantic descriptor binds exact terminals and structured templates, value types, location/kind applicability, empty-value rules, support state, sensitivity/content class, mandatory route, permitted outcomes, pinned package export names, snapshot-only source references, and explicit upstream constraints. The timing descriptor binds every basis to its native state, allowed provenance sources, location, evidence class, construction rule, and interval-versus-point shape, including the root-only derived child envelope required when native root timing is unavailable. The identity descriptor binds the ASID header, field types and ordering, complete domain layouts, enum inventories, continuity classes, projections, collision behavior, and privacy exclusions. The producer profile also binds the declarative indexed-provenance group segments, their owned semantic-template identifiers and span kinds, exact-over-deepest-over-ancestor precedence, unavailable prohibition, canonical-index bounds, ledger budget, fixed `INTERNAL` OTLP span-kind construction, and indexed event/link member-evidence grammar. Protocol recomputes and verifies descriptor fingerprints and the complete producer-profile fingerprint at load time. Any grammar, classification, route, timing compatibility, provenance resolution, identity, constraint, or registry change requires an intentional identity update and mutation test. Package drift tests resolve named OpenInference exports without deriving accepted grammar from `Object.values`. Every canonical resource carries the exact manifest identifier.

### ADR-008: Permit explicit incomplete native evidence without inventing values

**Decision:** A canonical LLM span carries a nonempty, provenanced `llm.system`, or it records an exact `llm.system` unavailable or redacted entry with a matching provenance source and truthful reason. No unknown or redaction sentinel is permitted.

**Context:** OpenInference constrains `llm.system` when it is present but does not require its presence. Agentscope deliberately requires either a present value or exact absence evidence so consumers can distinguish missing native evidence from policy redaction. Some supported native harness artifacts do not expose the value reliably, and fabricating a system would destroy uncertainty.

**Consequences:** The present-value form is OpenInference-conformant. An absent value with `state: unavailable` records incomplete native evidence; an absent value with `state: redacted` truthfully records policy removal. These absence records are an Agentscope evidence extension, not an upstream OpenInference requirement. Present-plus-absent accounting, absent-without-accounting, empty values, and `not-applicable` on an LLM span are rejected. Required nonempty structural names use only a descriptor-approved non-content replacement or suppress the trace; optional fields such as embedding vectors are omitted with redacted accounting rather than widened to a string placeholder.

### ADR-009: Brand only the singular versioned delivery envelope

**Decision:** `RedactedCanonicalTrace` is the exact envelope `{ envelopeVersion: 1, protocolManifestId, delivery: { identity, stability }, graph }`: one ASID delivery identity and continuity class from ADR-006 plus one canonical graph. The Core-only finalizer consumes one process-local Protocol-derived `IdentityBundle` and a pre-final graph whose spans and internal links carry transient logical-operation keys. Protocol injects `traceId`, `spanId`, `parentSpanId`, and internal-link target identities from that bundle, requires or adds exact `derived` provenance for those Protocol-assigned identity fields, strips the transient keys, and constructs the fixed envelope version, current manifest identifier, and delivery fields itself; caller-supplied wire identities and conflicting native provenance are non-authoritative. `span.links` retains the native or hook provenance of the observed relationship collection, while `span.links.target_ids` records the derived wire-target projection. Repeated links to the same internal target remain an ordered sequence, while missing or unknown targets reject. Protocol then cross-checks the graph's required resource manifest attribute, reconstructs and recursively freezes fresh plain data, and registers the value as redacted only after every check succeeds.

**Context:** A structural TypeScript type cannot prove that redaction and canonical validation happened. Duplicating trace, session, policy, destination, attempt, or transport-batch fields outside the graph would create conflicting sources of truth. JSON or IPC reconstruction cannot safely preserve an in-process lifecycle claim.

**Consequences:** Runtime redaction identity is process-local and unforgeable through ordinary DTO operations: spread, clone, JSON roundtrip, symbol or prototype spoofing, and cross-process rehydration all produce unbranded values. The public Protocol entrypoint exposes the envelope type, guard, and guarded serializer; only Core may import the separate finalization authority. This is a misuse-prevention boundary within the first-party package graph, not a malicious-code sandbox. Unsupported envelope or manifest versions fail with one content-free error before destination delivery.

### ADR-010: Keep transport and durable serialization distinct

**Decision:** OTLP JSON/protobuf codecs serialize only the canonical graph inside a branded envelope as an OTLP `ExportTraceServiceRequest`. Durable serialization stores the exact versioned Agentscope envelope. External OTLP decoding and persisted-envelope reading return fresh, frozen, explicitly unbranded values; neither operation is rehydration or permission to deliver.

**Context:** OTLP has no fields for Agentscope envelope version, protocol manifest identity, ASID delivery identity, or stability class. Adding those fields to a transport request would create a nonstandard second authority, while dropping them from durable storage would make exact version dispatch and idempotent delivery evidence impossible.

**Consequences:** OTLP encode/decode round trips preserve supported graph semantics but intentionally do not preserve delivery-envelope metadata or runtime brand. Persisted reads dispatch by an exact fingerprint-bound manifest allowlist and require a subsequent Core revalidation and current-policy redaction lifecycle before presentation or re-export. The manifest-bound compatibility profile records a permanent whole-contract generation archive separately from its executable reader window. Each generation binds the machine-readable schema descriptor consumed by its source parser and a literal sanitized fixture; startup binds the explicit `current` selector rather than an archive position. Contract 2 admits the exact contract-1 production checkpoint and current contract 2 into the executable window. Its adjacent migration strictly parses contract 1, proves that feedback semantics and the contract-2 transport marker are absent, constructs fresh unbranded data, preserves delivery identity only because the identity profile is equal, and replaces exact outer/resource manifest and scope identities. Numeric contract versions order lineage only and never substitute for exact manifest dispatch. `introducedInProtocolContractVersion` governs first appearance and immutable append-only lineage of `agentscope.*` extensions; upstream OpenInference semantic additions are instead semantic-profile generation changes.

### ADR-011: Govern complete OpenInference feedback objects and explicit transport claims

**Decision:** Protocol accepts all six manifest-pinned OpenInference annotation/evaluation forms only as complete flattened objects with a nonempty `name` and at least one numeric score, label, or explanation. Alias equality is matched by scope, name, and identifier—not list index—and ambiguous un-identified duplicates reject. Strict Agentscope production adds the Protocol-owned `agentscope.feedback.transport` value `inline` or `post-hoc`; only the explicit `post-hoc` value activates carrier correlation rules. Harness-native fields cannot supply this key: Core accepts a typed carrier intent only alongside a valid feedback compound, validates the native compound before redaction, and derives the marker and its provenance before final validation.

**Context:** The pinned OpenInference annotations specification defines compound object, session, alias, and post-hoc link invariants that cannot be enforced by accepting individual terminals independently. Indices are ordering positions rather than result identifiers, and ordinary inline target spans may already contain unrelated links.

**Consequences:** The fingerprinted feedback descriptor binds all 42 terminals, finite numeric scores, sparse zero-based indices, open annotator kinds, privacy routes, object atomicity, and correlation policy. Session feedback always requires `session.id`. An explicit post-hoc span or trace carrier has exactly one total Span Link; a session carrier uses `session.id` and may retain any ordinary links. A carrier contains one scope, while absence of the marker on tolerant external OTLP intake means correlation is unclassified and never inferred from `EVALUATOR`, parentage, or arbitrary links. Strict production rejects incomplete objects after redaction rather than emitting partial feedback.
