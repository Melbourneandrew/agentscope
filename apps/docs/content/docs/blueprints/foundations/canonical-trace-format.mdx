---
title: Canonical Agentscope Trace Format
description: ADRs for the OTLP/OpenInference cross-harness trace model.
---

## Capability Summary

Agentscope needs a durable internal trace format that reuses open telemetry standards while carrying coding-agent evidence those standards do not yet cover.

## Architecture Decision Records

### ADR-001: Use OTLP with OpenInference semantics as the canonical model

**Decision:** `@agentscope/core` persists and exchanges an OTLP `ResourceSpans`-shaped trace graph as its canonical body. Its span kinds and attributes follow a pinned OpenInference version wherever that convention applies. `CanonicalTraceEnvelope` is only a small Agentscope lifecycle wrapper around that standard graph, not a second trace schema.

**Context:** OpenTelemetry supplies the trace data model and transport; OpenInference supplies portable LLM, agent, tool, retrieval, message, token, timing, and error semantics. Recreating either would create needless translation and interoperability drift. Coding harnesses additionally expose installation ownership, harness identity, Git/worktree context, native artifact provenance, and unavailable-value reasons.

**Consequences:** Agentscope never duplicates OpenInference `AGENT`, `LLM`, `TOOL`, model, message, token, timing, or error fields. It adds only documented `agentscope.*` attributes such as `agentscope.harness.*`, `agentscope.workspace.branch`, `agentscope.workspace.repository`, `agentscope.workspace.worktree`, `agentscope.workspace.directory`, `agentscope.mapping.provenance`, and bounded unavailable/reason fields. Core pins versions and owns migrations; values that could disclose local paths remain subject to redaction.

### ADR-002: Redact before canonical durability

**Decision:** Raw native artifacts are transient adapter input only. Redaction occurs before a canonical envelope, source provenance, unknown field, raw pointer, spool entry, diagnostic, or reporter payload becomes durable.

**Context:** “Lossless” must preserve observability semantics, not retain secrets. Requirements prohibit sensitive data from reaching persistence or destinations.

**Consequences:** A raw pointer is a sanitized identity/reference, never an address to unredacted retained content. Fields that cannot be safely represented after redaction are omitted with a bounded unavailable/redacted reason.

### ADR-003: Export OpenInference-compatible OTLP with destination overlays

**Decision:** Reporters serialize the canonical graph as version-pinned OpenInference-compatible OTLP, then add destination-specific overlays only where required.

**Context:** The canonical graph is already OpenInference-shaped. OTLP remains the transport, while Langfuse and later destinations can require additional namespaced attributes for first-class presentation and retrieval.

**Consequences:** The Langfuse reporter maps only the small overlay (for example filterable trace metadata) rather than translating a second, duplicated agent model. Contract tests distinguish OpenInference/OTLP fields, `agentscope.*` fields, and each destination overlay.

### ADR-004: Preserve one standards-first trace pipeline

**Decision:** Every supported integration follows one unidirectional pipeline: **harness-native artifact → harness adapter → redacted OTLP/OpenInference canonical graph with `agentscope.*` context → destination reporter → destination transport**. The Langfuse transport is OTLP plus a minimal `langfuse.*` overlay.

**Context:** A separate per-destination canonical model would make harness behavior, privacy controls, and trace meaning diverge.

**Consequences:** Adapters never emit Langfuse-specific fields. Reporters never reinterpret native harness transcripts. A new destination consumes the same canonical graph and may add only its documented transport overlay; it cannot alter the OpenInference or `agentscope.*` semantic contract.

### ADR-005: Treat SF Platform as a reference, not a compatibility target

**Decision:** Agentscope has no requirement to preserve the SF Platform trace schema, APIs, storage format, or hook behavior. The existing implementation is used only to discover use cases, native artifacts, and regression scenarios.

**Context:** The standalone product can choose a simpler, standards-aligned design without carrying internal platform constraints forward.

**Consequences:** Compatibility decisions are driven by OTLP, OpenInference, supported harness behavior, and destination contracts. Migration work applies only to Agentscope's own published formats after they exist.
