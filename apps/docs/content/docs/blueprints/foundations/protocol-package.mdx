## Capability Summary

`@agentscope/protocol` provides the stable internal vocabulary shared by harnesses, Core, destinations, and tests without exposing a public SDK promise.

## Architecture Decision Records

### ADR-001: Isolate the canonical contract in Protocol

**Decision:** `packages/protocol` implements the semantics owned by Canonical Trace Format: validated OTLP JSON DTOs, generated OTLP protobuf codecs, the manifest-pinned OpenInference/OTel sensitivity descriptor and compiled lookup API, the governed `agentscope.*` extension registry, canonical schema validation, branded redaction-state APIs, canonical envelope versions, fixtures, and Protocol migrations. It has no filesystem, configuration, credential, network, harness, redaction-handler, or destination behavior.

**Context:** The canonical contract changes on a different cadence from machine-local orchestration. A pure package prevents Core from becoming the owner of every concept and keeps harness/destination adapters aligned on one standards-first model.

**Consequences:** Harnesses construct transient `CapturedTrace` values; Core applies redaction and asks Protocol to construct branded `RedactedCanonicalTrace` values; destinations consume only the latter. Protocol owns pure descriptor class/route names, exact-before-template lookup, natural-value-to-OTLP construction, fixed canonical construction rules, evidence-ledger building, completeness rejection, and identity verification. Core owns the exhaustive transform handlers and transient workspace/repository context, and may only strengthen the descriptor's ordered minimum route. Core submits exact post-redaction claims; Protocol alone validates indexed event/link suffixes and aligns retained members with their original source indices. The standards manifest pins exact upstream artifacts, named package exports, snapshot-only semantics, descriptor fingerprints, and generated-code provenance. Protocol is private: its API is an internal compatibility boundary, not a published SDK.

### ADR-002: Version protocol independently of implementation packages

**Decision:** Canonical envelope and attribute semantics carry an explicit Protocol version. A change to the pinned OpenInference or `agentscope.*` vocabulary is a Protocol migration with fixtures and compatibility tests.

**Context:** Persisted configuration, hook blocks, and durable destination payloads can outlive the running CLI even though all private packages ship in one atomic CLI release closure.

**Consequences:** Persisted-envelope reading dispatches through the compatibility compiler's exact executable window rather than a second allowlist or numeric range. A manifest-bound compatibility profile separates the permanent whole-Protocol generation archive from that executable reader window; `protocolContractVersion` is a strictly increasing whole-contract generation order for adjacent migrations and never authorizes a read by itself. To avoid manifest self-reference, archived generations name historical manifest IDs while the current generation uses a typed `current` selector that startup resolves against the complete manifest identity. Contract 2 archives and executes the exact contract-1 production manifest, source descriptor, extension snapshot, and literal sanitized fixture alongside current contract 2; production still rejects synthetic test schemas. The v1-to-v2 edge strictly rejects feedback rather than fabricating it, constructs fresh data, and preserves delivery identity only under the unchanged identity fingerprint. Descriptor or fixture drift changes the generation and compatibility identities. Readers return frozen unbranded DTOs and never recover the process-local redaction brand. Unsupported versions and malformed supported values have distinct fixed, content-free reader codes. No compatibility with the SF Platform model is implied.

### ADR-003: Separate the strict canonical producer from tolerant OTLP ingestion

**Decision:** Protocol exposes three non-interchangeable seams. The reporter producer accepts only a process-branded `RedactedCanonicalTrace` and encodes its graph as one OTLP `ExportTraceServiceRequest`. The bounded external OTLP reader accepts an untrusted multi-resource, multi-scope, multi-trace request and returns frozen unbranded per-trace dispositions. The persisted-envelope reader accepts untrusted bytes for exact version/manifest dispatch and returns a frozen unbranded envelope DTO. No reader invokes finalization, recovers a brand, or enters a destination sink.

**Context:** Reusing the strict producer validator as a general OTLP receiver would incorrectly reject forward-compatible external telemetry. Making the producer tolerant would allow unknown or sensitive fields into reporter payloads.

**Consequences:** Producer schemas reject unknown keys at every message and attribute location. OTLP transport encoding deliberately omits the Agentscope delivery wrapper; durable envelope serialization preserves its version, manifest, delivery identity/stability, and graph. The external reader ignores unknown standard OTLP names and binary fields, rejects unknown `agentscope.*` semantics, and rejects each trace unit containing unsupported known values without coercion. It accepts case-insensitive identity hex and ProtoJSON number-or-string integer forms, then normalizes to lowercase hex and decimal strings. Raw byte, JSON token, aggregate batch, and schema-aware protobuf wire budgets apply before generated decoding; binary readers preflight and decode one fresh owned snapshot. The fingerprinted codec profile is an exact executable contract: startup validation rejects coordinated claims that differ from the implemented unknown-field, duplicate, numeric, bytes, UTF-8, response, and persisted-reader behavior. Any decoded or persisted value must enter a new Core validation and policy lifecycle before output or re-export.

The strict producer requires `agentscope.feedback.transport` on feedback-bearing spans and revalidates complete objects after redaction. The tolerant OTLP reader may accept valid upstream feedback without that Agentscope marker; absence is preserved as an unclassified correlation state and does not assert inline or post-hoc semantics. Unknown feedback terminals are ignored at the tolerant wire seam, while every retained known object is compound-validated atomically.

### ADR-004: Separate observation from finalization authority

**Decision:** Protocol's root entrypoint exposes the governed schemas, descriptors, codecs, identity primitives, and construction helpers that consumers need, but its redacted-lifecycle authority is limited to the `RedactedCanonicalTrace` type, runtime guard, and guarded serializer. The explicit `@agentscope/protocol/core-finalization` entrypoint exports only the finalizer and is importable solely by Core; both entrypoints share one package-private runtime registry.

**Context:** Core and untrusted readers need the public contract vocabulary, while destinations need to recognize and serialize a completed canonical value but must never mint one. A public rebrand, parser, or rehydration API would let an untrusted DTO bypass Core policy application, while separately bundled registry copies would reject legitimate values.

**Consequences:** Workspace and ESLint policy reject static imports, dynamic imports, and `require` access to the authority from the CLI, harnesses, destinations, and testkit. Artifact tests bundle the public and Core entrypoints together and prove they observe the same registry. The finalizer accepts a runtime-recognized Protocol identity bundle plus transient logical span/link associations, injects all in-graph identities from that authority, strips the associations, performs hostile-input preflight and strict graph/manifest validation, recursively freezes, then registers last; fixed failures never expose input content. Serialization, IPC, workers, or loading a second physical Protocol copy intentionally loses either runtime authority and requires a new Core lifecycle rather than rehydration.
