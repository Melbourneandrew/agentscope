## Capability Summary

Harness adapters implement the [Harness Management](/docs/requirements/harness-management) contract for coding-agent runtimes.

## Architecture Decision Records

### ADR-001: Model harnesses, not model providers

**Decision:** Treat Codex, Claude Code, Gemini CLI, OpenCode, Pi, OpenClaw, Hermes, and additional coding-agent CLIs as harnesses; model providers remain metadata.

**Context:** Installation, hooks, transcript artifacts, and lifecycle events belong to the harness even when it can route across model providers.

### ADR-002: Keep adapter responsibilities narrow

**Decision:** Each adapter descriptor owns detection, the runtime compatibility range and compatibility-state logic, owned configuration generation, native artifact collection, and native-to-`CapturedTrace` mapping.

**Context:** Reporter behavior, redaction, delivery deadlines, and configuration persistence must remain common across harnesses.

**Consequences:** The integration capability manifest records pinned tested representatives and evidence rather than a second supported-version range. CI verifies that every matrix representative satisfies its descriptor and that advertised ranges meet the coverage policy. An adapter must supply a real-harness scenario before claiming compatibility.
