# Harness Abstraction

## Capability Summary

Harness adapters implement the [Harness Management](/docs/requirements/harness-management) contract for coding-agent runtimes.

## Architecture Decision Records

### ADR-001: Model harnesses, not model providers

**Decision:** Treat Codex, Claude Code, Gemini CLI, OpenCode, Pi, OpenClaw, Hermes, and future coding-agent CLIs as harnesses; model providers remain metadata.

**Context:** Installation, hooks, transcript artifacts, and lifecycle events belong to the harness even when it can route across model providers.

### ADR-002: Keep adapter responsibilities narrow

**Decision:** Each adapter owns detection, compatible-version checks, owned configuration generation, native artifact collection, and native-to-canonical mapping.

**Context:** Reporter behavior, redaction, retries, and configuration persistence must remain common across harnesses.

**Consequences:** An adapter package can evolve independently and must supply a real-harness scenario before claiming compatibility.
