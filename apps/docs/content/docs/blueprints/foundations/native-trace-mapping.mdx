## Capability Summary

Native artifacts vary by harness; this Blueprint defines how adapters map them without fabricating certainty.

## Architecture Decision Records

### ADR-001: Preserve provenance and uncertainty

**Decision:** Every captured field derived from a native artifact records source/provenance where ambiguity affects interpretation, and unavailable values remain unavailable. The owned hook launcher binds one exact registered first-party adapter identity and bounded context-evidence input before Core reads configuration. After Core has frozen configuration and effective policy, it invokes only that adapter's synchronous context projection over those owned bytes. The projection is side-effect free, performs no filesystem, Git, configuration, credential, or network access, and may return only an observed native-session workspace candidate or an exact unavailable reason. Core alone then selects and freezes the effective workspace and Git observation from the ordered candidates: launcher-bound hook workspace, projected native-session workspace, then the entry process working directory. Adapters never select the authoritative repository or run a later independent Git resolution.

**Context:** Transcript data, hook payloads, and process working directories can disagree or be incomplete.

**Consequences:** Core snapshots every candidate as an absolute canonical path under fixed path and command-output bounds, rejects nonexistent/non-directory candidates, and accepts a Git result only when Git proves that the selected workspace belongs to the returned worktree and repository. The selected workspace maps to `agentscope.workspace.directory`; Git's worktree top level maps to `agentscope.git.worktree`, while the repository root is the main worktree root for a linked worktree and otherwise the worktree top level. Credential-free remote identity maps to standard OTel VCS fields only after URI redaction; it is never used to choose the local repository.

Core invokes the owned Git executable without a shell, with a fixed argument inventory, sanitized environment, bounded stdout/stderr, the lesser of its short stage cap and the remaining hook budget, and no configuration or credential prompting. Global hook-deadline exhaustion stops initialization; a Git stage timeout while global time remains records Git as unavailable and permits capture to continue. The invocation snapshot records the complete exact field closure. Attached HEAD records head name, revision, and ref type as observed Git values. Detached HEAD records `vcs.ref.head.name` as `not-applicable` / `detached-head`, retains the observed revision, and records `vcs.ref.type` unavailable because the bounded status observation does not establish branch or tag authority. Not-a-repository, executable-missing, timeout, permission, malformed output, or internally inconsistent partial results record every Git-owned expected field as exact `unavailable` with one closed reason; independently resolved workspace evidence remains present. No family marker substitutes for the governed fields, no branch is inferred from environment or path names, and later repository changes do not mutate the snapshot.

### ADR-002: Normalize semantic primitives, retain native evidence

**Decision:** Map sessions, turns, model calls, tools, skills, files, errors, and child agents into a transient `CapturedTrace`; retain only sanitized raw-source identities after Core converts it to `RedactedCanonicalTrace`.

**Context:** Consumers need portable semantics and support engineers need a way to explain mappings, but raw native content cannot cross the redaction boundary.

**Consequences:** A harness adapter maps native evidence to OpenInference-shaped semantic candidates but cannot construct an exportable value. Core redaction and Protocol validation produce the applicable `AGENT`, `LLM`, `TOOL`, and other OTLP spans. `agentscope.*` remains limited to harness/Git/workspace/provenance concepts; model, message, token, timing, and error fields use their OpenInference definitions.

The harness-facing factory accepts exact descriptor-governed semantic terminals, a stable native operation locator or absolute pre-redaction ordinal, parent relations, native timing candidates, and explicit absence evidence. Protocol-owned candidate validation enforces value shapes and applicable upstream compound rules before Core stores the candidate. It rejects native transcript DTOs, OTLP placeholder graphs, provenance-group keys, lifecycle-owned Protocol fields, destination overlays, and provenance sources other than `native-artifact` or `hook-payload`. Core supplies snapshot identity, registered operation-ID scope, attempt identity, harness executable version evidence, and process observation context outside that input. Common high-dimensional embedding vectors fit the bounded transient representation even though the default redaction route later omits them.

### ADR-003: Persist only non-content incremental checkpoints

**Decision:** Adapters provide bounded native identity evidence and declare whether operation identifiers are session-global or parent-scoped; Core alone assigns canonical identities through Protocol. Each incremental adapter declares one closed monotonically ordered position kind. Before reading its capture window, the adapter must call the Core-supplied checkpoint resolver exactly once with its bounded native continuity evidence, generation, position kind, and earliest still-available position. Core reconstructs that request once as an exact frozen plain-data record, rejects accessors, symbols, proxies, extra keys, and malformed members, derives the digest from only that reconstruction, and returns one frozen `retained`, `replay-required`, `source-loss`, or `unavailable` disposition plus the authoritative start. Until the owned launcher supplies an isolated deadline-safe Operational State coordinator, the hook resolver performs no durable read: it returns `unavailable` at position zero or explicit `source-loss` at a later earliest-available position, so it can never jump past still-available unacknowledged input. The resolver is revoked as soon as the synchronous capture callback returns or throws. The captured boundary must match that same request reconstruction and returned start exactly; omission, duplicate or late resolution, or mismatch suppresses capture. Every attempted boundary supplies an exact half-open `[startPosition, exclusiveEndPosition)` with safe nonnegative values and `end > start`, plus a nonnegative adapter-observed source generation that never decreases or reuses an earlier value for the same native continuity source after rotation, replacement, or truncation. The start position is transient checkpoint evidence; the exclusive end remains part of canonical boundary identity. An incremental adapter may persist only versioned non-content checkpoints containing a fixed 32-byte SHA-256 digest over a domain/version prefix, exact adapter registry identity, declared native-identity kind, and at most 4 KiB of canonical UTF-8 native continuity evidence, plus generation, position kind, and acknowledged exclusive end; when destinations accept independently, checkpoint progress is connection-scoped. Core validates and includes generation and the exclusive end in capture-boundary identity, retains the start only until connection outcomes are classified, computes the digest from the same adapter evidence used for identity, then discards the raw digest input before any checkpoint call. A checkpoint never stores a native locator string, path, repository value, transcript value, `CapturedTrace`, or field copied from one.

**Context:** Append-only artifacts may be reread by repeated hooks. Advancing one global cursor can either duplicate earlier turns or skip delivery to a connection that did not accept them.

**Consequences:** Per connection, a checkpoint position is comparable only when adapter identity, continuity digest, native-identity kind, source generation, and position kind all match exactly. The next advancing boundary must have `startPosition` exactly equal to the prior durable exclusive end; Core advances only to the exclusive end of the highest contiguous prefix of accepted boundaries. Core serializes or compare-and-swap fences advancement against the previously acknowledged tuple and position; an out-of-order accepted boundary remains non-durable evidence and cannot skip an earlier unavailable, rejected, or outcome-unknown gap. A digest, generation, position-kind, or adjacency mismatch—including generation reuse—starts a separately identified bounded replay from the new source's available beginning, records fixed source-loss evidence, and never reuses or jumps to the old position. Adapters without stable native identity produce explicit boundary- or attempt-scoped at-least-once identity. Missing, expired, evicted, corrupt, or unavailable checkpoint evidence is never interpreted as an instruction to jump to the native tail: the adapter replays its declared bounded still-available window with the same stable identity inputs, emits a fixed checkpoint-unavailable or source-loss diagnostic when continuity cannot be proven regardless of later capture or delivery outcome, and accepts duplicates rather than skipping an available unacknowledged event. If an isolated coordinator loses its reply after an atomic replacement, the current hook does not claim persistence success; the next preload resolves the authoritative checkpoint and therefore retains only an already accepted committed boundary or replays from the prior durable end. Replay, append, rotation/truncation, restart, coordinator acknowledgement loss, concurrent out-of-order acceptance, every checkpoint-loss class, and partial-acceptance tests prove stable identity inputs and no skipped acknowledged events; destination idempotency determines whether repeated attempts are deduplicated.

### ADR-004: Preserve effective observation time without fabricating native intervals

**Decision:** OTLP span times are effective observation times. Protocol's manifest-pinned timing descriptor is the sole compatibility table for timing basis, native state, provenance source, location, construction, and interval-versus-point shape. A native interval or point cites observed `hook-payload` or `native-artifact` evidence; an artifact point cites `native-artifact` evidence with native timing unavailable; a hook-observed point cites the observing `process` with native timing unavailable. All point bases are zero-duration. When native root timing is unavailable and children occur at different effective times, the root alone uses `derived-child-envelope`: source `derived`, native state `unavailable`, start equal to the minimum descendant start, and end equal to the maximum descendant end.

**Context:** OTLP requires start and end timestamps, while native harness evidence may omit one or both. Silently synthesizing an apparent native operation duration would create false precision.

**Consequences:** Core constructs timing evidence by looking up the exported Protocol rule rather than duplicating source assumptions. Configuration and Git provenance cannot claim timing; generic derived provenance is valid only for the root-only descendant envelope. Start and end use the same rule and source. A derived envelope requires at least one descendant and must match the exact descendant bounds; it never claims a native root operation interval. Direct parent/event containment is not required because native operations may be asynchronous or use mixed clocks. Missing native timing remains explicitly unavailable even when a hook-observed point or derived envelope satisfies the OTLP wire requirement. Protocol rejects unsupported combinations with content-free validation codes.

### ADR-005: Construct compact indexed provenance from exact claims

**Decision:** Core supplies exact post-redaction present fields, exact per-field provenance claims, and exact unavailable claims to Protocol's ledger builder. Protocol alone compresses present indexed OpenInference members using manifest-fingerprinted, segment-based object-group specifications cross-validated against accepted semantic template identifiers and span kinds. Resolution precedence is exact terminal, deepest claimed group, then ancestor group.

**Context:** Flattened messages, tool calls, prompts, embeddings, and documents can contain many terminals from one native object. Repeating one source for every terminal is noisy, but letting adapters author group keys or regexes would duplicate Protocol grammar and make mixed-source members ambiguous.

**Consequences:** A group is only a compression default for members actually present in that span; it is never a native field and can never be unavailable. The builder may emit a group when at least two covered members share a unique default source, retains deeper group overrides and exact terminal overrides, canonical-sorts both ledgers, and rejects missing, duplicate, conflicting, unknown, kind-mismatched, ambiguous, or over-budget claims. Unavailable members always retain exact provenance plus an exact absence record. Canonical validation and Core construction use the same frozen target resolver; Core never supplies group keys, segment patterns, or precedence logic.

Events and links additionally use manifest-fingerprinted indexed member evidence. `span.events.<i>.event` and `span.links.<i>.link` prove atomic existence; name, time, relationship, and descriptor-valid attribute suffixes retain their own exact sources. The index is the original bounded source-order identity: omitted whole members and redacted attributes remain exact unavailable holes, while the retained OTLP arrays align to ascending present indices without renumbering. Aggregate `span.events` and `span.links` describe collection existence; `span.links.target_ids` separately records Protocol's derived wire-identity projection.
