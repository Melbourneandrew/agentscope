## Capability Summary

Agentscope must interoperate with industry telemetry without becoming dependent on an immature single AI schema.

## Architecture Decision Records

### ADR-001: Emit OpenTelemetry transport identity

**Decision:** Protocol uses OTel trace/span context and only explicitly allowlisted, redacted resource attributes in its canonical OTLP graph. Reporters preserve them wherever their destination supports it and disable automatic resource detection unless a detector's output is individually normalized and allowlisted.

**Context:** OTel is the broadly adopted trace transport and semantic-convention foundation, but SDK defaults may expose host, process, user, or environment identity outside a canonical payload.

**Consequences:** Export-contract tests assert the resource attribute allowlist as well as span fields; destination packages cannot add arbitrary environment-derived attributes.

### ADR-002: Own only transport interoperability here

**Decision:** This Blueprint owns OTLP protobuf/JSON transport encoding, redacted resource encoding, and detector allowlists. It consumes the OpenInference baseline and `agentscope.*` registry owned by Canonical Trace Format without redefining either.

**Context:** This gives Agentscope portable agent/LLM/tool semantics and direct OTLP interoperability while preserving the additional coding-agent domain context that OpenInference does not model.

**Consequences:** Transport tests use the Protocol manifest identifier and canonical fixtures. A transport or destination cannot reinterpret canonical fields or silently enable automatic resource detection.
