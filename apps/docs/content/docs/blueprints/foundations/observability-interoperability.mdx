## Capability Summary

Agentscope must interoperate with industry telemetry without becoming dependent on an immature single AI schema.

## Architecture Decision Records

### ADR-001: Emit OpenTelemetry transport identity

**Decision:** Protocol uses OTel trace/span context and only explicitly allowlisted, redacted resource attributes in its canonical OTLP graph. Reporters preserve them wherever their destination supports it and disable automatic resource detection unless a detector's output is individually normalized and allowlisted.

**Context:** OTel is the broadly adopted trace transport and semantic-convention foundation, but SDK defaults may expose host, process, user, or environment identity outside a canonical payload.

**Consequences:** Export-contract tests assert the resource attribute allowlist as well as span fields; destination packages cannot add arbitrary environment-derived attributes.

### ADR-002: Own only transport interoperability here

**Decision:** This Blueprint owns OTLP protobuf/JSON transport encoding, redacted resource encoding, and detector allowlists. It consumes the OpenInference baseline and `agentscope.*` registry owned by Canonical Trace Format without redefining either.

**Context:** This gives Agentscope portable agent/LLM/tool semantics and direct OTLP interoperability while preserving the additional coding-agent domain context that OpenInference does not model.

**Consequences:** Transport tests use the Protocol manifest identifier and canonical fixtures. A transport or destination cannot reinterpret canonical fields or silently enable automatic resource detection.

### ADR-003: Own raw OTLP codecs in Protocol

**Decision:** Protocol owns the strict OTLP/JSON producer and bounded external JSON/protobuf readers and generates the binary message types/codecs from the exact OTLP v1.11 proto closure pinned in the standards manifest. The manifest records Buf, Protobuf-ES runtime/plugin, source revision, normalized generator configuration, every proto input hash, every generated-output hash, receiver rules, budgets, and current persisted-reader support before a codec is accepted. Generation is offline during normal build/install; verification regenerates into a temporary directory with the local exact toolchain and byte-compares committed output. Agentscope does not use `@opentelemetry/otlp-transformer` as its canonical codec.

**Context:** The official transformer package is experimental and its public trace request surface accepts SDK `ReadableSpan` values; the raw request DTOs needed by Protocol are internal and unexported. Protocol needs independent JSON and protobuf readers for canonical values rather than an SDK exporter abstraction.

**Consequences:** The producer emits lowercase hexadecimal trace/span identities, canonical base64 for other bytes, integer enums, and decimal-string 64-bit integers. The external reader follows ProtoJSON plus the OTLP deviations independently: identity hex is case-insensitive; other bytes accept only valid standard or URL-safe padded or unpadded base64; quoted 64-bit integers remain exact while bare numbers have binary64 semantics; quoted 32-bit integers and finite or special floating-point strings are accepted; and `null` unsets a known field. Only exact lowerCamel known names are recognized, known proto snake_case aliases reject, and every unknown name is ignored regardless of spelling. Repeated identical JSON keys use the last value because the bounded parser preserves their order, while simultaneous alternate oneof members reject as ambiguous. Binary preflight validates tags, wire types, varints, declared lengths, nesting, matching bounded unknown groups, and field totals before generated recursive decoding; legal repeated singular/oneof fields retain protobuf last-wins or message-merge semantics. Each caller-owned byte view is copied once after the raw-size check, and the same owned snapshot is preflighted and decoded. Generated decoding drops unknown fields. Vendored proto inputs preserve the exact upstream bytes, every input/output directory has an exact regular-file closure, and offline regeneration byte-compares the entire pinned output. Generated code never becomes a source of hand-maintained semantic definitions. Compression, content headers, streaming decompression ratios, timeouts, and transport cancellation remain reporter/retriever responsibilities; Protocol imports no filesystem, network, or compression behavior.
