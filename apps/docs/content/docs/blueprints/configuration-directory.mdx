## Capability Summary

This Blueprint records how Agentscope persists configuration and operational state for the [Configuration Directory](/docs/requirements/configuration-directory) requirement.

## Architecture Decision Records

### ADR-001: Use one explicit Agentscope home

**Decision:** Resolve the default home as `~/.agentscope` on every supported platform, with `AGENTSCOPE_HOME` as the single explicit override.

**Context:** A stable product-owned path is easier for users, hooks, diagnostics, and hermetic tests to understand than platform-specific paths or several overlapping override variables.

**Consequences:** Path resolution occurs once in the CLI composition root and is injected into adapters and reporters. Tests set only `AGENTSCOPE_HOME`.

### ADR-002: Separate configuration, secrets, and operational state

**Decision:** Keep non-secret declarative configuration, locks/migration markers, bounded spool data, and diagnostics under separate subdirectories; store actual credentials in the OS credential store or CI environment.

**Context:** Configuration must be inspectable and migratable without turning a backup or doctor report into a credential leak.

**Consequences:** Configuration contains credential references, never token values. Spool and diagnostics have explicit retention bounds.

### ADR-003: Use atomic, versioned updates

**Decision:** Schema-validate configuration, write a same-directory temporary file, fsync where supported, and atomically rename; migration creates a bounded backup first.

**Context:** Hooks and interactive CLI commands may coexist, and interruption must not leave malformed configuration as the only copy.

**Consequences:** Hooks fail open on lock contention. `agentscope doctor --fix` may complete only known-safe migrations.
