## Resolution and ownership

```ts
function resolveAgentScopeHome(env: NodeJS.ProcessEnv, home: string): string {
  return env.AGENTSCOPE_HOME ?? path.join(home, ".agentscope");
}
```

`AGENTSCOPE_HOME` is intentionally the only override. A single root is easy to explain and makes hermetic harness tests trivial: each scenario receives a temporary root. The code must resolve once at process startup, canonicalize it, and pass a `ConfigPaths` value through the application instead of reading environment variables throughout reporters and adapters.

## Safe read/write API

```ts
interface ConfigStore {
  load(): Promise<LoadedConfig>;
  update(
    mutator: (config: AgentScopeConfig) => AgentScopeConfig,
  ): Promise<void>;
  migrate(): Promise<MigrationResult>;
}
```

`load` parses and schema-validates JSON into a typed domain model. `update` obtains a short-lived lock, validates the proposed model, serializes it deterministically, writes `config.json.tmp-<random>` with mode `0600`, fsyncs the file, atomically renames it over `config.json`, then fsyncs the containing directory where supported. Never edit JSON in place.

The store should use a mature cross-platform lock implementation or a small lock-file protocol with owner PID/start time and stale-lock detection. A hook must fail open if it cannot acquire the lock promptly; interactive CLI commands may wait briefly and return an actionable conflict error.

## Versioning and migrations

Every config document starts with `schemaVersion`. Migrations operate on parsed data, not untyped JSON, and each migration is pure and unit-tested from every supported prior version. Before changing a document, the CLI places a timestamped backup in `state/backups/`; it retains a bounded number of backups and never includes secrets.

`agentscope doctor --fix` may finish an interrupted, known-safe migration only after verifying the backup and target schema. It does not silently discard unknown keys: preserve them under an extension namespace or stop with an upgrade error so newer config is not corrupted by an older CLI.

## Separation of concerns

| Location                   | Contents                                         | Retention                  |
| -------------------------- | ------------------------------------------------ | -------------------------- |
| `config.json`, `profiles/` | Declarative, non-secret user intent              | Backed up during migration |
| OS credential store        | API tokens and client secrets                    | Managed by the platform    |
| `state/`                   | Installation ownership, locks, migration markers | Rebuildable/repairable     |
| `spool/`                   | Redacted, bounded undelivered batches            | TTL and size-limited       |
| `diagnostics/`             | Sanitized health evidence                        | TTL and size-limited       |

This division lets `agentscope doctor` and integration tests inspect configuration safely, lets a user back up intended configuration without leaking tokens, and prevents operational state from becoming configuration truth.
