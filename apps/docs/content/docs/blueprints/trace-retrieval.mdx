# Trace Retrieval

## Capability Summary

This Blueprint records how the CLI fulfills [Trace Retrieval](/docs/requirements/trace-retrieval) without coupling all reporters to Langfuse.

## Architecture Decision Records

### ADR-001: Make retrieval an optional adjacent plugin capability

**Decision:** A reporter plugin may expose a separate retrieval capability; reporting itself remains write-oriented.

**Context:** Some valid destinations are OTLP-only or write-only. Forcing them to implement search would create fake behavior and muddle failure modes.

**Consequences:** The CLI can report unsupported retrieval honestly while a Langfuse plugin can map portable searches to its API.

### ADR-002: Keep portable query semantics in the CLI

**Decision:** The CLI owns portable filters and result presentation; a retriever owns authentication, provider-filter translation, pagination, and unsupported-filter errors.

**Context:** Users need stable command semantics while destinations vary in query vocabulary and capabilities.

**Consequences:** Retrieval remains read-only and does not need a running harness or workspace.
