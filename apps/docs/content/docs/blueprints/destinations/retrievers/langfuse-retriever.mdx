title: Langfuse Retriever
description: ADRs for mapping portable Agentscope retrieval onto Langfuse APIs.

## Capability Summary

The Langfuse Retriever searches and reconstructs Agentscope-reported traces from a configured Langfuse project without exposing Langfuse API shapes to the CLI.

## Architecture Decision Records

### ADR-001: Retrieve through the Langfuse Observations API

**Decision:** The Retriever uses the immutable compatibility profile and manifest identity persisted for the connection during configuration. Langfuse Cloud and only exact manifest-enumerated self-hosted v4 versions use Observations API v2 with operation-specific field groups and its returned cursor. A reviewed self-hosted v3 events-table profile may advertise retrieval through deprecated Observations API v1 only for an exact manifest-enumerated version whose evidence exposes the advanced `filter` parameter and proves every portable predicate against the exact observation `metadata` and `traceTags` filter grammar; every v1 request sends the immutable selector `useEventsTable=true`, uses bounded page-offset continuation, and respects the endpoint's lower page limit. Omission, false, or mutation of that selector is a profile-conformance failure. The exact version/profile is an explicit operator-selected configuration admission key, not an authenticated attestation of the endpoint's deployed bytes. Protected evidence binds that profile version to exact image and source identities, but configuration and Doctor do not claim that a remote same-version deployment is byte-identical. A self-hosted version not enumerated by the manifest does not inherit compatibility from a semantic-version range. The profile does not apply to the older v1 observations-table path or to other v3 releases. Both advertised profiles always submit bounded start-time filters for search and group returned observation rows by `traceId`. If configuration cannot select a profile that implements every portable predicate, the connection withholds retrieval capability rather than weakening an individual query. Deprecated v1 is never selected for Langfuse v4, where that read API is removed.

**Context:** Langfuse's current API returns observation rows rather than complete trace objects, uses cursor pagination, sorts by start time descending, and supports selective field retrieval. Self-hosted v3 exposes only the deprecated full-row, page-offset endpoint. Self-hosted compatibility cannot be allowed to fork portable flags or result types.

**Consequences:** Configuration selects one tested transport profile without persisting credentials or response content. The selected exact version/profile and manifest identity participate in normalized connection settings and configuration identity, so Core cursor binding covers the endpoint and continuation grammar. The operator is responsible for selecting the profile that matches the self-hosted deployment; a modified or falsely versioned server is unsupported and provider behavior is still treated as untrusted. Doctor is observational only and may report a version mismatch, but it does not authenticate or silently change selection. A server upgrade or profile change requires explicit migration or reconfiguration; old cursors then fail configuration-identity validation before a provider token reaches the Retriever. Reporter and Retriever consume the same selection. Transport selection does not change portable flags, results, or errors. The destination compatibility manifest pins exact self-hosted versions rather than ranges and records the protected image/source evidence provenance for each one, plus endpoints, authentication, mandatory request selectors, field groups, one authoritative structured-filter composition, serialization, encoding, and precedence rule, page limits, continuation form, rate-limit mapping, response budgets, one current retrieval-capsule grammar, source revisions, and sanitized contract fixtures. Adding or changing a self-hosted version, capsule rule, or wire rule produces a new manifest and configuration identity. The fixtures include one positive and one negative request for every portable predicate, always composed with the reserved capsule-header predicate, plus explicit selector-present, omitted, false, and mutated v1 cases. Undocumented behavior and live visibility timing remain unclaimed until the protected compatibility workflow verifies them.

### ADR-002: Make the Reporter projection retrieval-aware

**Decision:** The Langfuse Reporter preserves the canonical W3C trace ID on every canonical span and projects Langfuse presentation fields without making the provider's mutable trace aggregate authoritative. All canonical observations retain the canonical OpenInference and `agentscope.*` attributes. For portable retrieval it creates one immutable capsule-header observation for each logical item in each Reporter invocation. The header carries a reserved current-version marker and all portable search keys and summary-only facts in exact observation-local fields: canonical TraceId; trace start/end; first-class session plus reserved v1 fallback; harness, branch, repository-safe identity, status, and canonical span count; and collision-checked reserved metadata entries plus a bounded indexed mirror for every canonical model identity and safe user tag. The manifest binds the exact metadata-key derivation, count, index, value, collision, and summary rules. Langfuse trace tags may still be populated for native presentation, but trace-scoped tag union across repeated graphs is never portable filter or reconstruction authority.

The Reporter encodes only the canonical graph through Protocol's current external-OTLP-compatible JSON codec before applying the Langfuse projection. It never serializes or projects the Agentscope delivery envelope, delivery identity, or stability class as data. Before its sole transport call, it mints one cryptographically random 128-bit capsule nonce per logical item for that Reporter invocation, rejects an all-zero nonce, and retains it only in the immutable request plan. Reporter code does not retry that transport call; a later Reporter invocation always mints a new nonce even for the same ASID delivery identity. If the graph-only OTLP JSON exceeds 131,072 UTF-8 bytes, the Reporter rejects the logical item before transport. Otherwise it base64url-encodes the exact bytes without padding, divides that text into fixed 180-ASCII-character chunks, and appends at most eleven immutable capsule-carrier observations. Through the pinned documented `langfuse.observation.metadata.*` wire prefix, the header stores the exact lowercase-hex capsule nonce, capsule version, graph-byte count, SHA-256 graph digest, and carrier/chunk counts. Header and carrier SpanIds use separate domain-separated deterministic collision-checked derivations from canonical TraceId, capsule version, nonce, fixed role, and dense carrier index. The exact bounded destination revision is the 32-character nonce: a random non-content attempt identity, not ASID delivery identity, the graph digest, or another content fingerprint. The digest remains private capsule-integrity data and never enters a portable locator or summary. Capsule metadata values never exceed the pinned events-table 200-character retained-value boundary. The manifest owns the randomness source and failure behavior, nonce grammar, header/carrier names, metadata keys and wire mapping, integer grammar, chunk distribution, ID derivation domains, revision encoding, size formulas, and rejection rules.

The header and every carrier are transport-only OTLP spans with the canonical TraceId and logical-root parent SpanId; a manifest-owned instrumentation scope distinct from the canonical graph; an exact reserved name; `INTERNAL` span kind; the canonical trace start instant for both start and end; unset status; zero flags and dropped counts; no events or links; no user, OpenInference, or arbitrary resource/span attributes; and only their closed capsule or summary attributes. They copy the canonical resource attributes required for Langfuse project routing and Protocol manifest accounting, and no others. Their provider traversal order is the pinned `(start time DESC, provider TraceId hash DESC, SpanId DESC)` order; equal-trace revision selection is therefore the exact header SpanId descending, not delivery identity, arrival time, or a claim of latest capture boundary. They may be visible as reserved internal observations in Langfuse, but cannot expand trace timing, participate in native trace aggregates as canonical spans, or be returned as canonical spans.

**Context:** Langfuse can filter first-class observation fields and exact string metadata, but it cannot infer Agentscope's branch, repository, or harness semantics from arbitrary OTLP attributes. Its OTLP ingestion maps observations into provider rows and does not expose canonical links, span events, nanosecond structural timing, flags, or every other canonical structural field through the Observations response. Reconstructing from those rows alone would silently lose reported data. Retrieval must not rely on downloading an unbounded project, filtering locally, or pretending a lossy provider projection is the reported canonical graph.

**Consequences:** Reserved Langfuse metadata keys and tag prefixes are a tested Reporter/Retriever contract, not a second canonical schema. User metadata and tags cannot overwrite them, and reserved tags are omitted from portable user-tag output. Search obtains a complete portable summary from capsule headers without returning chunks or performing a per-result native read. Duplicate provider rows with byte-identical closed fields collapse, while a duplicate nonce, deterministic ID, or dense index with conflicting fields is malformed. Any later Reporter invocation produces an independent immutable header and carrier set, including replay of the same delivery identity under identical or changed policy, configuration, Protocol state, or graph bytes. Search and TraceId-only get first exactly validate the complete bounded current-marker header response; any malformed or conflicting candidate makes the operation `malformed-response`. After validation, search returns at most one revision for a canonical TraceId within one page by retaining its first header in provider order, and direct get selects the first header under the same order at command time. No current header produces an empty search contribution or `not-found` get. Remote best-effort pagination can repeat that TraceId on a later page as already permitted by Query ADR-005. A full structured locator pins its exact header revision. Carrier completeness does not participate in selection: missing or malformed carriers for the selected header terminate get as `malformed-response`, and the Retriever never probes a lower-ranked revision. This is deterministic bounded selection from an immutable set, not latest-boundary or last-writer semantics. Commit-then-lost-ack and partial provider persistence remain `outcome-unknown`, and retrieval never upgrades them to a Reporter receipt, but a later completely observed header-plus-carrier set may be retrieved.

The graph limit, chunk formulas, complete root/carrier DTO formulas, final OTLP request byte measurement, provider page-size and response-byte formulas, and aggregate decode ledger are executable manifest fixtures rather than prose arithmetic. A logical item is attempted only if its complete canonical-spans-plus-carriers expansion fits the Reporter request ceiling; batching never splits one logical item's expansion. Get is admitted only when the complete matching carrier set fits the operation's request, page, aggregate response, and decode ceilings. Boundary fixtures cover one below, at, and above every limit. These are explicit destination limits, not a claim that every Protocol-valid maximum graph or every 32-item Reporter batch is deliverable or retrievable.

V1 summary reconstruction requires a complete canonical mirror and rejects missing, extra, duplicate, noncanonical, or over-limit entries as malformed provider data. Capsule digest validation detects truncation, reordering, and accidental corruption but is not authentication: the reconstructed OTLP graph remains untrusted, must strictly pass Protocol's current external-OTLP reader, must contain the selected canonical TraceId, and must be an unchanged fixed point under Core's current policy. A current-version header or exact revision that is absent returns `not-found`; the Retriever does not query historical markers merely to distinguish a pre-capsule, prior-version, or never-present record. Malformed, duplicate-conflicting, partial, or internally inconsistent current-version headers or carriers return `malformed-response`; a current-version graph that is structurally valid but not admitted by the current Protocol or policy contract returns `incompatible-trace`. Length limits, unsupported values, header/carrier-ID collisions, and reserved-key collisions are validated before delivery.

### ADR-003: Map portable filters without semantic weakening

**Decision:** Agentscope owns one canonical filter-composition rule: every search submits exactly one structured filter array containing the exact current capsule-header marker and every applicable portable predicate. It does not split portable predicate authority between Langfuse's structured and individual filter surfaces. Half-open time bounds map to header `startTime >= from` and `startTime < to`; canonical TraceId maps to exact `traceId`; session maps to exact header `sessionId` on v2 and its reserved metadata on v1; model, harness, branch, and every requested user tag map to exact collision-checked header metadata keys and values. Repository-safe identity remains a portable summary field, not a search predicate. The v1 `useEventsTable=true` selector remains a separate immutable transport control, never a portable predicate. The Retriever builds closed typed predicate objects in a manifest-pinned predicate and property order, preserves portable strings as data without interpolation or normalization, serializes the array once as JSON, and percent-encodes that JSON exactly once into one `filter` query key. It rejects duplicate `filter` or `useEventsTable` keys and any individual portable-filter query key. The Retriever validates every returned header against the normalized request after bounded provider parsing.

**Context:** Langfuse merges structured and individual filters that target different physical fields, but an advanced structured filter takes precedence over an individual filter for the same field. The current header metadata predicate does not shadow distinct trace-ID, start-time, or session fields. A single Agentscope-owned composition avoids a second precedence-dependent request grammar, makes every supported profile use the same reviewed predicate inventory, and closes future same-field collisions. Historical records can also produce broader matches than Agentscope's exact portable semantics.

**Consequences:** A profile that cannot express any portable predicate in the one structured-filter grammar never advertises retrieval capability. An advertised profile never silently ignores a predicate, splits portable authority across request surfaces, or implements a predicate through an unbounded client scan. The compatibility fixtures reject missing, duplicated, reordered-to-different-semantics, separately supplied, or multiply encoded portable predicates; prove match and miss behavior for each dimension while the current header marker is present; separately pin the provider's same-field shadowing and different-field merging behavior; and cover quotes, backslashes, query metacharacters, brackets, and Unicode without placing input or provider text in diagnostics. Bounded defensive post-validation may remove false positives, but it is never the primary implementation of a portable filter.

### ADR-004: Search immutable capsule headers and reconstruct by revision

**Decision:** Search queries only observations carrying the exact current capsule-header marker with the profile's summary field groups, preserves provider traversal, and collapses byte-identical duplicate headers plus repeated canonical TraceIds within the returned page. It returns the selected header's exact 128-bit capsule nonce as the locator's bounded non-content destination revision. The capsule profile admits exactly one current writer/reader version backed by Protocol's current external OTLP reader; a version change changes the provider-side marker, manifest, and configuration identity rather than creating a Langfuse-owned historical parser window.

Get with a destination revision queries that exact current header nonce and verifies its canonical TraceId, derived SpanId, and closed header fields. Get with only a canonical TraceId queries current-version headers for that trace, exactly validates the complete bounded response, and selects the first header in manifest-pinned provider order without reading carriers; any malformed/conflicting header is terminal `malformed-response`, and no header is `not-found`. It then requests only carrier observations matching the selected TraceId, version, digest, nonce, and derived ID domain under the operation bounds. It accepts exactly the declared dense carrier and chunk sets, collapses only byte-identical duplicate rows, rejects conflicting duplicates and undeclared capsule fields, reassembles chunks after exact-key parsing, and verifies the declared byte count and SHA-256 digest before JSON parsing. Missing or malformed selected carriers are terminal `malformed-response`; get never probes another header. It uses Protocol's current bounded external-OTLP reader, binds the decoded graph TraceId to the requested locator, and verifies the graph's current Protocol manifest identity. Provider-native names, content, status, metadata, arrival time, and nonselected revisions never override the capsule.

**Context:** One canonical TraceId can have multiple immutable reported graphs because appended capture boundaries retain trace identity and delivery is at least once. Langfuse does not provide mutable observation updates or read-path deduplication, so neither arrival order nor repeated provider IDs are a valid active-record authority.

**Consequences:** Search remains lightweight; get pays the cost of bounded graph reconstruction. A graph completely observed through one current header and all matching carriers round-trips through the current graph-only codec, subject to current-policy fixed-point governance. This is retrieval evidence, not retroactive proof that a previous Reporter attempt returned `accepted`. A capsule version change is an intentional manifest/configuration migration: new searches use only the new provider-side marker, cursors fail configuration-identity validation, and a stored nonce from a prior version follows the same bounded current-marker lookup as any other revision and returns `not-found` when absent. Invalid or internally inconsistent current-version provider data returns `malformed-response`; incompatible current-version graph evidence returns `incompatible-trace`. Historical Agentscope records and non-Agentscope Langfuse traces never fabricate a portable partial graph and are not queried merely to classify their history. A separately reviewed future decision may add a Protocol-owned historical graph-reader archive and version-bound locator plus finite provider-side multi-version query, but v1 does neither.

### ADR-005: Bind pagination and identity to the configured project

**Decision:** The Core cursor envelope wraps the Langfuse cursor or compatible page position together with the immutable connection ID, normalized query fingerprint, and fixed upper time bound. Search and get accept only W3C-format canonical TraceIds for Agentscope-reported traces. The capsule nonce is the bounded non-content destination revision; provider observation IDs remain provenance only.

**Context:** Langfuse trace IDs are W3C-compatible 32-character hexadecimal identifiers, but two configured projects can contain the same ID. A raw provider cursor does not identify its project or original filters.

**Consequences:** Credentials, host, and project binding come from the resolved destination connection, never cursor data. Cursor reuse across projects, connections, or filters fails locally. Reporter contract tests prove that OTLP ingestion preserves the trace ID used for subsequent retrieval.

### ADR-006: Validate against both mock and real Langfuse behavior

**Decision:** Unit tests use synthetic, reviewed provider DTO fixtures and generated malformed cases; those fixtures prove parser and request-shape behavior, not provider compatibility by themselves. Hermetic destination tests use a Langfuse-compatible request ledger that asserts endpoint, authentication shape, filters, field groups, cursor flow, the complete header/carrier OTLP wire shape, and reconstruction. They cover empty/minimum and exact-limit capsules; one-below/at/above every graph, chunk, carrier, request, page, aggregate-response, and decode boundary; deterministic header/carrier ID collision handling; reserved-key collision; malformed base64url; wrong byte count/digest/TraceId/version; missing/duplicate-identical/duplicate-conflicting/reordered/extra headers, chunks, and carriers; prior versions; and response/request/deadline limits. A malformed higher-ranked header plus a valid lower header is terminal `malformed-response`; zero current headers is empty search or `not-found`; missing selected carriers never cause fallback. Each Reporter invocation makes one transport call and mints one nonce per logical item; later invocations for the same delivery identity use distinct nonces under identical and changed policy/configuration/graph states. Commit-then-lost-ack, multiple appended capture boundaries, provider-order selection, page-split repeated TraceIds, exact-revision get, and canonical-TraceId get prove immutable selection without treating delivery identity or arrival time as an ordering key.

The protected compatibility workflow deterministically seeds the complete portable match/miss matrix plus same-field-shadow, different-field-merge, selector, hostile-character, and multi-carrier capsule cases; executes it against exact manifest-pinned self-hosted v3 and v4 build digests and the isolated current Langfuse Cloud test project; and regenerates sanitized, hashed request/response-shape artifacts through one reviewed sanitizer. It proves every 180-character carrier metadata value survives exact round trip, carrier observations do not appear in header search, exact duplicate header/carrier delivery collapses, conflicting duplicates fail, provider ordering selects the same revision for direct get, exact revision lookup remains pinned, and the matching carrier set is returned by bounded TraceId-plus-capsule traversal. It also reports a uniquely tagged trace containing at least one canonical event and link, polls within a bounded visibility window, searches it through the Retriever, gets it by both locator forms, compares the complete graph-only OTLP round trip, and deletes or expires the fixture according to the test-project policy. This evidence is a trusted candidate and release gate, not a runtime revocation feed: every record binds the exact package commit, manifest identity, provider source or image identity, sanitizer identity, and execution time, and Cloud evidence must be no more than seven days old when the release candidate is admitted. A mismatching or stale profile fails that candidate until a reviewed manifest migration or fresh matching evidence is supplied.

**Context:** A hand-written mock proves Agentscope logic but cannot detect changes in Langfuse ingestion projection, field availability, filter operators, or eventual visibility.

**Consequences:** Protected tests run with isolated credentials and never on untrusted pull requests. Their fixed seed, provider image/source identities, sanitizer identity, artifact hashes, and manifest identity make the full matrix reproducible without retaining credentials or trace content. The Cloud result is time-bounded evidence for the observed deployment rather than a claim of an immutable Cloud build. Tests use the non-deprecated trace-deletion endpoint for their exact test traces, then poll within the documented asynchronous-deletion window without claiming immediate cleanup. Compatibility drift fails with sanitized request/response-shape diagnostics and retained non-content artifacts; synthetic fixtures cannot override it. A later scheduled drift result blocks affected profiles from a future candidate or package selection until reviewed, but it cannot silently change an installed configuration, its advertised capability, or existing cursor identity. Reporter and Retriever releases share the same Langfuse compatibility evidence.
