## Capability Summary

The Langfuse Retriever searches and reconstructs Agentscope-reported traces from a configured Langfuse project without exposing Langfuse API shapes to the CLI.

## Architecture Decision Records

### ADR-001: Retrieve through the Langfuse Observations API

**Decision:** The Retriever uses the immutable compatibility profile and manifest identity persisted for the connection during configuration. Langfuse Cloud and only exact manifest-enumerated self-hosted v4 versions use Observations API v2 with operation-specific field groups and its returned cursor. A reviewed self-hosted v3 events-table profile may advertise retrieval through deprecated Observations API v1 only for an exact manifest-enumerated version whose evidence exposes the advanced `filter` parameter and proves every portable predicate against the exact observation `metadata` and `traceTags` filter grammar; every v1 request sends the immutable selector `useEventsTable=true`, uses bounded page-offset continuation, and respects the endpoint's lower page limit. Omission, false, or mutation of that selector is a profile-conformance failure. The exact version/profile is an explicit operator-selected configuration admission key, not an authenticated attestation of the endpoint's deployed bytes. Protected evidence binds that profile version to exact image and source identities, but configuration and Doctor do not claim that a remote same-version deployment is byte-identical. A self-hosted version not enumerated by the manifest does not inherit compatibility from a semantic-version range. The profile does not apply to the older v1 observations-table path or to other v3 releases. Both advertised profiles always submit bounded start-time filters for search and group returned observation rows by `traceId`. If configuration cannot select a profile that implements every portable predicate, the connection withholds retrieval capability rather than weakening an individual query. Deprecated v1 is never selected for Langfuse v4, where that read API is removed.

**Context:** Langfuse's current API returns observation rows rather than complete trace objects, uses cursor pagination, sorts by start time descending, and supports selective field retrieval. Self-hosted v3 exposes only the deprecated full-row, page-offset endpoint. Self-hosted compatibility cannot be allowed to fork portable flags or result types.

**Consequences:** Configuration selects one tested transport profile without persisting credentials or response content. The selected exact version/profile and manifest identity participate in normalized connection settings and configuration identity, so Core cursor binding covers the endpoint and continuation grammar. The operator is responsible for selecting the profile that matches the self-hosted deployment; a modified or falsely versioned server is unsupported and provider behavior is still treated as untrusted. Doctor is observational only and may report a version mismatch, but it does not authenticate or silently change selection. A server upgrade or profile change requires explicit migration or reconfiguration; old cursors then fail configuration-identity validation before a provider token reaches the Retriever. Reporter and Retriever consume the same selection. Transport selection does not change portable flags, results, or errors. The destination compatibility manifest pins exact self-hosted versions rather than ranges and records the protected image/source evidence provenance for each one, plus endpoints, authentication, mandatory request selectors, field groups, one authoritative structured-filter composition, serialization, encoding, and precedence rule, page limits, continuation form, rate-limit mapping, response budgets, source revisions, and sanitized contract fixtures. Adding or changing a self-hosted version or wire rule produces a new manifest and configuration identity. The fixtures include one positive and one negative request for every portable predicate, always composed with the reserved root predicate, plus explicit selector-present, omitted, false, and mutated v1 cases. Undocumented behavior and live visibility timing remain unclaimed until the protected compatibility workflow verifies them.

### ADR-002: Make the Reporter projection retrieval-aware

**Decision:** The Langfuse Reporter preserves the canonical W3C trace ID and projects the portable search keys and summary-only facts onto the logical root observation: session ID into Langfuse's session field and reserved v1 fallback metadata; a reserved root marker; harness and branch into exact-filterable namespaced metadata; repository-safe identity and canonical span count into summary metadata; one reserved tag per canonical model identity; and user tags into Langfuse tags without altering their portable values. A bounded indexed reserved-metadata mirror carries canonical model identities and safe user tags for the pinned v1 response, which omits Langfuse tags. The manifest binds exact mirror count, index, value, and collision rules. All observations retain the canonical OpenInference and `agentscope.*` attributes.

**Context:** Langfuse can filter first-class observation fields and exact string metadata, but it cannot infer Agentscope's branch, repository, or harness semantics from arbitrary OTLP attributes. Retrieval must not rely on downloading an unbounded project and filtering locally.

**Consequences:** Reserved Langfuse metadata keys and tag prefixes are a tested reporter/retriever contract, not a second canonical schema. User metadata and tags cannot overwrite them, and reserved tags are omitted from portable user-tag output. Search obtains a complete portable summary from root rows without an unbounded child scan or per-result native read. V1 summary reconstruction requires a complete, canonical mirror and rejects missing, extra, duplicate, noncanonical, or over-limit entries as malformed provider data. Length limits, unsupported values, and collisions are validated before delivery; the canonical OpenInference plus `agentscope.*` graph remains authoritative when reconstructing a trace.

### ADR-003: Map portable filters without semantic weakening

**Decision:** Agentscope owns one canonical filter-composition rule: every search submits exactly one structured filter array containing the reserved Agentscope root-marker predicate and every applicable portable predicate. It does not split portable predicate authority between Langfuse's structured and individual filter surfaces. Half-open time bounds map to `startTime >= from` and `startTime < to`; canonical trace ID maps to exact `traceId`; session maps to exact `sessionId` on v2 and its reserved root metadata on v1; model maps to its reserved root tag; harness and branch map to exact root-metadata filters; user tags map to Langfuse trace tags with all requested tags required. Repository-safe identity remains a portable summary field, not a search predicate. The v1 `useEventsTable=true` selector remains a separate immutable transport control, never a portable predicate. The Retriever builds closed typed predicate objects in a manifest-pinned predicate and property order, preserves portable strings as data without interpolation or normalization, serializes the array once as JSON, and percent-encodes that JSON exactly once into one `filter` query key. It rejects duplicate `filter` or `useEventsTable` keys and any individual portable-filter query key. The Retriever validates every returned root against the normalized request after bounded provider parsing.

**Context:** Langfuse merges structured and individual filters that target different physical fields, but an advanced structured filter takes precedence over an individual filter for the same field. The current root metadata predicate does not shadow distinct trace-ID, start-time, or session fields. A single Agentscope-owned composition avoids a second precedence-dependent request grammar, makes every supported profile use the same reviewed predicate inventory, and closes future same-field collisions. Historical records can also produce broader matches than Agentscope's exact portable semantics.

**Consequences:** A profile that cannot express any portable predicate in the one structured-filter grammar never advertises retrieval capability. An advertised profile never silently ignores a predicate, splits portable authority across request surfaces, or implements a predicate through an unbounded client scan. The compatibility fixtures reject missing, duplicated, reordered-to-different-semantics, separately supplied, or multiply encoded portable predicates; prove match and miss behavior for each dimension while the root marker is present; separately pin the provider's same-field shadowing and different-field merging behavior; and cover quotes, backslashes, query metacharacters, brackets, and Unicode without placing input or provider text in diagnostics. Bounded defensive post-validation may remove false positives, but it is never the primary implementation of a portable filter.

### ADR-004: Search logical roots and reconstruct by trace ID

**Decision:** Search queries observations carrying the reserved Agentscope root marker with the profile's summary field groups and collapses duplicate roots deterministically. Get queries all observation rows for one canonical trace ID, follows cursor or page-offset pagination under the operation bounds, validates parent references, and reconstructs the OpenInference plus `agentscope.*` graph. Missing parents, multiple logical roots, or truncated pages produce explicit completeness diagnostics.

**Context:** A trace can contain many Langfuse observations, and logical root status is not identical to physical parentlessness. Returning the first observation would lose model, tool, token, and timing data.

**Consequences:** Search remains lightweight; get pays the cost of full reconstruction. A trace written by Agentscope can round-trip to the governed canonical graph within the documented Protocol compatibility window. Non-Agentscope Langfuse traces may return a portable partial representation with explicit provenance and unavailable fields, never fabricated Agentscope metadata.

### ADR-005: Bind pagination and identity to the configured project

**Decision:** The Core cursor envelope wraps the Langfuse cursor or compatible page position together with the immutable connection ID, normalized query fingerprint, and fixed upper time bound. Search and get accept only W3C-format canonical trace IDs for Agentscope-reported traces, while retaining any provider observation IDs solely as provenance.

**Context:** Langfuse trace IDs are W3C-compatible 32-character hexadecimal identifiers, but two configured projects can contain the same ID. A raw provider cursor does not identify its project or original filters.

**Consequences:** Credentials, host, and project binding come from the resolved destination connection, never cursor data. Cursor reuse across projects, connections, or filters fails locally. Reporter contract tests prove that OTLP ingestion preserves the trace ID used for subsequent retrieval.

### ADR-006: Validate against both mock and real Langfuse behavior

**Decision:** Unit tests use synthetic, reviewed provider DTO fixtures and generated malformed cases; those fixtures prove parser and request-shape behavior, not provider compatibility by themselves. Hermetic destination tests use a Langfuse-compatible request ledger that asserts endpoint, authentication shape, filters, field groups, cursor flow, and reconstruction. The protected compatibility workflow deterministically seeds the complete portable match/miss matrix plus same-field-shadow, different-field-merge, selector, and hostile-character cases; executes it against exact manifest-pinned self-hosted v3 and v4 build digests and the isolated current Langfuse Cloud test project; and regenerates sanitized, hashed request/response-shape artifacts through one reviewed sanitizer. It also reports a uniquely tagged trace, polls within a bounded visibility window, searches it through the Retriever, gets it, compares the canonical graph, and deletes or expires the fixture according to the test-project policy. This evidence is a trusted candidate and release gate, not a runtime revocation feed: every record binds the exact package commit, manifest identity, provider source or image identity, sanitizer identity, and execution time, and Cloud evidence must be no more than seven days old when the release candidate is admitted. A mismatching or stale profile fails that candidate until a reviewed manifest migration or fresh matching evidence is supplied.

**Context:** A hand-written mock proves Agentscope logic but cannot detect changes in Langfuse ingestion projection, field availability, filter operators, or eventual visibility.

**Consequences:** Protected tests run with isolated credentials and never on untrusted pull requests. Their fixed seed, provider image/source identities, sanitizer identity, artifact hashes, and manifest identity make the full matrix reproducible without retaining credentials or trace content. The Cloud result is time-bounded evidence for the observed deployment rather than a claim of an immutable Cloud build. Tests use the non-deprecated trace-deletion endpoint for their exact test traces, then poll within the documented asynchronous-deletion window without claiming immediate cleanup. Compatibility drift fails with sanitized request/response-shape diagnostics and retained non-content artifacts; synthetic fixtures cannot override it. A later scheduled drift result blocks affected profiles from a future candidate or package selection until reviewed, but it cannot silently change an installed configuration, its advertised capability, or existing cursor identity. Reporter and Retriever releases share the same Langfuse compatibility evidence.
