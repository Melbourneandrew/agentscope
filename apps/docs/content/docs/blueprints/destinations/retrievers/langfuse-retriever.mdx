## Capability Summary

The Langfuse Retriever searches and reconstructs Agentscope-reported traces from a configured Langfuse project without exposing Langfuse API shapes to the CLI.

## Architecture Decision Records

### ADR-001: Retrieve through the Langfuse Observations API

**Decision:** The Retriever uses the immutable compatibility profile and manifest identity persisted for the connection during configuration. Langfuse Cloud and self-hosted v4 use Observations API v2 with operation-specific field groups and its returned cursor. A reviewed self-hosted v3 events-table profile may advertise retrieval through deprecated Observations API v1 only when its pinned server range exposes the advanced `filter` parameter and its manifest proves every portable predicate against the exact observation `metadata` and `traceTags` filter grammar; every v1 request sends the immutable selector `useEventsTable=true`, uses bounded page-offset continuation, and respects the endpoint's lower page limit. Omission, false, or mutation of that selector is a profile-conformance failure. The profile does not apply to the older v1 observations-table path or to v3 releases outside that proven range. Both advertised profiles always submit bounded start-time filters for search and group returned observation rows by `traceId`. If configuration cannot select a profile that implements every portable predicate, the connection withholds retrieval capability rather than weakening an individual query. Deprecated v1 is never selected for Langfuse v4, where that read API is removed.

**Context:** Langfuse's current API returns observation rows rather than complete trace objects, uses cursor pagination, sorts by start time descending, and supports selective field retrieval. Self-hosted v3 exposes only the deprecated full-row, page-offset endpoint. Self-hosted compatibility cannot be allowed to fork portable flags or result types.

**Consequences:** Configuration selects one tested transport profile without persisting credentials or response content. The selected profile and manifest identity participate in normalized connection settings and configuration identity, so Core cursor binding covers the endpoint and continuation grammar. Doctor is observational only. A server upgrade or profile change requires explicit migration or reconfiguration; old cursors then fail configuration-identity validation before a provider token reaches the Retriever. Reporter and Retriever consume the same selection. Transport selection does not change portable flags, results, or errors. The destination compatibility manifest pins exact server ranges, endpoints, authentication, mandatory request selectors, field groups, filter grammar, page limits, continuation form, rate-limit mapping, response budgets, source revisions, and sanitized contract fixtures, including one positive and one negative v1 fixture for every portable predicate plus explicit selector-present, omitted, false, and mutated cases. Undocumented behavior and live visibility timing remain unclaimed until the protected compatibility workflow verifies them.

### ADR-002: Make the Reporter projection retrieval-aware

**Decision:** The Langfuse Reporter preserves the canonical W3C trace ID and projects the portable search keys and summary-only facts onto the logical root observation: session ID into Langfuse's session field and reserved v1 fallback metadata; a reserved root marker; harness and branch into exact-filterable namespaced metadata; repository-safe identity and canonical span count into summary metadata; one reserved tag per canonical model identity; and user tags into Langfuse tags without altering their portable values. A bounded indexed reserved-metadata mirror carries canonical model identities and safe user tags for the pinned v1 response, which omits Langfuse tags. The manifest binds exact mirror count, index, value, and collision rules. All observations retain the canonical OpenInference and `agentscope.*` attributes.

**Context:** Langfuse can filter first-class observation fields and exact string metadata, but it cannot infer Agentscope's branch, repository, or harness semantics from arbitrary OTLP attributes. Retrieval must not rely on downloading an unbounded project and filtering locally.

**Consequences:** Reserved Langfuse metadata keys and tag prefixes are a tested reporter/retriever contract, not a second canonical schema. User metadata and tags cannot overwrite them, and reserved tags are omitted from portable user-tag output. Search obtains a complete portable summary from root rows without an unbounded child scan or per-result native read. V1 summary reconstruction requires a complete, canonical mirror and rejects missing, extra, duplicate, noncanonical, or over-limit entries as malformed provider data. Length limits, unsupported values, and collisions are validated before delivery; the canonical OpenInference plus `agentscope.*` graph remains authoritative when reconstructing a trace.

### ADR-003: Map portable filters without semantic weakening

**Decision:** Time bounds map to `fromStartTime` and `toStartTime`; canonical trace ID maps to `traceId`; session maps to `sessionId` on v2 and its reserved root metadata on v1; model maps to its reserved root tag; harness and branch map to exact root-metadata filters; user tags map to Langfuse trace tags. Repository-safe identity remains a portable summary field, not a search predicate. The reserved root marker selects Agentscope logical roots independently of provider physical-parent semantics. The Retriever submits all applicable predicates server-side and validates every returned root against the normalized request.

**Context:** Provider filter syntax and historical records can produce broader matches than Agentscope's exact portable semantics.

**Consequences:** A profile that cannot express any portable predicate never advertises retrieval capability. An advertised profile never silently ignores a predicate or implements it through an unbounded client scan. Bounded defensive post-validation may remove false positives, but it is never the primary implementation of a portable filter.

### ADR-004: Search logical roots and reconstruct by trace ID

**Decision:** Search queries observations carrying the reserved Agentscope root marker with the profile's summary field groups and collapses duplicate roots deterministically. Get queries all observation rows for one canonical trace ID, follows cursor or page-offset pagination under the operation bounds, validates parent references, and reconstructs the OpenInference plus `agentscope.*` graph. Missing parents, multiple logical roots, or truncated pages produce explicit completeness diagnostics.

**Context:** A trace can contain many Langfuse observations, and logical root status is not identical to physical parentlessness. Returning the first observation would lose model, tool, token, and timing data.

**Consequences:** Search remains lightweight; get pays the cost of full reconstruction. A trace written by Agentscope can round-trip to the governed canonical graph within the documented Protocol compatibility window. Non-Agentscope Langfuse traces may return a portable partial representation with explicit provenance and unavailable fields, never fabricated Agentscope metadata.

### ADR-005: Bind pagination and identity to the configured project

**Decision:** The Core cursor envelope wraps the Langfuse cursor or compatible page position together with the immutable connection ID, normalized query fingerprint, and fixed upper time bound. Search and get accept only W3C-format canonical trace IDs for Agentscope-reported traces, while retaining any provider observation IDs solely as provenance.

**Context:** Langfuse trace IDs are W3C-compatible 32-character hexadecimal identifiers, but two configured projects can contain the same ID. A raw provider cursor does not identify its project or original filters.

**Consequences:** Credentials, host, and project binding come from the resolved destination connection, never cursor data. Cursor reuse across projects, connections, or filters fails locally. Reporter contract tests prove that OTLP ingestion preserves the trace ID used for subsequent retrieval.

### ADR-006: Validate against both mock and real Langfuse behavior

**Decision:** Unit tests use captured, reviewed provider DTO fixtures and generated malformed cases. Hermetic destination tests use a Langfuse-compatible request ledger that asserts endpoint, authentication shape, filters, field groups, cursor flow, and reconstruction. Protected live tests report a uniquely tagged trace to a real Langfuse project, poll within a bounded visibility window, search it through the Retriever, get it, compare the canonical graph, and delete or expire the fixture according to the test-project policy.

**Context:** A hand-written mock proves Agentscope logic but cannot detect changes in Langfuse ingestion projection, field availability, filter operators, or eventual visibility.

**Consequences:** Live tests run with isolated credentials and never on untrusted pull requests. They use the non-deprecated trace-deletion endpoint for their exact test trace, then poll within the documented asynchronous-deletion window without claiming immediate cleanup. Compatibility drift fails with sanitized request/response shape diagnostics and retained non-content artifacts. Reporter and Retriever releases share the same Langfuse compatibility evidence.
