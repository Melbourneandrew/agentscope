## Capability Summary

Retrievers let a named Trace Destination search and reconstruct previously reported traces through one destination-neutral Core contract.

## Architecture Decision Records

### ADR-001: Define one internal Retriever port

**Decision:** `packages/destinations/core` owns the internal `Retriever` port and its runtime-validated, process-branded DTOs. Every retriever implements exactly two operations: `search(TraceSearchRequest, RetrievalContext)` returning `TraceSearchPage`, and `get(TraceGetRequest, RetrievalContext)` returning `RetrievedTrace`. Concrete destination clients and provider DTOs remain private to their destination package.

**Context:** The CLI and coding agents need one predictable retrieval surface, while Langfuse and Local SQLite have different APIs, identities, and pagination mechanisms.

**Consequences:** The CLI never switches on destination type. `packages/core` resolves one named connection, binds its credentials and deadline, invokes its Retriever, validates the result, reapplies governance, and returns presentation-safe DTOs. The interface is an internal first-party seam, not a published SDK or plugin contract.

### ADR-002: Make search and get the mandatory portable capability

**Decision:** A destination advertises retrieval only when its descriptor supplies one synchronous factory that returns a runtime-recognized Retriever implementing both portable operations. Search accepts the canonical filter vocabulary and returns bounded summaries; get accepts a destination-qualified trace locator and returns a normalized trace. Core resolves and validates the destination configuration and endpoint before it binds the same origin-scoped credentials and transport capability used by the Reporter family. A write-only destination omits the Retriever factory and produces `RETRIEVAL_UNSUPPORTED` before credential binding.

**Context:** Capability flags for individual filters would make the same CLI command behave unpredictably across destinations. Pretending that an unsupported filter succeeded is worse than rejecting the destination's retrieval capability during configuration or Doctor checks.

**Consequences:** First-party retrievers pass the same contract suite. Destination-specific query features are not added to the portable command until their semantics can be expressed for every retrieval-capable destination; provider-native tooling remains available outside Agentscope.

### ADR-003: Keep destination selection outside the Retriever

**Decision:** `--destination <connection-name>` is required for every search and get. Core resolves the immutable connection identifier and exact configuration snapshot before calling the Retriever; the Retriever receives a resolved connection context and cannot select, fall back to, or fan out to another connection. Search requests and get locators are process-branded after exact connection and destination-type validation, and a result is accepted only through the matching operation boundary.

**Context:** A user may configure multiple Langfuse projects and a Local SQLite database. A type name such as `langfuse` is not enough to identify which repository is queried.

**Consequences:** Search results carry the connection name, immutable connection identifier, destination type, canonical trace ID, destination-native trace ID when one exists, and a bounded opaque destination revision when the backend exposes multiple immutable reported representations for one canonical trace. A destination revision is created only by that Retriever from provider evidence, is always subordinate to the canonical TraceId and exact connection/configuration authority, and cannot select another connection or trace. A trace reference from one connection cannot be used against another.

### ADR-004: Use typed terminal outcomes

**Decision:** Retriever operations return success DTOs or stable typed failures: invalid query, unknown connection, unsupported retrieval, unauthorized, forbidden, rate limited, unavailable, deadline exceeded, malformed response, incompatible trace, and not found. Core reconstructs every returned value through the family runtime, races the operation against a same-process monotonic deadline and `AbortSignal`, and rejects malformed, oversized, late, or unbranded results. First-party Retriever implementations must honor the provider-request count supplied in the operation context; the shared contract suite verifies that limit through their bound transport ledger.

**Context:** Network and repository failures need automation-safe meaning without leaking provider payloads, secrets, or stack traces.

**Consequences:** CLI exit codes and structured diagnostics map from the stable taxonomy. Retry hints may be displayed when safely derived from headers, but Core does not retry or change destinations implicitly. Provider-native bodies are retained only in bounded in-memory parsing state and never appear in diagnostics.

### ADR-005: Treat all retrieved content as untrusted

**Decision:** A Retriever validates provider DTOs but returns an untrusted normalized candidate. The family boundary accepts either a strictly parsed supported persisted envelope or a strictly parsed canonical graph, verifies its canonical trace ID against the selected `TraceLocator`, and never grants the Protocol redacted-envelope brand. Core then reapplies the current non-weakening redaction policy, applies the retrieval summary allowlist, and constructs presentation DTOs. Search fields that the current policy would omit are absent from the portable summary. A full retrieved graph is emitted only when every structural name and semantic value is already an unchanged fixed point under the current policy; if any value would be omitted, replaced, normalized, or suppressed, Core returns the stable incompatible-trace result instead of attempting an evidence-breaking partial rewrite.

**Context:** A destination can contain data written by older Agentscope releases, another producer, or a compromised service. Data that was acceptable when reported may no longer satisfy current disclosure policy.

**Consequences:** Retriever packages cannot construct terminal strings or structured CLI output. Human output escapes terminal control characters. Machine output contains only versioned portable DTOs, never a raw destination response. Malformed and incompatible traces fail closed for output while leaving the remote repository unchanged. This conservative fixed-point rule preserves canonical compound and provenance invariants while still permitting a later dedicated graph-redaction reconstruction path.

### ADR-006: Verify retrievers with one contract suite

**Decision:** Destination family Core exports a Retriever contract suite covering query semantics, identity binding, pagination, cancellation, bounds, typed failures, untrusted data, and redaction handoff. Each concrete retriever supplies a test adapter and provider fixtures; hermetic integration tests run the same cases against its mock repository.

**Context:** A shared TypeScript interface alone cannot prove that two backends interpret filters and cursors the same way.

**Consequences:** Local SQLite and Langfuse must pass identical portable behavior tests plus destination-specific mapping tests. Adding a first-party retriever requires no changes to CLI parsing or generic retrieval scenarios.
