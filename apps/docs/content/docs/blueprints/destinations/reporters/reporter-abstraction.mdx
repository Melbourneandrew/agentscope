## Capability Summary

Reporters send redacted canonical batches to an external destination for the [Reporting and Destinations](/docs/requirements/reporting-and-destinations) capability.

## Architecture Decision Records

### ADR-001: Require reporting, make retrieval optional

**Decision:** Every Trace Destination has a reporter; only destinations that support queries expose a retriever.

**Context:** Delivery is core product behavior while many valid destinations are write-only.

**Consequences:** `packages/destinations/core` owns both ports and their shared lifecycle vocabulary. Reporter and Retriever are sibling capabilities of one named destination connection; neither inherits from the other, and a retriever never receives hook-time delivery calls.

### ADR-002: Centralize delivery policy

**Decision:** Core owns redaction, batching, routing, hook deadline enforcement, and sanitized delivery diagnostics. A reporter receives a nonempty bounded batch of the original branded `RedactedCanonicalTrace` references, one Core-authored `AbortSignal`, and one branded same-process monotonic absolute deadline. It maps that batch to its origin-bound destination transport and returns one exact content-free terminal receipt: accepted, rejected, unavailable, deadline-exceeded, or outcome-unknown. The envelope's existing delivery identity is the sole per-item authority; reporters cannot replace it.

**Context:** Failure semantics cannot vary by destination or block a harness. A provider body, thrown error, acknowledgement loss, or unattributable partial-batch response must not leak content or be misreported as a definite non-commit.

**Consequences:** Empty, oversized, sparse, accessor-backed, cloned, forged, duplicate-identity, persisted-reader, or external-reader batches fail before reporter invocation. Application Core accepts a receipt only if it settles before the deadline. Expiry before invocation is deadline-exceeded; once invocation begins, a throw, rejection, malformed receipt, abort, deadline race, lost acknowledgement, or any partial-batch result is outcome-unknown unless a trusted transport proves that the complete batch was accepted or that no remote commit was possible. Reporter version 1 deliberately has no per-item receipt map: even a provider response that attributes some accepted and rejected items is one `outcome-unknown` connection attempt, never accepted or rejected. No native checkpoint advances for that attempt. Late settlement is observed and discarded.

### ADR-003: Make destination testing a package capability

**Decision:** Each first-party Trace Destination package supplies a `DestinationTestAdapter` through the explicit test-only destination-family subpath. The family provides a closed behavior vocabulary and normalized delivery ledger; provider packages configure their mock endpoint and translate native requests into those generic reporting/retrieval assertions. The reusable exhaustive contract suite lands separately from the primitive adapter seam so provider matrices do not fork.

**Context:** Langfuse/OTLP is the first destination, not an assumption embedded in harness tests.

**Consequences:** An additional Phoenix/Arize, warehouse, or internal-service Trace Destination extends the suite through a reviewed Agentscope pull request without changing scenario orchestration or harness packages. A console destination is not part of the product because writing trace content to a hook's terminal would create an unsafe and unreliable disclosure path.

### ADR-004: Ship integrations only as first-party packages

**Decision:** Agentscope supports harness and Trace Destination integrations only as private first-party workspace packages bundled into the public CLI artifact. Adding one is a reviewed pull request and CLI release.

**Context:** A Node package loaded in the CLI process has ambient filesystem, environment, and network authority. Agentscope has no current product need for third-party executable integration loading.

**Consequences:** Core owns credentials, redaction, delivery, and retrieval boundaries. Package contracts remain internal and well-tested; no plugin marketplace, third-party loading mode, or public executable-extension ABI is in scope.

### ADR-005: Reserve a constrained enrichment seam instead of arbitrary code

**Decision:** Agentscope supports declarative, schema-validated filtering, redaction, and additional metadata rules owned by Core. It does not execute user-supplied enrichers or filters.

**Context:** Filtering and metadata attachment are the most plausible user extension needs, but arbitrary callbacks could see sensitive data, block hooks, or make output non-reproducible.

**Consequences:** Declarative rules have deterministic tests and Doctor diagnostics. Executable user extensions are outside the current product scope.

### ADR-006: Fan out once per selected connection within the hook lifetime

**Decision:** Core routing policy version 1 is one unconditional explicit set of opaque connection identities plus one configured hook duration. The duration is an integer from 50 through 60,000 milliseconds; migration of the prior routing shape writes the reviewed 2,000 millisecond default. CLI configuration may resolve a globally unique presentation name to its immutable identity, but the persisted policy and runtime result use only the identity. The empty set selects nothing; Core never activates every configured connection or a default connection implicitly. Version 1 does not inspect span attributes, trace content, harness identity, destination type, ordering, or prior outcomes. Any future conditional selector requires a new routing-policy version and disclosure review because routing observes only branded redacted metadata.

At hook entry Core creates one same-process monotonic absolute deadline from the launcher-owned bootstrap duration. After the immutable configuration is read, the configured hook duration is measured from that original entry instant and may only shorten the deadline. Core snapshots the selected identities in canonical identity order and immediately starts one independent concurrent connection task for every selected identity. Each task begins with exact connection, endpoint, credential, transport, and Reporter preparation and may then perform at most one Reporter attempt. Setup uses a task-local cancellation controller composed with the global hook signal and may consume at most the lesser of a fixed 1,000 millisecond setup cap and the global remaining budget. Local setup expiry closes only that task and records `unavailable` while global time remains; it never aborts a sibling. Global expiry before Reporter invocation records `deadline-exceeded`; after invocation it records `outcome-unknown`. Setup callbacks must own and close or unref their handles, observe late settlement without retaining the batch or changing the frozen result, and perform no detached work. A configuration, endpoint, credential, or factory failure before invocation is `unavailable` when Core can prove no remote commit began. Once Reporter invocation begins, Core accepts its exact receipt or conservatively uses `outcome-unknown` according to ADR-002. Each selected identity appears exactly once in the frozen result with accepted, rejected, unavailable, deadline-exceeded, or outcome-unknown. The receipt is connection-attempt scoped; every uniform full-batch result maps directly, while every partial-batch result maps to `outcome-unknown` without per-item checkpoint advancement. There is no trace spool, retry queue, `agentscope flush`, resident daemon, detached delivery work, or Core-owned serialized batch.

**Context:** The product must fail open, and deferred local storage changes the privacy, disk, and operational model substantially. A failed trace is less harmful than adding a durable copy of agent activity to every developer machine without an explicit product need.

**Consequences:** Configuration validation rejects unknown or duplicate selected identities before hook time. An empty selection produces one fixed content-free `routing-unselected` lifecycle result immediately after snapshot resolution and invokes no adapter capture, redaction, connection preparation, credential resolution, transport, or Reporter. One connection's local setup failure or timeout never aborts, cancels, or compensates another accepted delivery; the shared deadline alone requests cooperative abort for every still-unfinished task. Core waits only until that deadline, observes late settlements without changing its frozen result, and does not claim that an uncooperative transport stopped. Routing order creates no priority. The original branded envelope references and their existing delivery identities pass unchanged into every selected attempt; Core neither clones nor serializes them for fanout. Reporters map Core's stable delivery identity to native idempotency where available and otherwise declare possible duplicates. Tests prove empty/unknown/duplicate selection, all selected setup tasks starting concurrently, canonical result order, mixed outcomes, local setup timeout not cancelling siblings, setup failure, lost acknowledgement, attributable and unattributable partial acceptance, pre- and post-invocation global deadline races, late settlement, one failure not cancelling siblings, and absence of Core-owned trace persistence.

### ADR-007: Resolve a non-weakening redaction policy once

**Decision:** Core resolves a built-in, versioned mandatory baseline plus one validated declarative user policy from the same immutable hook-start snapshot used for routing. The exact rule grammar, disclosure meet, route defaults, immutable safety ceilings, deadline composition, and effective policy identity are owned by Canonical Trace Format ADR-002. Secret detection and local-path protection cannot be disabled; user rules may only omit additional descriptor-governed values. An invalid, unknown, unavailable, or over-budget policy suppresses persistence/export, returns the fixed pre-brand sanitized lifecycle result and best-effort persists it as defined by Canonical Trace Format ADR-002, and still fails open to the harness.

**Context:** Harness execution may fail open, but disclosure must fail closed. Structural validation does not prove a trace is safe to persist or export.

**Consequences:** Every exported or durable envelope records the applied policy identifier without matched content. Doctor reports effective policy provenance safely; expanding collected/exported categories requires an explicit policy migration and acceptance tests.
