## Capability Summary

Langfuse is a first-party Trace Destination using OTLP delivery.

## Architecture Decision Records

### ADR-001: Use OTLP delivery

**Decision:** The Langfuse reporter sends the OpenInference-compatible canonical OTLP graph to Langfuse's OTLP/HTTP trace endpoint and adds only documented `langfuse.*` overlays needed for Langfuse filtering and presentation. Configuration persists one reviewed compatibility profile and manifest identity for the connection. That profile supplies the exact endpoint suffix, supported JSON or protobuf encoding, authentication shape, and required ingestion-version header; the current Langfuse v4 profile always sends the documented ingestion-version header that makes direct OTLP data visible to Observations API v2 without the legacy ingestion delay.

**Context:** Langfuse accepts OTLP, while its first-class trace metadata and filtering can require Langfuse-specific attributes beyond generic OpenTelemetry/OpenInference fields.

**Consequences:** Contract tests prove which OpenInference fields Langfuse renders directly and which Agentscope fields require an explicit `langfuse.*` mapping; unmapped `agentscope.*` attributes remain namespaced metadata rather than silently becoming product fields. Reporter and Retriever consume the same persisted profile and manifest identity. A server-profile change requires explicit configuration migration or reconfiguration and therefore changes configuration identity; Doctor may observe compatibility but never changes it. Profile selection never changes the canonical graph, delivery identity, or Reporter receipt semantics.

**Required flow:** The reporter accepts only the redacted canonical OTLP/OpenInference graph. It preserves OpenInference and `agentscope.*` fields, adds the narrow tested `langfuse.*` overlay, and serializes an OTLP payload. It does not read a harness transcript or construct a separate Langfuse-native trace model.

### ADR-002: Avoid overlapping vendor hooks

**Decision:** Installation detects Langfuse's official harness integration and requires explicit migration before an Agentscope hook takes ownership.

### ADR-003: Project portable retrieval keys deliberately

**Decision:** The Reporter preserves the canonical W3C trace ID and writes one closed retrieval projection onto the logical root observation. It includes the first-class Langfuse session field; an exact-filterable reserved root marker; namespaced session-fallback, harness, branch, repository-safe identity, and canonical span-count metadata; one reserved tag for each canonical model identity; and safe user tags. Because the supported Observations API v1 response omits Langfuse tags, the root metadata also carries a bounded indexed summary mirror of canonical model identities and safe user tags. The session fallback and summary mirror are read adaptations for the pinned v1 profile, not alternate canonical fields. The destination compatibility manifest owns the exact reserved keys, counts, index encoding, tag prefix, value grammar, length limits, and profile-specific wire attributes. All projection values are derived from the governed canonical graph and cannot be supplied or overwritten by user metadata.

**Context:** Reporting and retrieval are two capabilities of the same configured destination. A trace that is visible in Langfuse but cannot be found through the portable query contract is not a complete Agentscope delivery.

**Consequences:** Reporter contract tests assert both the OTLP/OpenInference payload and the retrieval projection. Root search never downloads child observations or issues one native read per result merely to calculate a summary count or discover a model or tag value. Values that cannot be represented exactly under the pinned Langfuse limits fail before transport rather than being truncated, dropped, or made unsearchable. Reserved tags are removed from portable user-tag output, and v1 reconstructs portable models and tags only from the exact reserved mirror and count fields. Changes to a projection key require coordinated Reporter/Retriever compatibility evidence; they never change the authoritative OpenInference plus `agentscope.*` representation.
