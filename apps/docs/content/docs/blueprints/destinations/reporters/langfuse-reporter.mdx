## Capability Summary

Langfuse is a first-party Trace Destination using OTLP delivery.

## Architecture Decision Records

### ADR-001: Use OTLP delivery

**Decision:** The Langfuse reporter sends the OpenInference-compatible canonical OTLP graph to Langfuse's OTLP/HTTP trace endpoint and adds only documented `langfuse.*` overlays needed for Langfuse filtering and presentation plus the closed transport-only retrieval capsule defined by the paired Langfuse Retriever Blueprint. The capsule encodes only the same canonical graph through Protocol's graph-only OTLP JSON codec and never stores or derives authority from delivery-envelope fields. One fresh per-item Reporter-invocation capsule nonce, retained only inside that immutable request plan, identifies the corresponding append-only retrieval revision. Reporter code performs one transport call and no retry. Configuration persists one reviewed compatibility profile and manifest identity for the connection. That profile supplies the exact endpoint suffix, supported JSON or protobuf encoding, authentication shape, one current retrieval-capsule writer/reader identity, and required ingestion-version header; the current Langfuse v4 profile always sends the documented ingestion-version header that makes direct OTLP data visible to Observations API v2 without the legacy ingestion delay.

**Context:** Langfuse accepts OTLP, while its first-class trace metadata and filtering can require Langfuse-specific attributes beyond generic OpenTelemetry/OpenInference fields.

**Consequences:** Contract tests prove which OpenInference fields Langfuse renders directly and which Agentscope fields require an explicit `langfuse.*` mapping; unmapped `agentscope.*` attributes remain namespaced metadata rather than silently becoming product fields. The synthetic carrier spans are a bounded destination transport encoding, never canonical spans or a second graph authority. Their full resource, scope, timing, parent, kind, status, flags, dropped-count, attribute, event, link, ID, and visibility rules are manifest-bound and shared with the Retriever. Reporter and Retriever consume the same persisted profile and manifest identity. A server-profile or capsule change requires explicit configuration migration or reconfiguration and therefore changes configuration identity; Doctor may observe compatibility but never changes it. Profile selection never changes the canonical graph, delivery identity, or Reporter receipt semantics.

**Required flow:** The reporter accepts only the redacted canonical OTLP/OpenInference graph. It preserves OpenInference and `agentscope.*` fields, adds the narrow tested `langfuse.*` overlay, derives the bounded graph-only retrieval capsule, and serializes one OTLP request in which one logical trace's canonical spans and carriers are atomic for Reporter receipt classification. It does not read a harness transcript, serialize delivery-envelope fields, or construct a separate Langfuse-native trace model. A graph or expanded logical item that exceeds its capsule or final request bounds fails before transport. Provider partial success, commit-then-lost-ack, and every other non-uniform or unproved settlement remain the family-level `outcome-unknown`; later retrieval visibility never rewrites that receipt.

### ADR-002: Avoid overlapping vendor hooks

**Decision:** Installation detects Langfuse's official harness integration and requires explicit migration before an Agentscope hook takes ownership.

### ADR-003: Project portable retrieval keys deliberately

**Decision:** The Reporter preserves the canonical W3C TraceId and writes one closed retrieval projection onto each immutable capsule-header observation. It includes the first-class Langfuse session field; an exact current capsule-header marker; namespaced session-fallback, harness, branch, repository-safe identity, status, and canonical span-count metadata; and collision-checked exact metadata keys plus a bounded indexed mirror for every canonical model identity and safe user tag. Langfuse tags remain a native presentation projection only. The session fallback and summary mirror are read adaptations for the pinned v1 profile, not alternate canonical fields. The destination compatibility manifest owns the exact reserved keys, key derivation, counts, index encoding, tag prefix, value grammar, length limits, and profile-specific wire attributes. All projection values are derived from the governed canonical graph and cannot be supplied or overwritten by user metadata.

**Context:** Reporting and retrieval are two capabilities of the same configured destination. A trace that is visible in Langfuse but cannot be found through the portable query contract is not a complete Agentscope delivery.

**Consequences:** Reporter contract tests assert both the OTLP/OpenInference payload and the retrieval projection. Header search never downloads carrier observations or issues one native read per result merely to calculate a summary count or discover a model or tag value. Values that cannot be represented exactly under the pinned Langfuse limits fail before transport rather than being truncated, dropped, or made unsearchable. Reserved tags are removed from portable user-tag output, and v1 reconstructs portable models and tags only from the exact reserved mirror and count fields. Changes to a projection key require coordinated Reporter/Retriever compatibility evidence; they never change the authoritative OpenInference plus `agentscope.*` representation.

### ADR-004: Treat the graph capsule as bounded destination transport

**Decision:** Every logical item in every Reporter invocation mints one fresh cryptographically random 128-bit capsule nonce and produces one immutable current-version capsule header plus its immutable carrier set. The header owns the search summary and exact capsule metadata; the nonce is the bounded non-content destination revision, and manifest-domain SpanIds derive from it without exposing graph content. The full graph digest is capsule-integrity data only. A later Reporter invocation always appends a new header and carrier set, even for the same ASID delivery identity or identical graph. Byte-identical duplicate provider rows within one nonce collapse and conflicting duplicates fail retrieval. Neither Reporter nor Retriever interprets the nonce, ASID delivery identity, or provider arrival time as a boundary-ordering value.

**Context:** Appended capture boundaries intentionally retain canonical TraceId and existing SpanIds while changing opaque boundary and delivery identities. Delivery is at least once, and an acknowledged response can be lost after remote commit. Treating every repeated carrier as corruption would make legitimate replay unretrievable; treating an opaque delivery identity as a sequence would invent authority the canonical identity profile does not provide.

**Consequences:** Search and direct canonical-TraceId get exactly validate their complete bounded current-marker header response, fail malformed/conflicting candidates closed, and then select the first header under the manifest-pinned provider order; a full structured locator pins one exact header revision. Carrier completeness never affects selection, and selected-carrier failure never falls through to another revision. Repeated TraceIds may recur across best-effort remote pages, but one page returns at most one summary for a canonical TraceId. Contract and protected-provider tests cover later-invocation replay with identical and changed graph bytes, changed policy/configuration replay, partial persistence, conflicting provider duplicates, malformed-higher/valid-lower ordering, multiple appended boundaries, provider-order selection, page splits, selected-carrier failure, no-fallback behavior, and exact revision lookup. A complete remotely observed capsule is retrieval evidence only and never changes the terminal Reporter receipt already returned to Core. Capsule version changes use a new exact provider-side marker and configuration identity; v1 retains no destination-owned historical reader window.
