## Capability Summary

MockServer and loopback telemetry services make real harness execution deterministic while exposing every relevant protocol request to test assertions. Model-provider credentials never enter these tests.

## Architecture Decision Records

### ADR-001: Use one protected upstream model-protocol service

**Decision:** Scenarios use one controller-owned MockServer built from pinned upstream source and a narrowly reviewed control-authentication patch. It owns the deterministic model/tool responses and namespaced request ledger for the APIs required by the selected scenario. The controller alone configures expectations and retrieves evidence for the independent scenario oracle. No bespoke gate server, model gateway, proxy chain, second parser, or fallback implementation is admitted.

Before candidate access, the controller establishes one per-run control-plane trust anchor inaccessible to the candidate. REST controls, listener/configuration operations, ledger access, dashboard routes, and every otherwise-ungated WebSocket upgrade, including callback upgrades, enforce that same control decision. This applies whenever the candidate can route to the listener, including separate containers on one private Docker network. The patch changes no model-route behavior and creates no second credential or control registry. Container scenarios authenticate the immutable image built from the exact source and patch; native scenarios authenticate the corresponding exact executable under the trusted controller principal without inventing OCI identity.

Every harness uses only its selected internal model route; public egress is independently denied and probed. No model-provider credential enters preparation, scenario configuration, environment, homes, fixtures, or evidence. A harness Blueprint may permit a fixed non-authoritative sentinel only when required for that mode's local parsing; it grants no provider authority and cannot resemble a usable credential. Model-request processing is independent of hook timing. The service does not hold sockets or require gate generations, pre-parser receipts, or a custom per-byte accounting protocol.

**Context:** Independent model requests and destination observations prove different effects; a transcript parser alone cannot prove endpoint overrides, tool flow, or hook invocation. A candidate that can configure responses or mutate assertion records can invalidate that independence even on an internal network. Investigation of pinned upstream MockServer versions found that REST authentication did not cover the callback WebSocket path. The narrow patch closes this reachable control boundary while retaining upstream protocol behavior; a token or image version change alone is not proof.

**Consequences:** Container rows expose no host port. Native rows expose only the scenario-private loopback protocol endpoint, never an external listener. In either variant, candidate processes cannot inspect, signal, or mutate the service process, control authority, ledger storage, or retained evidence. Existing isolation, absolute deadlines, bounded output, service/process settlement, and exact resource reconciliation remain governed by their owning Blueprints. Before accepting evidence, the controller ends candidate request authority, settles admitted service work, obtains one complete final ledger with no later mutation possible, and joins the service within those existing deadlines; incomplete observation or uncertain settlement fails the run. This uses the existing service lifecycle and independent ledger, not a new parser receipt mechanism.

Each selected-service update reauthenticates the upstream source, patch, and artifact and audits all candidate-reachable HTTP and upgrade routes. Hermetic runtime evidence must prove candidate denials, controller-positive required configuration and ledger operations, unchanged scenario model responses, and inability to replace the trust anchor. Unexpected egress, provider authentication, alternate routing, control access, or uncertain cleanup fails. An unpatched artifact or source inspection alone cannot satisfy admission. If the exact selected service cannot prove this boundary, work stops at that bounded blocker; a different network boundary, gateway, or execution mechanism requires a separate earlier architecture decision.

### ADR-002: Observe destination delivery independently

**Decision:** A destination test adapter owns a loopback OTLP receiver or other destination-native mock and normalizes its request ledger into common assertions. Langfuse reporting is verified exclusively as OTLP delivered to the loopback receiver; tests never contact Langfuse or hold an authority-bearing Langfuse credential. A fixed synthetic credential canary may exercise the local reference lifecycle but cannot authenticate to any external service.

**Context:** Model traffic and trace export are distinct evidence. An additional Trace Destination must not require a harness test rewrite.

**Consequences:** Generic assertions cover canonical hierarchy, branch/model/tool context, redaction, and delivery shape; a checksum-bound scenario adapter adds harness and destination-specific behavior without modifying generic orchestration. Unit contracts consume normalized delivery ledgers through the destination-family testing subpath; integration adapters remain responsible only for translating native mock requests into that ledger.

### ADR-003: Model destination retrieval as a separate protocol

**Decision:** A retrieval-capable destination test adapter exposes deterministic search, pagination, get, authorization, rate-limit, malformed-response, and mutation scenarios independently from its ingestion ledger. It can seed provider-native rows directly and can make a delivered trace visible according to the destination's declared consistency behavior.

**Context:** A mock OTLP receiver proves delivery but cannot prove that the Retriever maps provider filters, cursors, observation trees, or failures into the portable contract.

**Consequences:** Generic retrieval scenarios run against every Retriever through the same named contract-case factory and normalized operation ledger, including the supplied provider-request maximum. Langfuse-specific cases assert Observations API field groups, exact metadata filters, logical-root grouping, cursor flow, and graph reconstruction. Model mocks, ingestion mocks, and retrieval mocks use separate endpoints and ledgers even when one test service process hosts them.
