## Capability Summary

MockServer and loopback telemetry services make real harness execution deterministic while exposing every relevant protocol request to test assertions. Model-provider credentials never enter these tests.

## Architecture Decision Records

### ADR-001: Treat MockServer as the model-protocol authority

**Decision:** Testkit configures protocol-aware MockServer routes for the OpenAI/Responses, Anthropic, Gemini, and other APIs required by a scenario. MockServer is one controller-owned model-protocol authority selected from a closed implementation policy: the authenticated pinned upstream service, or an authenticated repository-owned exact build when an earlier harness Blueprint requires a lifecycle-gated route that upstream cannot express. One scenario selects exactly one implementation; implementations are never chained. The selected service owns its endpoint, socket admission, protocol parser, deterministic model and tool responses, namespaced sanitized request ledger, and terminal connection/parser receipts in one protected process boundary. A repository-owned implementation has a closed production source-to-artifact graph and verifier and may expose a challenge-bound control channel only to the controller. Every harness is configured to use only its selected internal route; public egress is denied and probed, and no model-provider credential is present in preparation, scenario configuration, environment, homes, fixtures, or evidence.

**Context:** A transcript parser cannot prove endpoint overrides, native tool flow, or hook invocation. A real outbound request would make a test costly, nondeterministic, and unsafe.

**Consequences:** A container row reaches controller-owned mocks only on its internal Docker network, with no host port publication. A native row runs mocks and ledgers under the trusted controller principal on the disposable native runner, binds only the protocol endpoint to a scenario-private loopback address, and exposes no listener on an external interface; candidate code can send bounded protocol requests but cannot inspect, signal, or mutate the service process, control channel, parser state, assertion ledger, or storage. A gate-capable implementation must bind every `pending`, `armed`, `parsing-first`, `admitted`, `draining`, `denied`, or `expired` transition and terminal parser/connection receipt to the exact run and ledger generation. `parsing-first` is provisional and cannot authorize relay work; if its admission cutoff wins before one complete valid first request, the service cancels and joins that parser work, records denial, and can never advance to `admitted`. An unsettled parser, connection, receipt, or ledger cannot become scenario evidence. Native network containment denies public egress independently. An unexpected egress, provider-authentication attempt, externally reachable listener, oracle-control access, alternate model route, or fallback implementation fails the scenario. Fixed sentinel values may exercise harness-owned local parsing only where the selected mode requires them, but they grant no provider authority and cannot resemble a usable credential.

### ADR-002: Observe destination delivery independently

**Decision:** A destination test adapter owns a loopback OTLP receiver or other destination-native mock and normalizes its request ledger into common assertions. Langfuse reporting is verified exclusively as OTLP delivered to the loopback receiver; tests never contact Langfuse or hold an authority-bearing Langfuse credential. A fixed synthetic credential canary may exercise the local reference lifecycle but cannot authenticate to any external service.

**Context:** Model traffic and trace export are distinct evidence. An additional Trace Destination must not require a harness test rewrite.

**Consequences:** Generic assertions cover canonical hierarchy, branch/model/tool context, redaction, and delivery shape; a checksum-bound scenario adapter adds harness and destination-specific behavior without modifying generic orchestration. Unit contracts consume normalized delivery ledgers through the destination-family testing subpath; integration adapters remain responsible only for translating native mock requests into that ledger.

### ADR-003: Model destination retrieval as a separate protocol

**Decision:** A retrieval-capable destination test adapter exposes deterministic search, pagination, get, authorization, rate-limit, malformed-response, and mutation scenarios independently from its ingestion ledger. It can seed provider-native rows directly and can make a delivered trace visible according to the destination's declared consistency behavior.

**Context:** A mock OTLP receiver proves delivery but cannot prove that the Retriever maps provider filters, cursors, observation trees, or failures into the portable contract.

**Consequences:** Generic retrieval scenarios run against every Retriever through the same named contract-case factory and normalized operation ledger, including the supplied provider-request maximum. Langfuse-specific cases assert Observations API field groups, exact metadata filters, logical-root grouping, cursor flow, and graph reconstruction. Model mocks, ingestion mocks, and retrieval mocks use separate endpoints and ledgers even when one test service process hosts them.
