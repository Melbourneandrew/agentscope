## Capability Summary

MockServer and mock telemetry services make real harness execution deterministic while exposing every relevant protocol request to test assertions.

## Architecture Decision Records

### ADR-001: Treat MockServer as the model-protocol authority

**Decision:** Testkit configures protocol-aware MockServer routes for the OpenAI/Responses, Anthropic, Gemini, and other APIs required by a scenario. It returns deterministic model and tool responses and records a namespaced, sanitized request ledger.

**Context:** A transcript parser cannot prove endpoint overrides, native tool flow, or hook invocation. A real outbound request would make a test costly, nondeterministic, and unsafe.

**Consequences:** Mock services are reachable only on the scenario's internal Docker network and are never published on host ports. An unexpected egress attempt fails the scenario rather than falling back to a real provider.

### ADR-002: Observe destination delivery independently

**Decision:** A destination test adapter owns a mock OTLP/Langfuse or destination-native endpoint and normalizes its request ledger into common assertions.

**Context:** Model traffic and trace export are distinct evidence. An additional Trace Destination must not require a harness test rewrite.

**Consequences:** Generic assertions cover canonical hierarchy, branch/model/tool context, redaction, and delivery shape; a harness adapter adds native expectations and a destination adapter adds protocol-specific expectations.
