## Capability Summary

The same manifest drives a small selected local scenario and the complete hermetic CI matrix without leaving dependencies, containers, or mock routing on a developer workstation.

## Architecture Decision Records

### ADR-001: Make local execution targeted and safe by default

**Decision:** Local commands select an explicit scenario, harness, tag, deterministic shard, or deliberate full run and execute it in Docker. They print exact named containers, networks, images, and fixed-root artifact paths before cleanup; `pnpm test:integration:clean` removes only validated owned targets.

**Context:** Developers may use AgentScope and coding harnesses outside this repository. A test command must not alter their real configuration or make their active agents talk to MockServer.

**Consequences:** The suite never mounts the user's home or injects model endpoint variables into the host shell. Repeated local runs reuse only named, bounded prepared inputs; scenario and sidecar resources have explicit memory, process, request, concurrency, and time ceilings. Cleanup is inspectable and never follows symlinked roots or recursively accepts an arbitrary path.

### ADR-002: Gate pull requests with the defined hermetic matrix

**Decision:** Pull requests run the manifest's required hermetic compatibility set in CI shards. Scheduled/manual CI may run broader supported-version coverage; protected live tests remain a separate non-PR lane.

**Context:** The fast required matrix detects cross-harness regressions without making every PR wait for every historical version or paid external service.

**Consequences:** A prerequisite job prepares the candidate once; shard and replay jobs consume that exact checksum-bound artifact. The CI summary reports each harness/version/destination result, image digest, and scenario identity. A matrix change that lowers coverage requires an explicit review explanation.
