## Capability Summary

The same manifest drives a small selected local scenario and the complete hermetic CI matrix without leaving dependencies, containers, or mock routing on a developer workstation.

## Architecture Decision Records

### ADR-001: Make local execution targeted and safe by default

**Decision:** Local commands select an explicit scenario, harness, tag, deterministic shard, or deliberate full run and execute it in Docker. They print exact named containers, networks, images, and fixed-root artifact paths before cleanup; `pnpm test:integration:clean` removes only validated owned targets.

**Context:** Developers may use AgentScope and coding harnesses outside this repository. A test command must not alter their real configuration or make their active agents talk to MockServer.

**Consequences:** The suite never mounts the user's home or injects model endpoint variables into the host shell. Repeated local runs reuse only named, bounded prepared inputs; scenario and sidecar resources have explicit memory, process, request, concurrency, and time ceilings. Resource names and labels bind the physical Docker daemon identity, repository identity, workspace identity, and fresh run nonce. Run registration and repository-owned artifact mutation use one host-local OS socket lease derived from the physical Docker daemon plus repository identity, so separate worktrees of this repository cannot hold conflicting cleanup authority. Each run then holds a fresh-nonce claim in that repository-scoped registry bound to the same daemon, repository, and workspace identities plus either a non-reusable operating-system process handle or the authenticated tuple of host boot identity, process identifier, and process start identity; PID-only liveness is never authority. Under the socket lease, a later controller double-checks the exact claim and may advance it to a new exclusive fenced recovery generation only after the bound operating-system identity proves that exact owner no longer exists. Live or indeterminate identity blocks reclamation; every admitted crash prefix therefore resumes the exact live generation, advances a proved-dead generation for exact reconciliation, or fails closed. A proved stale claim authorizes reconciliation only of the exact run identities recorded by that generation, and generation revalidation precedes each mutation. Cleanup removes only exact repository/run-specific containers, networks, tags, references, archives, contexts, and evidence; it never deletes a shared content digest from the Docker or BuildKit store, whose garbage collection remains daemon-owned. The kernel releases exclusion when its owner exits, so interruption cannot leave a stale pathname lock. Cleanup is inspectable, accepts only exact bound labels and identities, and never follows symlinked roots or recursively accepts an arbitrary path.

### ADR-002: Gate pull requests with the defined hermetic matrix

**Decision:** Pull requests run unconditional, separately sharded scenarios for all and only the finite exact support rows claimed by the applicable release support manifest. Each shard binds the exact support-row identity, clean-installs the same packed CLI candidate, invokes the catalog-pinned actual binary, uses only internal model mocks and the loopback OTLP ledger, denies public egress, and proves cleanup. No path, relevance classifier, or deduplication by version/mode may omit or combine claimed rows. Scheduled/manual CI may run broader advisory coverage, but it never changes the required pinned set or contacts a model provider, Langfuse, or another public destination service.

**Context:** The fast required matrix detects cross-harness regressions without making every PR wait for every historical version. Hermetic execution keeps evidence deterministic and avoids exposing provider credentials or test data to an external service.

**Consequences:** A prerequisite job prepares the candidate once; shard and replay jobs consume that exact checksum-bound artifact, exact support-row identity, and catalog-authenticated harness identity. Manual dispatch can select one exact manifest scenario. The CI summary reports the exact support-row identity, including its harness claim, full-platform tuple, and destination combination, plus the backend-appropriate prepared artifact identity and scenario identity. A matrix change that lowers a release claim requires changing the release support manifest rather than silently weakening CI.

### ADR-003: Fence uncertain daemon mutation across controller exit

**Decision:** Before a trusted executor starts an operation that may mutate the Docker daemon after its client stops responding, it uses the ADR-001 socket lease to durably create one bounded, canonical recovery claim. The claim binds a fresh generation to the physical daemon, repository, workspace, run, owner process-start identity, exact executable and operation identity, and the complete exact run-owned resource set. That set includes the applicable builder, tag or reference, container, network, volume, context, archive, and evidence identities; it never includes shared Docker or BuildKit content digests. Claim creation and every generation change use private no-follow state, atomic replacement, and directory durability before mutation authority is released.

The active controller clears the claim only after independently proving the operation process set terminal and reconciling every bound resource to its required terminal state. If process-set absence, daemon settlement, or resource state is uncertain, the claim survives client close and controller exit, blocks later mutation on that repository and daemon, and publishes no prepared-input, cleanup, cache-adoption, or scenario-pass evidence. A later controller may advance the claim to one exclusive recovery generation only after independently proving the exact recorded owner and operation process set dead. It revalidates that generation and the physical daemon before each exact-identity reconciliation step and clears the claim only after the complete bound inventory is terminal. Live, indeterminate, missing, malformed, oversized, substituted, or symlinked authority remains fenced for explicit reconciliation.

**Context:** A client timeout or closed local socket does not prove that daemon-side creation or publication stopped. An in-memory marker disappears with the controller and can permit a later run to race a surviving mutator or delayed resource publication.

**Consequences:** This is one testing-infrastructure recovery authority shared by uncertain preparation builds and native evidence-volume creation; those capabilities do not define parallel ledgers or clearing rules. Prefix sweeps, elapsed polling, tag or name absence alone, controller-exit cleanup, and deletion of shared daemon content cannot establish terminal state. The claim stores identities and closed state only, never credentials, commands containing secrets, artifact contents, or scenario evidence.
