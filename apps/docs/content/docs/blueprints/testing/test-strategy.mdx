## Capability Summary

Agentscope needs independent proof of deterministic semantics and real CLI/hook behavior.

## Architecture Decision Records

### ADR-001: Separate unit and integration lanes

**Decision:** Unit tests are colocated with the app/package that owns pure parsing, schemas, mapping, redaction, bounded delivery outcomes, and reporter contracts; root integration tests verify live harness/setup behavior.

**Context:** Transcript fixtures cannot prove executable flags, hook invocation, or configuration mutation.

**Consequences:** `apps/**` and `packages/**` retain their own fast unit and contract suites. `tests/integration/` owns hermetic cross-package scenarios. Automated tests never receive an authority-bearing model-provider or Langfuse credential, never contact a model provider or Langfuse, and verify Langfuse reporting only as OTLP delivered to a loopback ledger. Fixed synthetic credential canaries may exercise local reference lifecycle but grant no external authority.

### ADR-002: Treat capability claims as test-backed

**Decision:** A harness/reporter/version is supported only when its required unit contracts and real-harness scenario pass.

### ADR-003: Make test cleanup owned and inspectable

**Decision:** The test system gives every owned resource an exact backend-appropriate AgentScope identity. A container row gives every Docker resource an exact prefixed name and label and keeps scenario homes and worktrees in container-local tmpfs. A native row keeps candidate-visible state beneath one exact candidate-principal disposable root on the native host and binds that root, principal, and runner identity into cleanup evidence; it never uses a user's home or project. Candidate code cannot access retained-evidence storage. In both variants, only the trusted controller sanitizes terminal evidence and copies it beneath the fixed repository artifact root. Cleanup reports sizes and accepts only the closed backend resource-name and artifact-child grammars. It does not use an AgentScope runtime cache to retain traces.

**Context:** Repeated package installs can consume material disk space; cleanup must never risk a user's project, home, or active AgentScope state.

**Consequences:** One admitted integration controller owns preparation, routes, scenarios, bounded evidence maintenance, and cleanup inside either a GitHub-hosted job allocated by GitHub Actions or a disposable Crabbox guest and lease allocated by the supported coordinator. Repository code binds the supplied platform and run identity, exact Docker executable and endpoint, closed inputs, and owned run resources into one non-forgeable in-process capability; internal stages are not public commands. Request-capable or cleanup uncertainty fails the run and requires outer-host retirement without same-host retry, even if cleanup reports success. Both environments reject symlinked or unexpected artifact paths and never touch a user's home, active harness configuration, project worktree, or production `~/.agentscope` directory.
