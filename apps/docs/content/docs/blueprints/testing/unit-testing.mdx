## Capability Summary

Unit tests protect the canonical model and first-party package contracts without network, Docker, or installed harness dependencies.

## Architecture Decision Records

### ADR-001: Test contracts at seams

**Decision:** Fixtures follow semantic ownership. Protocol owns canonical graph/schema fixtures. Core owns only integration-neutral redaction, routing, deadline, diagnostic, configuration, and retrieval-boundary fixtures. Harness family Core owns generic adapter-contract helpers; destination family Core owns generic reporter/retriever helpers; each concrete integration owns its native mapping or transport fixtures. Testkit consumes only explicit test exports.

**Context:** Stable seams make first-party package contributions testable before real-harness scenarios are available, but centralizing integration fixtures in Core would violate production dependency boundaries.

**Consequences:** Mapping fixtures evolve with their adapter, destination ledgers evolve with their destination, and boundary linting applies to test exports as well as production code. Tests never import another package's private `src` path.

Harness family Core exposes one explicit test-only contract subpath. Its frozen named cases own the discovery/compatibility oracle, sanitized native-fixture and provenance closure, fixed launcher arguments, owned install/uninstall/explicit-overlap migration, concurrent-edit rejection, fail-open deadline behavior, and the generic scenario-adapter record consumed by the integration capability manifest. A minimal reference adapter must pass every case, while seeded secret, private-path, shell-syntax, mapping, overlap, deadline, and compatibility violations must fail stable assertion codes. Concrete harness packages provide only their descriptor, sanitized versioned fixture, mapping callback, installation planner, hook runner, and scenario data; adding a harness does not change the generic runner.

### ADR-002: Keep native fixtures sanitized and versioned

**Decision:** Native traces are checked-in, sanitized fixtures tagged by harness/version family.

**Context:** They provide fast regression coverage while not substituting for integration tests.

### ADR-003: Reuse workspace dependencies

**Decision:** Unit tests use the workspace dependency installation and create no per-test `node_modules` trees.

**Context:** Per-scenario package installation is slow and creates avoidable disk pressure.

### ADR-004: Run destination contracts against every implementation

**Decision:** Destination family Core exports internal contract-test factories for Reporter and Retriever independently. The Retriever suite verifies the canonical filter truth table, destination-qualified identities, cursor/query binding, ordering, bounds, cancellation, stable failures, malicious provider DTOs, and safe Core handoff. Each destination adds mapping fixtures without copying generic assertions.

**Context:** Structural TypeScript compatibility does not establish behavioral compatibility across an HTTP API and a local SQL store.

**Consequences:** The framework-neutral factories return frozen, named asynchronous cases with stable assertion codes; a package's Vitest suite registers and runs those cases without making Vitest a destination-family runtime dependency. The Retriever factory requires the exact family-owned match/miss matrix for every portable filter, conjunction, all-tags, limit, continuation, and partial-result behavior; callers cannot omit a case by narrowing the input inventory. Cursor tokens are reconstructed under the exact connection, configuration, query, and upper-time binding before the adapter sees them. A deterministic family-owned adapter proves the suite itself, and seeded filter-ignoring or identity-swapping adapters must fail the exact relevant assertion. Protocol exposes its canonical fixture only through a test-only package entrypoint, so destination tests neither copy canonical-schema ownership nor import another package's private source. A destination cannot advertise retrieval until its implementation passes the full shared suite. Langfuse adds API-profile fixtures and Local SQLite adds query-plan, migration, and transaction fixtures; both are held to the same CLI-visible semantics.

### ADR-005: Standardize TypeScript unit and contract tests on Vitest

**Decision:** Every TypeScript unit and contract suite runs directly from source through Vitest with V8 coverage. Compiled `node:test` suites are not supported. Coverage includes all production TypeScript reachable in the package, excludes tests and declarations, and enforces the reviewed per-package floors in the repository quality-policy registry.

**Context:** Mixing compiled Node tests with Vitest produced different discovery, transformation, and coverage behavior. Allowing every empty workspace to pass also made a missing suite indistinguishable from an intentionally skeletal package.

**Consequences:** A package with substantive production code must contain at least one discoverable test and may not use `--passWithNoTests`. Mechanically bounded marker-only scaffolds may pass without tests only until they exceed their declared file or source-line allowance. Coverage thresholds ratchet upward and cannot be lowered relative to the pull request base. Unit suites remain deterministic and may not use network, Docker, installed harnesses, or per-test dependency installations.
