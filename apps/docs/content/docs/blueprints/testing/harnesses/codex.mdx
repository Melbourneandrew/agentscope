## Capability Summary

The Codex integration must install an authenticated exact binary, exercise each claimed documented interface against internal model mocks, own a reversible root hook, and produce independent evidence without a model-provider credential or public model traffic.

## Architecture Decision Records

### ADR-001: Authenticate exact public npm inputs during ephemeral preparation

**Decision:** Trusted preparation fetches exact public `@openai/codex` wrapper and platform packages without npm authentication and verifies registry integrity, npm signatures, and published provenance for the same release identity. A container backend builds the ephemeral prepared image defined by [Matrix Operations](/docs/blueprints/testing/integration/matrix-operations); a native backend installs the same authenticated exact input on its disposable runner and records the installed binary identity without inventing an image. The compatibility catalog, not a moving installer or research exemplar, selects the supported version. A persistent mirror requires a separate license and artifact-content review; the repository license alone is not a blanket redistribution conclusion for every packaged component.

**Context:** Codex documents npm installation and publishes Apache-2.0 source and release artifacts with registry provenance ([installation](https://developers.openai.com/codex/cli), [open-source repository](https://developers.openai.com/codex/open-source)). Exact package integrity and provenance can be checked before scenario isolation.

**Consequences:** No npm credential, GHCR image, vendor installer execution on the host, or moving `latest` input is required. Cache hits remain non-authoritative until reverified.

### ADR-002: Treat TUI and exec as separate documented interfaces

**Decision:** Interactive evidence drives `codex` through the semantic PTY contract; headless evidence drives `codex exec`, with `--json` used as one native observation plane. A release claim names the exact mode exercised and cannot infer parity between them.

The closed canonical pairs are `interactive` with `semantic-pty` and `exec` with `jsonl`. Each pair is a distinct harness claim identity for the exact Codex version; neither may satisfy the other.

**Context:** Codex documents the interactive CLI and a distinct non-interactive `exec` interface with JSON Lines output ([CLI reference](https://developers.openai.com/codex/cli/reference), [non-interactive mode](https://developers.openai.com/codex/non-interactive-mode)).

### ADR-003: Route Responses traffic to one unauthenticated internal provider

**Decision:** The scenario uses an isolated `CODEX_HOME` and a version-bound custom model-provider configuration whose `base_url` names only the controller-owned upstream-derived MockServer selected under [Mock Services ADR-001](/docs/blueprints/testing/integration/mock-services), `wire_api` is `responses`, and `requires_openai_auth` is false. The candidate can reach its deterministic Responses data plane but cannot configure the service, read or mutate its assertion ledger, or access its control authority. The controller authenticates the exact service artifact and candidate exclusion before releasing input. Provider retries and alternate transports are disabled. No OpenAI or other model-provider credential, synthetic token, stored login, MCP server, or ambient provider configuration is present. Credential absence, denied public egress, and independently retrieved model requests prove the bounded no-fallback claim; a SessionStart gate supplies none of those authorities.

**Context:** Codex supports custom model providers and an unauthenticated Responses configuration ([advanced configuration](https://developers.openai.com/codex/config-advanced), [configuration reference](https://developers.openai.com/codex/config-reference)). A disposable exact-binary research probe completed through `/v1/responses` without an authorization header; its details remain in the Codex research Bead rather than becoming a support pin.

**Consequences:** Update checks, web search, analytics, feedback, apps, plugins, memories, multi-agent features, MCP discovery, and every non-loopback telemetry route are disabled where the selected version documents a control and are still denied at the network boundary. A CLI-reported cost field cannot prove spend. The scenario adds no model gateway, bespoke protocol parser, alternate ledger, or hook-dependent socket-admission service.

### ADR-004: Block admission until the root hook contract is proven

**Decision:** Agentscope installs one owned reversible user-root Codex hook only after the selected binary proves the official hook lifecycle for every claimed mode. Installation preserves foreign configuration, rejects conflicting concurrent edits, captures within the hook deadline, fails open to Codex, and uninstall removes only owned state. A documented shell-command handler is admissible under [Hook Installation ADR-004](/docs/blueprints/operations/hook-installation). For Codex 0.149.1 on each admitted platform, the owned command-hook block reserves exactly 1,000 milliseconds for vendor shell, loader, and runtime mediation before launcher entry and derives its integer timeout in seconds as `ceil((configured hook duration in milliseconds + 1,000) / 1,000) + 1`. This produces seven seconds for the 5,000-millisecond default and at most 62 seconds for the 60,000-millisecond configuration ceiling. The exact installed timeout is transactionally bound to the same duration as the launcher. Candidate-bound actual-binary evidence must measure from vendor dispatch to the launcher's first instruction and reject admission unless that interval is at most 1,000 milliseconds; once admitted, the formula leaves from 1,000 through 1,999 milliseconds after the complete Agentscope deadline. An absent, fixed, rounded-down, clamped, or mismatched value, or an unproved or exceeded mediation reserve, is ineligible rather than shortened. Pre-launch mediation remains outside Agentscope's launcher deadline and is never attributed to it. The integration remains unadmitted while a required lifecycle event does not execute or the exact installed representation cannot prove bounded launcher behavior, durable acceptance at the selected duration, deadline fail-open behavior, and absence of retry or detached work.

**Context:** Codex documents user hooks and event payloads ([hooks](https://developers.openai.com/codex/hooks)). Research found that a `Stop` hook did not fire under the tested `exec` configuration. Authenticated Codex 0.149.1 Linux evidence then reproduced three real-TUI completions without durable acceptance or trace under the former 2,500-millisecond Agentscope deadline; observed 2,639–2,752-millisecond failed paths prove only that the old budget is insufficient, not that the selected 5,000-millisecond policy succeeds. The documented shell-string form requires exact encoding and actual-binary proof, but shell mediation and upstream input mutation are not themselves Agentscope safety failures. Missing lifecycle evidence may not be papered over with transcript polling.

**Consequences:** Codex remains unverified until disposable exact-version tests prove hook discovery, lifecycle coverage, exact installed command behavior, failure semantics, and owned install/uninstall for each claimed mode.

### ADR-005: Correlate independent native and Agentscope observations

**Decision:** The independent scenario oracle correlates process/PTY completion, the exact internal Responses ledger, vendor-invoked `Stop` capture, the required graceful `SessionEnd` observation, documented `exec --json` events for that mode, bounded version-specific rollout observations when needed, loopback OTLP receipt, installed configuration ownership, filesystem mutation, and cleanup. `SessionStart` is a diagnostic observation, not capture initialization or acceptance authority. The oracle owns fixed stimuli and expected trace hierarchy, context, redaction, and session/turn correlation; neither a scenario adapter nor a model response supplies expected success. Rollout files are never the sole oracle or a stable cross-version schema. Local SQLite evidence applies only to a scenario claiming that destination and cannot replace OTLP evidence.

**Context:** Codex exposes documented JSONL output while rollout persistence is an implementation detail whose path and record shapes can change.

**Consequences:** Raw rollout, terminal, prompt, response, and complete trace content remains scenario-local. Missing or duplicate required capture/lifecycle records, cross-session substitution, malformed or contradictory native observations, unexpected model routes, absent or mismatched OTLP delivery, public requests, or uncertain cleanup fail admission. An absent diagnostic `SessionStart` is recorded truthfully and cannot alone fail otherwise complete capture evidence.

### ADR-006: Treat vendor-mediated hook input as untrusted

**Decision:** A vendor-selected shell or other process may read, alter, truncate, or fabricate hook input before the Agentscope launcher starts. Agentscope treats every byte received at launcher entry as untrusted and governs its own behavior beginning at its first userland instruction. A shell-mediated Codex handler is admissible when its installed constant command representation uses the exact-version/platform dialect and path encoder bound by [Hook Installation ADR-004](/docs/blueprints/operations/hook-installation), deterministically names the exact absolute Agentscope-owned launcher, interpolates no per-invocation value, gives the launcher zero external arguments and one bounded EOF-framed stdin stream, and preserves the launcher's bounded zero-output fail-open terminal after entry. Shell mediation neither authenticates the caller nor disqualifies the integration.

Both canonical claim pairs—`interactive` with `semantic-pty` and `exec` with `jsonl`—independently prove capture through one vendor-invoked `Stop` after each completed root turn and the exact installed launcher. Graceful root-session shutdown additionally requires exactly one `SessionEnd` after transcript flush. `Stop` is the trace-producing boundary; `SessionEnd` supplies graceful lifecycle evidence and is not itself claimed to produce a trace. `SessionStart` neither initializes capture nor grants provider, controller, or oracle authority. Prompt release and model-request processing do not wait for it, and its absence or position relative to the first request is not an admission predicate. Any observed startup event is classified truthfully without fabricating a missing event or attributing its timing to capture.

Interactive input still passes through the sole semantic PTY transport after the authenticated process-topology checkpoint supplied by the Testkit kernel and selected isolation backend. This decision removes the hook-dependent pending/armed model gate, pre-parser socket hold, gate-generation receipts, and dedicated model-admission cutoff; it does not replace or extend the existing kernel deadlines, controller containment reserve, bounded service shutdown, candidate/controller separation, or exact resource reconciliation. An unjoined service or process, mutable or incomplete final ledger, or uncertain cleanup remains a failure. The timeout envelope and actual-binary mediation proof in ADR-004 remain mandatory and cannot be inferred from a diagnostic SessionStart observation.

The installed constant command, arbitrary-input handling, launcher-entry deadline, zero-output fail-open terminal, ownership, conflict, upgrade, and uninstall contract remain independently required for every claimed mode. `PreToolUse`, `PostToolUse`, permission, compaction, and subagent hooks neither substitute for nor add to this root capture contract. Hard process or container termination is an interruption: independent process evidence must classify it and must never fabricate `SessionEnd` or reuse graceful-shutdown evidence. No transcript poll, manually invoked hook, fake executable, or externally supplied canonical trace can replace the real completed-turn capture path.

**Context:** Exact public source commit `ff29a44391deccde0aba0f8390337d7f3c319ea4` shows the 0.149.1 command runner passing one configured command string to a selected shell before launcher entry. That mediation remains outside Agentscope's trust and deadline claims. The product capture path handles `Stop` without SessionStart initialization. `AC-CAP-001.1` through `AC-CAP-001.5` require fail-open, bounded invocation, immutable configuration, and truthful trace identity; they do not require capture setup before inference. Historical interactive evidence showed that waiting for SessionStart before prompt input can deadlock, and subsequent gate-arm failures remained intermittent after diagnostic-only changes. That history does not identify a vendor defect or prove a causal repair. The pre-model gate is retired because its ordering obligation is unnecessary for the product capture and independent safety proof.

**Consequences:** Admission requires exact-version, exact-mode packed-CLI evidence of real Stop capture and independent delivery plus graceful lifecycle, launcher, installation, and cleanup behavior. A model request before SessionStart, or a run without that diagnostic event, may pass only when all those independent obligations pass. Missing Stop, missing graceful SessionEnd, missing destination delivery, or uncertain containment still fails. Removing the gate neither admits a support row nor certifies a replacement mock; the selected upstream-derived service must first prove the protected control boundary in Mock Services ADR-001. Historical failures remain recorded rather than relabeled as fixed.
