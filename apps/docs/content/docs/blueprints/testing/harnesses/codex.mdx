## Capability Summary

The Codex integration must install an authenticated exact binary, exercise each claimed documented interface against internal model mocks, own a reversible root hook, and produce independent evidence without a model-provider credential or public model traffic.

## Architecture Decision Records

### ADR-001: Authenticate exact public npm inputs during ephemeral preparation

**Decision:** Trusted preparation fetches exact public `@openai/codex` wrapper and platform packages without npm authentication and verifies registry integrity, npm signatures, and published provenance for the same release identity. A container backend builds the ephemeral prepared image defined by [Matrix Operations](/docs/blueprints/testing/integration/matrix-operations); a native backend installs the same authenticated exact input on its disposable runner and records the installed binary identity without inventing an image. The compatibility catalog, not a moving installer or research exemplar, selects the supported version. A persistent mirror requires a separate license and artifact-content review; the repository license alone is not a blanket redistribution conclusion for every packaged component.

**Context:** Codex documents npm installation and publishes Apache-2.0 source and release artifacts with registry provenance ([installation](https://developers.openai.com/codex/cli), [open-source repository](https://developers.openai.com/codex/open-source)). Exact package integrity and provenance can be checked before scenario isolation.

**Consequences:** No npm credential, GHCR image, vendor installer execution on the host, or moving `latest` input is required. Cache hits remain non-authoritative until reverified.

### ADR-002: Treat TUI and exec as separate documented interfaces

**Decision:** Interactive evidence drives `codex` through the semantic PTY contract; headless evidence drives `codex exec`, with `--json` used as one native observation plane. A release claim names the exact mode exercised and cannot infer parity between them.

The closed canonical pairs are `interactive` with `semantic-pty` and `exec` with `jsonl`. Each pair is a distinct harness claim identity for the exact Codex version; neither may satisfy the other.

**Context:** Codex documents the interactive CLI and a distinct non-interactive `exec` interface with JSON Lines output ([CLI reference](https://developers.openai.com/codex/cli/reference), [non-interactive mode](https://developers.openai.com/codex/non-interactive-mode)).

### ADR-003: Route Responses traffic to one unauthenticated internal provider

**Decision:** The scenario uses an isolated `CODEX_HOME` and a version-bound custom model-provider configuration whose `base_url` is one non-aliasable endpoint of the repository-owned, exact-build, gate-capable Responses MockServer selected under [Mock Services ADR-001](/docs/blueprints/testing/integration/mock-services), `wire_api` is `responses`, and `requires_openai_auth` is false. That single controller-owned process is the socket-admission authority, HTTP parser, deterministic Responses route, terminal connection/parser authority, and sole namespaced request ledger; it never forwards to another model service. Its exact production source-to-artifact graph and executable identity are authenticated before launch. It runs outside the candidate process boundary, exposes only the scenario endpoint to the candidate, and exposes its challenge-bound control channel, parser state, ledger, and storage only to the controller. Before prompt release and again after ledger settlement, the controller authenticates that topology and proves no alternate candidate-reachable model route exists. A missing, substituted, candidate-co-resident, independently controlled, or unjoined service is ineligible. Provider retries and alternate transports are disabled. No OpenAI or other model-provider credential, synthetic token, stored login, MCP server, or ambient provider configuration is present. Public egress denial and this MockServer ledger are the authority that no fallback occurred.

**Context:** Codex supports custom model providers and an unauthenticated Responses configuration ([advanced configuration](https://developers.openai.com/codex/config-advanced), [configuration reference](https://developers.openai.com/codex/config-reference)). A disposable exact-binary research probe completed through `/v1/responses` without an authorization header; its details remain in the Codex research Bead rather than becoming a support pin.

**Consequences:** Update checks, web search, analytics, feedback, apps, plugins, memories, multi-agent features, MCP discovery, and every non-loopback telemetry route are disabled where the selected version documents a control and are still denied at the network boundary. A CLI-reported cost field cannot prove spend; credential absence, denied egress, and the internal ledger do.

### ADR-004: Block admission until the root hook contract is proven

**Decision:** Agentscope installs one owned reversible user-root Codex hook only after the selected binary proves the official hook lifecycle for every claimed mode. Installation preserves foreign configuration, rejects conflicting concurrent edits, captures within the hook deadline, fails open to Codex, and uninstall removes only owned state. A documented shell-command handler is admissible under [Hook Installation ADR-004](/docs/blueprints/operations/hook-installation). For Codex 0.149.1 on each admitted platform, the owned command-hook block reserves exactly 1,000 milliseconds for vendor shell, loader, and runtime mediation before launcher entry and derives its integer timeout in seconds as `ceil((configured hook duration in milliseconds + 1,000) / 1,000) + 1`. This produces seven seconds for the 5,000-millisecond default and at most 62 seconds for the 60,000-millisecond configuration ceiling. The exact installed timeout is transactionally bound to the same duration as the launcher. Candidate-bound actual-binary evidence must measure from vendor dispatch to the launcher's first instruction and reject admission unless that interval is at most 1,000 milliseconds; once admitted, the formula leaves from 1,000 through 1,999 milliseconds after the complete Agentscope deadline. An absent, fixed, rounded-down, clamped, or mismatched value, or an unproved or exceeded mediation reserve, is ineligible rather than shortened. Pre-launch mediation remains outside Agentscope's launcher deadline and is never attributed to it. The integration remains unadmitted while a required lifecycle event does not execute or the exact installed representation cannot prove bounded launcher behavior, durable acceptance at the selected duration, deadline fail-open behavior, and absence of retry or detached work.

**Context:** Codex documents user hooks and event payloads ([hooks](https://developers.openai.com/codex/hooks)). Research found that a `Stop` hook did not fire under the tested `exec` configuration. Authenticated Codex 0.149.1 Linux evidence then reproduced three real-TUI completions without durable acceptance or trace under the former 2,500-millisecond Agentscope deadline; observed 2,639–2,752-millisecond failed paths prove only that the old budget is insufficient, not that the selected 5,000-millisecond policy succeeds. The documented shell-string form requires exact encoding and actual-binary proof, but shell mediation and upstream input mutation are not themselves Agentscope safety failures. Missing lifecycle evidence may not be papered over with transcript polling.

**Consequences:** Codex remains unverified until disposable exact-version tests prove hook discovery, lifecycle coverage, exact installed command behavior, failure semantics, and owned install/uninstall for each claimed mode.

### ADR-005: Correlate independent native and Agentscope observations

**Decision:** The Codex oracle correlates process/PTY completion, the exact internal Responses ledger, hook invocations, documented `exec --json` events, bounded version-specific rollout observations when needed, loopback OTLP receipt, installed configuration ownership, filesystem mutation, and cleanup. Rollout files are never the sole oracle or a stable cross-version schema.

**Context:** Codex exposes documented JSONL output while rollout persistence is an implementation detail whose path and record shapes can change.

**Consequences:** Raw rollout, terminal, prompt, and response content remains scenario-local. Unknown native records, missing hooks, public requests, or correlation gaps fail admission.

### ADR-006: Treat vendor-mediated hook input as untrusted

**Decision:** A vendor-selected shell or other process may read, alter, truncate, or fabricate hook input before the Agentscope launcher starts. Agentscope treats every byte received at launcher entry as untrusted and governs its own behavior beginning at its first userland instruction. A shell-mediated Codex handler is admissible when its installed constant command representation uses the exact-version/platform dialect and path encoder bound by [Hook Installation ADR-004](/docs/blueprints/operations/hook-installation), deterministically names the exact absolute Agentscope-owned launcher, interpolates no per-invocation value, gives the launcher zero external arguments and one bounded EOF-framed stdin stream, and preserves the launcher's bounded zero-output fail-open terminal after entry. Shell mediation neither authenticates the caller nor disqualifies the integration.

Both canonical claim pairs—`interactive` with `semantic-pty` and `exec` with `jsonl`—must independently prove one closed root lifecycle with one `Stop` after each completed root turn and exactly one `SessionEnd` after transcript flush on graceful root-session shutdown. Each pair must also prove exactly one `SessionStart` at its strongest truthful version-bound boundary. The `exec` with `jsonl` claim, and any future interface without an earlier contrary Blueprint decision, requires `SessionStart` before the first user turn. Codex 0.149.1 `interactive` with `semantic-pty` instead requires `SessionStart` before the protected MockServer admission endpoint accepts the first Responses request into its route or ledger. Only that exact version and interactive mode may accept bounded user input before `SessionStart`, and only inside the already authenticated, isolated process boundary.

Before releasing the prompt, the controller creates exactly one challenge-and-run-bound pending gate in the selected MockServer. Its named model-admission cutoff is fixed before service launch, is at least 5,000 milliseconds earlier than the execution kernel cutoff, and can only be shortened by an earlier governing deadline. The fixed interval between those cutoffs is reserved solely to settle and join the service, its control operation, every connection, parser work, and ledger; the controller's later containment and backend-reconciliation reserve remains untouched. An initial socket that arrives while the gate is pending may be held below the HTTP parser until the model-admission cutoff, but no application byte may be read, parsed, routed, ledgered, or answered. After independently observing the exact completed `SessionStart`, the controller arms the gate over its protected control channel and requires an acknowledgement bound to the same challenge, run, and single-use generation. Only then may the service pass the socket to its parser and atomically enter provisional `parsing-first` state. One complete valid Responses request received before the cutoff advances that generation to admitted relay state; partial, malformed, canceled, or late first-request work cannot. Later requests or connections are allowed only in admitted state and before the model-admission cutoff, remain bound to the same run and original deadline, and are governed by the closed scenario oracle; they do not re-arm or weaken the first-request proof.

Gate creation, socket hold, arm, acknowledgement, parsing, admission, relay, denial, terminal receipt, ledger settlement, and service join all consume only the original remaining authority; none starts a fresh window. One atomic transition winner governs cutoff-versus-arm, arm-versus-acknowledgement, acknowledgement-versus-parse, parsing-first-versus-admission, first-request-versus-relay, and cutoff-versus-new-connection or request races. At the model-admission cutoff, a pending or armed gate becomes permanently denied; provisional `parsing-first` atomically becomes denied, cancels and closes its incomplete parser/connection work, joins it within the reserved interval, and can never become admitted; an admitted relay atomically becomes draining, closes socket admission, and rejects every not-yet-admitted request before parser work. The reserved interval admits no new application work and drains only operations that won admission before the cutoff. Missing, duplicate, substituted, late, or ambiguous transition evidence, any connection before the initial one is admitted, or any pre-arm application read permanently fails the scenario; no later observation can reopen it. After the endpoint and parser are frozen against later mutation and all canceled or admitted work settles, the same service emits a content-free terminal receipt bound to the run and ledger generation that accounts for every connection, EOF or close disposition, accepted, canceled, and rejected parser work, malformed or truncated framing, parser errors, and every ledger mutation; only then may the controller take the final immutable ledger snapshot. Pipelining and later valid requests are accepted only when the scenario oracle permits them and they win admission before the cutoff. An unsettled or unaccounted socket, byte, parser operation, receipt, or ledger mutation, or failure to join the service by the kernel cutoff, is terminal uncertainty and cannot become cleanup or admission evidence.

The semantic PTY transport consumes the pre-prompt authenticated process-topology checkpoint supplied by the sole Testkit kernel and selected isolation backend; it does not authenticate, freeze, or own that process set itself. Any live checkpoint notification used by the controller must be authenticated as that kernel's completed event across the candidate principal boundary; a candidate-sendable signal, shared writable marker, or candidate-accessible descriptor is not checkpoint authority. The MockServer control listener and every accepted control connection remain accessible only to the controller for their entire lifetime, including before first selection and after listener closure; a challenge or closed pathname alone does not make a candidate-reachable channel private. The independent scenario oracle must correlate the selected MockServer's admission transition, terminal receipt, and ledger with the same `SessionStart` open-and-close records in the final graceful lifecycle. Any scenario-local or candidate-co-resident gateway, alternate model mock, additional request ledger, parser, route, or protocol amendment point is forbidden. `PreToolUse`, `PostToolUse`, permission, compaction, and subagent hooks neither substitute for nor add to this root capture contract. A hard process or container termination cannot run `SessionEnd`; its independent process evidence must classify the missing event as crash/interruption and reconciliation must never fabricate it or reuse graceful-shutdown evidence. A future version or interface that needs a later `SessionStart` boundary requires its own earlier standalone Blueprint decision and hostile proof before implementation or admission.

**Context:** Exact public source commit `ff29a44391deccde0aba0f8390337d7f3c319ea4` shows the 0.149.1 command runner passing one configured command string to the selected shell with `-c`, or to `$SHELL` or `/bin/sh` with `-lc`. That shell, native loader, interpreter startup, and startup policy execute before launcher code, so Agentscope does not assign their behavior to its launcher deadline, zero-output terminal, or mutation/cleanup evidence. Its safety obligation is to install a constant correctly encoded representation and make its own code handle arbitrary received input without escaping the contract after entry. Exact GitHub-hosted hermetic evidence recorded in repo-local Bead `agentscope-wth.2`, comment `01a0b114-1abb-7bb4-b611-74c8faa477a3`, proves that Codex 0.149.1 does not emit `SessionStart` merely by opening its interactive TUI: withholding the prompt until the hook completed deadlocked at TUI startup, while the exact PTY/runtime and substrate checks passed. The first enforceable mediation boundary for that interface is therefore the protected MockServer admission endpoint before any model request is admitted, not raw prompt acceptance inside the isolated process.

**Consequences:** Codex 0.149.1 is no longer excluded solely because it mediates the hook through a shell or because its interactive interface starts the hook after bounded prompt input. It remains unverified until each claimed mode proves the complete root lifecycle and packed actual-binary contract, including exact dialect/path encoding, arbitrary-input handling, launcher-entry deadline, fail-open, ownership, conflict, upgrade, uninstall, process, and cleanup behavior. Interactive evidence must drive the prompt through the PTY rather than argv, consume the kernel-owned topology checkpoint before input, use the one-shot pending/armed MockServer protocol for the completed `SessionStart`, deny the first Responses request when that predicate is absent or mismatched, and reject an admission transition or final lifecycle that does not correlate to the exact observed run. This ADR authorizes no component work, milestone selection, manifest row, or support claim. The vendor shell, runtime startup, caller identity, and pre-launch input history are outside the launcher claim rather than additions to Agentscope's trusted computing base.
