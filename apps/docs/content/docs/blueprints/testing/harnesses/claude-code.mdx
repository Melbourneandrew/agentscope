## Capability Summary

The Claude Code integration must authenticate an exact binary, exercise documented interactive and print interfaces through an internal Anthropic mock, own a reversible root hook, and prevent overlap with direct-to-Langfuse plugins.

## Architecture Decision Records

### ADR-001: Verify exact platform packages against Anthropic's signed manifest

**Decision:** Trusted preparation fetches an exact public Claude Code platform package without npm authentication, verifies its registry integrity, verifies the contained binary digest against Anthropic's exact-version manifest, and authenticates that manifest with Anthropic's documented release-signing key. A container backend builds the ephemeral prepared image; a native backend installs the same authenticated exact input on its disposable runner and records the installed binary identity without inventing an image. A moving bootstrap installer is not artifact authority. Persistent mirroring or redistribution is prohibited unless vendor terms or explicit permission establish that right.

**Context:** Anthropic documents exact-version manifests, platform checksums, and detached signatures for current releases ([installation and binary integrity](https://code.claude.com/docs/en/installation)). Its legal material does not provide a general redistribution grant ([legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)).

**Consequences:** The default path needs no npm credential, new GitHub secret, or GHCR image. The catalog selects the supported version; observed research artifacts do not silently become pins.

### ADR-002: Treat interactive and print modes as separate interfaces

**Decision:** Interactive evidence drives `claude` through the semantic PTY contract. Headless evidence drives `claude -p` and binds the selected text, JSON, or stream-JSON contract. A support claim names the exact mode and output contract exercised.

The closed canonical pairs are `interactive` with `semantic-pty`, `print` with `text`, `print` with `json`, and `print` with `stream-json`. Each pair is a distinct harness claim identity for the exact Claude Code version and needs its own native evidence.

**Context:** Claude Code documents interactive and programmatic interfaces separately ([CLI reference](https://code.claude.com/docs/en/cli-usage), [headless use](https://code.claude.com/docs/en/headless)).

### ADR-003: Route Anthropic traffic through one internal endpoint with synthetic auth

**Decision:** The scenario uses an isolated Claude home and an explicit environment allowlist. `ANTHROPIC_BASE_URL` names only the internal MockServer and `ANTHROPIC_AUTH_TOKEN` contains a fixed non-authoritative sentinel accepted only by that mock. All API keys, stored OAuth state, cloud-provider selectors and credentials, host-managed provider settings, browser login, and alternate provider routes are absent. The mock implements the exact version-bound Anthropic Messages streaming profile observed from the selected binary; public egress denial and the request ledger prove no fallback.

**Context:** Anthropic documents base-URL and authentication precedence ([authentication](https://code.claude.com/docs/en/authentication), [environment variables](https://code.claude.com/docs/en/env-vars)). Print and interactive modes do not necessarily accept the same credential source or emit the same auxiliary requests.

**Consequences:** Tests assert exact request counts and routes, including auxiliary title or summary traffic. CLI-reported nominal cost is not spend evidence. No authority-bearing Anthropic, cloud-provider, or model-provider credential enters preparation or execution.

### ADR-004: Suppress optional network authorities and rely on denied egress

**Decision:** The selected version's documented controls disable updates, nonessential traffic, telemetry, error reporting, feedback, marketplace registration, login/logout, Claude.ai connectors, terminal-title requests, browser integration, slash-command discovery, MCP sources, and unneeded tools. The scenario still denies public egress and fails on every attempted external route because configuration suppression is not an isolation boundary.

**Context:** Claude Code documents individual and aggregate network controls, with explicit exceptions ([environment variables](https://code.claude.com/docs/en/env-vars), [data usage](https://code.claude.com/docs/en/data-usage)).

### ADR-005: Own one root hook and require explicit Langfuse-plugin migration

**Decision:** Agentscope installs one owned reversible handler block in the isolated user-root Claude settings only if the selected Claude Code version proves that the documented handler representation deterministically reaches the exact absolute Agentscope launcher, the launcher receives zero external arguments and one bounded untrusted stdin payload, and the owned representation performs no `PATH` lookup or per-invocation interpolation. Vendor shell mediation is permitted and does not authenticate the caller or payload. The integration preserves unrelated settings and hooks, proves idempotence and concurrent-edit rejection, captures the required session/turn/tool lifecycle within the hook deadline, fails open to Claude, and removes only owned state. If the official Langfuse Claude plugin or another trace exporter owns overlapping events, installation reports the conflict and requires explicit migration to one capture owner; hook ordering is never used to coordinate duplicate exporters.

**Context:** Claude supports user, project, policy, plugin, skill, and subagent hooks, and matching handlers may coexist without an ordering authority ([hooks](https://code.claude.com/docs/en/hooks)). The Langfuse plugin registers overlapping hooks, reads transcripts, persists state, may acquire dependencies, and reports directly with Langfuse credentials ([Langfuse plugin](https://github.com/langfuse/claude-observability-plugin/tree/d06829810cce8a8a4f486e0afebd155e95ab9517)).

**Consequences:** Shell mediation alone is not an admission blocker. Exact-version evidence must still prove the installed representation performs no per-invocation input interpolation and reaches the owned launcher with its bounded fail-open behavior; the launcher treats every received byte as untrusted. The hermetic suite never installs, enables, or live-tests the Langfuse plugin. Agentscope reporting evidence is only OTLP to the loopback ledger.

### ADR-006: Treat local transcripts as version-specific observations

**Decision:** The Claude Code oracle correlates process/PTY completion, exact model-mock ledger, denied-egress probe, hook ledger, documented stream events, loopback OTLP receipt, settings ownership, filesystem mutation, and cleanup. Local transcript JSONL may supplement that oracle only through strict exact-version parsing and sanitized fixtures; it is never a stable cross-version contract or sole source of truth.

**Context:** Hook payloads expose a transcript path, but Anthropic does not publish a stable schema for the local transcript file.

**Consequences:** Unknown records, missing hooks, duplicate ownership, or correlation gaps fail admission. Raw transcripts never leave the disposable scenario.

### ADR-007: Keep Claude Code unadmitted until lifecycle replay passes

**Decision:** Each exact Claude Code claim identity is admitted independently. It cannot enter the compatibility catalog or release support manifest until the selected binary passes that pair's documented interface under denied public egress, proves its exact internal request and fallback behavior and root launcher contract, and completes its packed-Agentscope hook install, capture, fail-open deadline, conflict, concurrent-edit, uninstall, process, filesystem, backend-appropriate prepared-input and resource cleanup, and ledger evidence. Passing another mode/output pair neither satisfies nor blocks this claim, except where an explicitly shared version-wide acquisition or suppression invariant itself fails. Research observations establish candidate controls and oracles, not support.

**Context:** Official-source and disposable research established a viable authenticated acquisition and internal routing candidate, but did not complete the governed packed-CLI lifecycle or release admission replay.

**Consequences:** A catalog proposal that lacks any of these version-bound proofs remains explicitly unverified and cannot be substituted with a fake executable, transcript fixture, CLI cost field, or live service test.

### ADR-008: Use a four-event owned profile with an enclosing handler budget

**Decision:** For Claude Code 2.1.245 on each eligible POSIX platform, the owned root profile consists of `SessionStart`, `PreToolUse`, `PostToolUse`, and `Stop`. These boundaries must preserve the required session, turn, and tool observations and the incremental capture and correlation rules in [Native Trace Mapping](/docs/blueprints/foundations/native-trace-mapping). Agentscope does not install a `SessionEnd` handler or set a global vendor hook-timeout override. Native session-end occurrence, reason, and timing remain explicitly unavailable when not independently observed; neither `Stop` nor process completion fabricates them. Session continuity and effective observation timing retain their existing provenance and unavailable-state rules.

For every configured integer Agentscope hook duration `D` from 50 through 60,000 milliseconds, each owned handler encodes `ceil((D + 2,000) / 1,000)` timeout seconds in the same transaction that binds the launcher duration. The resulting finite range is 3 through 62 seconds. The selected envelope allocates 1,000 milliseconds to vendor mediation before the launcher's first instruction and at least 1,000 milliseconds to terminal settlement after the complete Agentscope deadline. These are proposed finite budgets, not observed or certified vendor guarantees: exact-version, exact-platform actual-binary evidence must prove the pre-entry bound and post-deadline terminal behavior before installation eligibility or admission. A version or platform that cannot represent or prove the envelope is unsupported rather than clamped, silently shortened, or admitted using another harness's evidence.

The launcher still creates its one original configured absolute deadline at its first instruction. Pre-entry mediation is outside that authority; the vendor timeout never restarts or extends it. Parent cancellation, zero-output fail-open behavior, capture cancellation, prevention of later work, and joined process/resource cleanup remain required. Every mode/output pair in ADR-002 independently proves its real vendor-invoked profile, required capture and delivery, exact installed timeout, and the remaining lifecycle obligations in ADR-007; component or static-source evidence alone admits no pair.

Upgrade replaces an exact authenticated prior Agentscope-owned five-event block with this four-event block through [Hook Installation ADR-001](/docs/blueprints/operations/hook-installation)'s existing transaction. Uninstall recognizes an exact authenticated prior five-event or current four-event owned block and removes only that block. Partial, modified, ambiguous, or overlapping blocks retain the existing conflict and explicit-migration rules; a foreign `SessionEnd` or other hook is never removed merely because its event is absent from the new profile. Status and Doctor verify the selected owned profile and derived timeout rather than adopting a mismatched block.

**Context:** Data-only inspection of exact Claude Code 2.1.245 inputs found that the settings-derived overall `SessionEnd` budget is capped at 60,000 milliseconds. It therefore cannot enclose a 60,000-millisecond Agentscope deadline plus positive mediation and settlement reserves. The other four selected dispatch paths use their explicit handler timeout without that inspected `SessionEnd` cap. Static inspection does not prove actual dispatch timing, cancellation, or terminal behavior. [Trace Capture](/docs/requirements/trace-capture) requires useful observed context, safe bounded capture, and truthful unavailable metadata; it does not require installing a hook named `SessionEnd`.

**Consequences:** This profile avoids changing a global vendor budget or narrowing Agentscope's configured duration range. It does not claim a native session-end observation, guaranteed completed capture, a full capture window under every vendor interruption, or current Claude support. Installation, ownership, conflict detection, foreign-hook preservation, deadline fail-open behavior, and cleanup remain independently required; missing required session/turn/tool capture or uncertain settlement still fails admission.
