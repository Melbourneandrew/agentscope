## Capability Summary

Agentscope development may use a self-hosted Crabbox coordinator on Cloudflare Workers to acquire bounded disposable Hetzner Linux workers. The deployment follows the documented Wrangler, Crabbox, Cloudflare, and Hetzner operating paths. The custom protected launcher and every associated credential ceremony, policy, installer, service, and runtime are removed completely; they are neither an alternative nor a recovery authority.

Crabbox supplies disposable outer development capacity. The shared hermetic scenario runner remains the inner test boundary across workstation execution, CI execution, and Crabbox execution. Crabbox is optional development capacity; GitHub-hosted CI remains merge and release authority.

## Architecture Decision Records

### ADR-001: Use the supported upstream Crabbox coordinator

**Decision:** Agentscope self-hosts the Cloudflare Worker and SQLite-backed `FleetDurableObject` from `openclaw/crabbox` tag `v0.46.0`, exact commit [`8ba71f913bbe57285ae29af45ef0d8ec6712477d`](https://github.com/openclaw/crabbox/tree/8ba71f913bbe57285ae29af45ef0d8ec6712477d). Deployment and client commands follow that revision's documented [Cloudflare coordinator](https://github.com/openclaw/crabbox/blob/8ba71f913bbe57285ae29af45ef0d8ec6712477d/docs/infrastructure.md) and [Hetzner provider](https://github.com/openclaw/crabbox/blob/8ba71f913bbe57285ae29af45ef0d8ec6712477d/docs/providers/hetzner.md) paths. Agentscope does not copy or fork the coordinator implementation. A version change requires a standalone reviewed Blueprint change before rollout.

**Context:** The upstream coordinator already owns lease serialization, provider calls, active-lease and spend limits, expiry, cleanup retries, and the supported Cloudflare-to-Hetzner lifecycle. A local control plane duplicates that lifecycle and created the failures this decision replaces.

**Consequences:** Cloudflare Workers is the coordinator runtime and Hetzner is the only initially enabled provider. Direct-provider operation, custom domains, Cloudflare Access, Tailscale, checkpoints, portal artifacts, and other providers are outside the initial path. If the pinned path fails, operation stops for a reviewed upstream correction or version change; it does not restore a local launcher.

### ADR-002: Deploy with the upstream lock and ordinary Wrangler commands

**Decision:** The operator checks out the pinned source, installs `worker/package-lock.json` with `npm ci --prefix worker`, and deploys with the project-local Wrangler resolved by that lock. Cloudflare mutations use the documented Wrangler commands for secret upload, deployment, and inspection; deletion follows ADR-004's terminal reconciliation lifecycle. The reviewed development profile names one Worker, its `FLEET` Durable Object binding and migration, its 15-minute trigger, workers.dev exposure, required secret names, and bounded non-secret variables; it contains no secret value.

**Context:** Wrangler is Cloudflare's supported deployment and secret-management interface. A signed-plan grammar, privileged installer, observer, or local mutation executor adds a second unsupported authority.

**Consequences:** The operator records the pinned source, Node, npm, Wrangler, profile, account, and resulting Worker deployment identities. Moving `latest`, a global Wrangler selected from ambient `PATH`, dashboard-only configuration, and generated profiles are not deployment authority.

### ADR-003: Keep credentials ordinary, least-privilege, and out of workloads

**Decision:** One explicitly selected personal Cloudflare account hosts the development Worker, and one dedicated Hetzner project contains only Crabbox disposable workers. The operator creates the minimum Cloudflare API token required by documented Wrangler deployment and a Hetzner project Read & Write token. The Hetzner token and one random Crabbox shared token are Worker secrets; the Cloudflare token is used only for attended deployment. The shared bearer's only reusable copies are that Worker secret and Crabbox's ordinary mode-0600 client configuration of a dedicated fleet-control operating-system principal that never runs repository or candidate code. That principal resolves the pinned canonical coordinator origin before bearer lookup and makes direct Crabbox operation attended only. All credentials remain outside the repository, logs, artifacts, VM transfer, scenario inputs, and command arguments.

**Context:** Provider credentials necessarily have broader authority than a single worker. A dedicated project, an explicitly selected account, and Worker secret storage confine the practical scope without inventing a custom credential broker.

**Consequences:** Loss or suspected exposure freezes acquisition, first records exact active lease identities and restores attended cleanup authority for only those resources through the dedicated project's operator console, then revokes and replaces the affected Worker secret. Browser OAuth, an admin token, separate observer credentials, keychain wrappers, signer roots, and credential-role enrollment are not part of this path. Unattended use requires a later standalone Blueprint that admits a replay-safe broker and independent bounded reaper; it cannot be inferred from this direct attended path.

### ADR-004: Start with one small bounded worker and prove cleanup

**Decision:** Direct Crabbox use selects an explicit Hetzner server type, hard TTL, idle timeout, concurrency cap, modeled reservation cap, and no-retention/no-checkpoint policy before acquisition; it never accepts the provider default or a capacity fallback. Current values and the one-worker substrate procedure belong in the repo-local operational instructions and Beads, not this Blueprint. The limits are admission controls, not invoice guarantees; actual billing, network charges, and rate variance are independently observed and recorded.

A content-free substrate proof makes no repository-test claim and requires a retained non-secret fleet receipt that binds the exact lease, server, managed SSH-key, requested limits, and terminal times; zero active coordinator leases; and an independent, identity-bound observation through the dedicated Hetzner project that the exact server and managed key are absent. Any missing, pending, or mismatched resource class fails the proof. Coordinator rollback or retirement freezes acquisition, reconciles every active or historical unresolved lease and owned resource, preserves a compatible coordinator/reaper and Durable Object state until independent absence is proven, then removes the exact Worker secrets and deployment through supported Wrangler operations. It never deletes or rewinds Durable Object state merely to make inventory appear empty.

**Context:** The upstream Hetzner provider defaults to a larger class. An explicit small type and one-shot lifecycle make the first provider action bounded and legible.

**Consequences:** A capacity failure does not permit an implicit larger type. If cleanup is uncertain, new acquisition stops; recovery targets only the exact lease and provider identities through supported Crabbox and Hetzner tools.

### ADR-005: Completely remove the custom protected launcher

**Decision:** Before replacement-path Cloudflare or Hetzner mutation, remove the custom protected launcher completely from the repository and workstation: source, installers, upgraders, tests, CI contracts, documentation, services, stored launcher credentials, and installed program/configuration. Git history records repository removal. Beads retains the content-free exact terminal evidence for launcher-owned installed state, processes and services, and credential revocation or absence; do not retain a separate removal receipt in the current tree. The protected launcher, seven-slot enrollment, one-use plans, signer roots, observer roles, privileged ceremony, brokered credential store, and terminal retirement artifact must not remain optional, deprecated, installed, credential-bearing, or authoritative.

**Context:** Keeping an optional legacy path preserves duplicate credentials and conflicting deployment authority. The user has explicitly selected the upstream happy path as the sole authority.

**Consequences:** Legacy credentials are revoked without touching replacement credentials, and only exact launcher-owned files, processes, and identities are removed. The replacement path never migrates or reads legacy credentials. A need for stronger separation in the future starts with a new reviewed Blueprint; it cannot reactivate the deleted launcher.

### ADR-006: Keep Crabbox outside hermetic and release authority

**Decision:** Crabbox provisions only the disposable outer Linux guest. Before a guest may run repository tests, a repo-owned setup path must hydrate the exact inner hermetic scenario without provider credentials and retain output within that boundary. Every admitted Crabbox scenario composes the complete evidence and reconciliation contract in Harness Execution ADR-006, including its candidate, catalog, artifact, runtime, containment, and owned-resource identities; the ADR-004 receipt is only supplemental fleet-operational evidence. Until such a path is separately admitted, Crabbox is limited to the content-free substrate proof in ADR-004.

GitHub-hosted CI remains merge and release authority. Crabbox results are development evidence only; provider availability, quota, budget, cleanup delay, or Crabbox results can never make CI pass or block a product release.

**Context:** A remote SSH host is capacity, not a product-support or isolation boundary.

**Consequences:** Each admitted scenario retains the complete bounded, content-free Harness Execution ADR-006 evidence record. Its supplemental fleet receipt adds source/client and Worker identities, lease and server identities, requested limits, terminal times, cost observation, and cleanup result. It excludes tokens, IP addresses, SSH material, synchronized source, raw terminal content, prompts, traces, and harness output.
