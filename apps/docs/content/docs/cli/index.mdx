The `agentscope` command is the composition root for capture, configuration, installation, destination, retrieval, and diagnostic workflows. The currently shipped configuration surface is plan-first: `init` does not mutate without `--yes`, destination configuration is descriptor-driven, and routing is always explicit.

## Current availability

The packed production registry contains the reviewed Langfuse and Local SQLite destination descriptors. Local SQLite lifecycle commands remain gated by the exact native/platform candidate manifest and fail closed when that runtime is unavailable; descriptor presence alone is not a support claim. The packed harness registry remains empty until actual executable adapters complete their separate acceptance gates. `doctor` inspects configuration, recovery, credential, retained health, destination state, and Git state without inventing remote-provider or unsupported-platform evidence.

## Syntax

```bash
agentscope [--help] [--version] [command]
```

Root help and version use the `human` output mode and do not read configuration, resolve credentials, mutate state, or access the network.

## Output and exits

The CLI owns stdout, stderr, and process exit status. Domain packages return typed values and never write directly to terminal streams.

| Category            | Exit | Meaning                                       |
| ------------------- | ---: | --------------------------------------------- |
| `success`           |    0 | The requested operation completed.            |
| `usage`             |    2 | Arguments or an output mode were invalid.     |
| `not-found`         |    3 | The requested named resource was not found.   |
| `conflict`          |    4 | Current state prevented the requested change. |
| `unavailable`       |    5 | A required local or remote service failed.    |
| `permission-denied` |    6 | Required authority was not available.         |
| `internal-error`    |   70 | A closed internal contract failed.            |

## Automation

The root command currently supports only `human`. Public leaf commands that support `json` or `jsonl` declare a command-specific versioned data schema. JSON emits one newline-terminated result document. JSONL emits independently typed data records followed by one summary record. For a plan-first `--yes` mutation, the exact pre-mutation plan is written and flushed to stderr using the same selected presentation mode before Core receives the one-use apply authority; the final result remains the sole stdout result. JSON plans use `agentscope.cli.plan.v1`, and JSONL plans use `agentscope.cli.plan-record.v1`; neither is a result or diagnostic envelope. Machine-readable diagnostics are separate newline-terminated records on stderr, and failures emit no final machine result on stdout.

## Diagnostics

Diagnostics contain a stable code and closed category, never a stack trace, credential, provider response body, raw exception message, or echoed hostile argument. Root command failures use `cli.usage` or `cli.internal`.

## Examples

```bash
agentscope --help
agentscope --version
agentscope init
agentscope doctor --output json
agentscope destination list
agentscope routing list
```
