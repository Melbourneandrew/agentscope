Harnesses are coding-agent runtimes such as Codex or Claude Code, not model providers. The harness commands expose descriptor-owned discovery and the distinct explicit migration authority. Install and uninstall remain top-level plan-first commands.

The current packed CLI contains the generic plan-first harness command surface but no admitted concrete harness adapters. `harness list` is therefore empty and named status/install/uninstall/migrate requests return `harness.adapter-missing`. Codex and Claude Code are the 0.1.0 targets, but they enter this registry only after packed-CLI actual-binary admission. Other product-roster harnesses are later work and are not implied supported by the first alpha.

## Syntax

```bash
agentscope harness <list|status|migrate>
```

## Output and exits

This group help uses `human` output. Each subcommand documents its versioned `json` and `jsonl` result.

## Automation

Use `harness list` for a read-only roster, `harness status` for one adapter, and `harness migrate` only after an overlap diagnostic. No command infers a model provider from a harness name.

## Diagnostics

Group help performs no inspection and emits no operational diagnostic.

## Examples

```bash
agentscope harness list
agentscope harness status codex
agentscope harness migrate codex
```
