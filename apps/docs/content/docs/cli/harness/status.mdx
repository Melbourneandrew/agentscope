`agentscope harness status <harness>` reports both compatibility discovery and the current install-plan disposition without applying the plan. A recovery-required disposition is preserved rather than guessed from a journal.

No concrete adapter is registered in the current packed CLI, so named status requests currently return `harness.adapter-missing`.

## Syntax

```bash
agentscope harness status <harness> [--output human|json|jsonl]
```

## Output and exits

`human` prints the discovery and installation states. `json` emits one `agentscope.cli.harness-status.v1` result; `jsonl` emits the same single record.

## Automation

Use exact state values. `ready` means a fresh plan would change owned targets, not that mutation occurred. `unchanged` means no target change is currently planned.

## Diagnostics

- `harness.adapter-missing` means the requested first-party adapter is not registered.
- `harness.unavailable` means discovery or safe installation inspection could not complete.

## Examples

```bash
agentscope harness status codex
agentscope harness status codex --output json
```
