Deletion is intentionally separate from unconfiguration. The destination implementation must identify an exact owned local file and Core must validate ownership before removal. Remote destinations and descriptors without a governed deletion capability are unsupported.

For Local SQLite, `<selector>` may be the configured name or the opaque selector returned by an earlier unconfigure in another process. The first invocation is non-mutating and reports the exact lifecycle plan. `--confirm` presents that same plan before the package-owned handler deletes only the authenticated database family. Remote destinations remain unsupported.

## Syntax

```bash
agentscope destination delete <selector> [--confirm] [--output human|json|jsonl]
```

## Output and exits

Without `--confirm`, `human`, `json`, and `jsonl` report `state: planned` and `deleted: false`. Applied success uses `agentscope.cli.destination-delete.v1`. No command output contains deleted trace content or a credential.

## Automation

`--confirm` applies only to the exact file identified for this invocation. It cannot authorize a newly discovered path or a different connection.

## Diagnostics

- `configuration.unavailable` means ownership state could not be verified.
- `destination.confirmation-required` means explicit confirmation was absent.
- `destination.connection-missing` rejects an unknown connection.
- `destination.data-delete-unsupported` means the descriptor has no governed local deletion capability.
- `destination.lifecycle-busy`, `destination.lifecycle-outcome-unknown`, `destination.lifecycle-reconciliation-required`, and `destination.lifecycle-unavailable` are closed Local lifecycle outcomes.

## Examples

```bash
agentscope destination delete destination-connection-v1-<opaque-selector>
agentscope destination delete destination-connection-v1-<opaque-selector> --confirm
```
