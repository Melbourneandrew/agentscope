The 0.1.0 alpha does not admit Local SQLite or any other destination with a
local deletion capability. This registered command therefore fails closed
before producing a deletion plan or mutating data. Descriptor discovery and
the syntax below are reserved for future admitted lifecycle work.

Deletion remains intentionally separate from unconfiguration. A future
admitted implementation must identify one exact owned local file and Core must
validate ownership before removal. Remote destinations and descriptors without
a governed deletion capability remain unsupported.

## Syntax

```bash
agentscope destination delete <selector> [--confirm] [--output human|json|jsonl]
```

## Output and exits

For 0.1.0, no applied-success flow is available. `human`, `json`, and `jsonl`
failure output contains no trace content or credential.

## Automation

`--confirm` does not make an unavailable lifecycle capability available.

## Diagnostics

- `configuration.unavailable` means ownership state could not be verified.
- `destination.confirmation-required` means explicit confirmation was absent.
- `destination.connection-missing` rejects an unknown connection.
- `destination.data-delete-unsupported` means the descriptor has no governed local deletion capability.
- `destination.lifecycle-busy`, `destination.lifecycle-outcome-unknown`, and `destination.lifecycle-reconciliation-required` are closed lifecycle outcomes.
- `destination.lifecycle-unavailable` means no admitted Local lifecycle handler is available.

## Examples

The following syntax remains unavailable in 0.1.0:

```bash
agentscope destination delete <selector>
```
