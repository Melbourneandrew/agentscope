Destination commands operate on named connections described by reviewed first-party descriptors. Core owns the outer configuration document, credential references, and routing invariants; provider packages never own terminal output or configuration transactions.

The packed CLI registers the reviewed Langfuse and Local SQLite descriptors.
Langfuse uses the remote descriptor path. The 0.1.0 alpha does not admit the
Local SQLite capability: configuration refuses before settings, credentials, a
plan, or mutation, and its lifecycle commands remain unavailable. Descriptor
discovery is not a Local Reporter, Retriever, or platform support claim.

## Syntax

```bash
agentscope destination <configure|list|inspect|unconfigure|delete|recover|rotate>
```

## Output and exits

Group help uses `human`. Leaf commands additionally support their declared machine modes and fixed diagnostic-to-exit mapping.

## Automation

Langfuse configuration accepts non-secret JSON and explicit CI environment
references. Secrets are never accepted as settings or rendered in results.
The required Langfuse slot IDs are `public-key` and `secret-key`. Local SQLite
commands in 0.1.0 fail with `destination.capability-unavailable`; they do not
present or apply a persistence plan.

## Diagnostics

Leaf command pages list their exact fixed diagnostics. Group parsing failures use the root `cli.usage` contract.

## Examples

```bash
agentscope destination list
agentscope destination configure langfuse --name langfuse --credential-env public-key=LANGFUSE_PUBLIC_KEY secret-key=LANGFUSE_SECRET_KEY
```
