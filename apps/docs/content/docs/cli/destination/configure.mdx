The generic configure command resolves `<type>` through the compiled first-party registry, validates non-secret settings with the descriptor's detached strict schema, validates every declared credential slot, and commits one new configuration generation atomically.

In human output mode on a macOS terminal, omitting `--credential-env` collects every required credential through hidden terminal input before creating any stored credential. No value is echoed or placed in arguments or configuration. The foreground command has one 60-second allowance including setup, all prompts, and credential/configuration work; activity and additional slots do not reset it. This is an implementation policy, not a typing-time guarantee. Cancellation or expiry refuses later work and may require reconciliation of an already-started mutation. Native platform admission remains separate from this command contract.

Langfuse and Local SQLite remain registered first-party types. The 0.1.0 alpha does not admit the Local SQLite capability: both planning and `--yes` return `destination.capability-unavailable` before settings, credentials, plan presentation, or filesystem/configuration mutation. Local descriptor discovery is not a support claim.

## Syntax

```bash
agentscope destination configure <type> --name <name> [--settings <json>] [--credential-env <slot=VARIABLE...>] [--yes] [--output human|json|jsonl]
```

## Output and exits

Local SQLite returns exit 5 and the stable capability-unavailable diagnostic; no plan or connection record is emitted. An admitted destination's applied `json` and `jsonl` result contains exactly one public connection record with `connectionId`, `destinationType`, `name`, `routed`, `settingsVersion`, and `transport`. `human` output reports the configured connection and configuration generation. Every mode derives from `agentscope.cli.destination-configure.v1`. Credential values are never output.

## Automation

Unknown settings, duplicate slots, missing required slots, credential-shaped settings, and an unavailable or malformed referenced variable fail before the atomic write. `--credential-env` resolves only the exact named variable for preflight and stores only its CI environment reference; the credential value is never copied into configuration, output, or diagnostics.

JSON, JSONL, and non-terminal invocations never prompt. Supply the complete declared set with `--credential-env`; partial environment assignments are not completed interactively. Credential rotation remains unsupported.

## Diagnostics

- `configuration.conflict`, `configuration.missing`, and `configuration.unavailable` describe the Core configuration boundary.
- `destination.capability-unavailable` means the alpha does not admit this destination capability; refusal precedes plan or mutation.
- `destination.connection-exists` rejects duplicate names.
- `destination.credential-unavailable` means credential input or resolution could not safely complete. Fixed boolean facts can indicate an observed configuration commit or a need for reconciliation; failure does not imply that an already-started mutation was undone.
- `destination.lifecycle-busy`, `destination.lifecycle-outcome-unknown`, `destination.lifecycle-reconciliation-required`, and `destination.lifecycle-unavailable` are closed Local lifecycle outcomes.
- `destination.type-missing` rejects a type absent from the first-party registry.

## Examples

```bash
agentscope destination configure local-sqlite --name local-history
agentscope destination configure local-sqlite --name local-history --yes
```
