Unconfiguration removes the connection and its routing selection atomically. It never deletes a Local SQLite database or other destination-owned data. Local SQLite first returns a read-only retention plan; `--yes` presents the plan, preserves the database unchanged, and returns the opaque retained-delete selector needed by a later fresh process. Credential-bearing connections first require the proof-bound credential retirement lifecycle.

## Syntax

```bash
agentscope destination unconfigure <name> [--yes] [--output human|json|jsonl]
```

## Output and exits

Without `--yes`, `human`, `json`, and `jsonl` report the plan with `applied: false`. On apply they report the committed generation, `dataPreserved: true`, and the retained selector using `agentscope.cli.destination-unconfigure.v1`.

## Automation

This command is safe for local data retention but is not equivalent to data deletion. Use the separate confirmed delete command for an exact owned file.

## Diagnostics

- `configuration.conflict` and `configuration.unavailable` describe the atomic write.
- `destination.connection-missing` rejects an unknown name.
- `destination.credential-removal-required` prevents orphaning a referenced credential.
- `destination.lifecycle-busy`, `destination.lifecycle-outcome-unknown`, `destination.lifecycle-reconciliation-required`, and `destination.lifecycle-unavailable` are closed Local lifecycle outcomes.

## Examples

```bash
agentscope destination unconfigure local-history --yes
```
