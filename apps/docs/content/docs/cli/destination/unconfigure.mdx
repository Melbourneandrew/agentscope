Unconfiguration removes an admitted connection and its routing selection
atomically. The 0.1.0 alpha does not admit Local SQLite, so it offers no Local
retention plan, applied lifecycle result, or retained-delete selector. By
default, stored credentials and the configuration backup are retained.
Explicit `--retire-credentials` requests the canonical complete-connection
retirement: both configuration reference sets must be proved free before
deleting the exact owned stored set. Partial or uncertain proof does not permit
deletion.

## Syntax

```bash
agentscope destination unconfigure <name> [--yes] [--retire-credentials] [--output human|json|jsonl]
```

## Output and exits

In `human`, `json`, and `jsonl` modes, admitted non-Local connections report
the committed configuration generation using
`agentscope.cli.destination-unconfigure.v1`. Stored retirement never implies
destination data deletion.

## Automation

This command is not equivalent to destination data deletion.

The original foreground 60-second allowance includes all credential work; cancellation and expiry do not start a fresh cleanup window. A fixed failure may retain committed or uncertain work for reconciliation. `--retire-credentials` is not a rotation operation and is not applicable to Local SQLite.

## Diagnostics

- `configuration.conflict` and `configuration.unavailable` describe the atomic write.
- `destination.connection-missing` rejects an unknown name.
- `destination.credential-removal-required` prevents orphaning a referenced credential.
- `destination.lifecycle-busy`, `destination.lifecycle-outcome-unknown`, and `destination.lifecycle-reconciliation-required` are closed lifecycle outcomes.
- `destination.lifecycle-unavailable` means no admitted Local lifecycle handler is available.

## Examples

```bash
agentscope destination unconfigure langfuse --yes
```
