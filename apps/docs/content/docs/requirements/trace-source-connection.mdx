## User flow

```bash
agentscope configure reporter langfuse
agentscope install codex
agentscope status
```

The configuration flow selects a reporter, validates its settings, stores secrets through the platform credential store where possible, and creates a named trace-source connection. A connection binds a reporter implementation and a configuration profile; it does not bind a user to a single harness. The non-secret configuration lives at `~/.agentscope`.

## Requirements

- Configuration is machine-scoped by default at `~/.agentscope`; `AGENTSCOPE_HOME` is the explicit override for isolated tests and CI.
- The CLI accepts interactive setup, non-interactive flags, and environment-backed secret references for CI.
- Reporter credentials are validated with a minimal health check that does not emit a production trace.
- Multiple named connections may coexist; a routing policy decides the active connection(s) for each capture.
- Config files contain references and non-secret settings only. The doctor output masks all credential-like values.

The initial Langfuse connection supports OTLP export. Direct Langfuse ingestion can be another reporter implementation later without changing harness adapters.

Read the [configuration directory requirement](/docs/requirements/configuration-directory) and [lifecycle blueprint](/docs/blueprints/configuration-directory) for persistence, migrations, and cleanup rules.
