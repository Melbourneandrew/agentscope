## Goal

The overall goal is an agent scope system as a way to capture agent traces from coding agents CLIs and report them to external services like Langfuse.

AgentScope is an installable observability control plane for **agent harnesses**: Codex, Claude Code, Gemini CLI, OpenCode, Pi, OpenClaw (CLAW), Hermes, and future coding-agent runtimes. It is not an LLM provider SDK and it is not a replacement for the harness. It makes the harness's work observable without changing the work it performs.

## Product surface

| Surface           | User outcome                                              | Primary owner               |
| ----------------- | --------------------------------------------------------- | --------------------------- |
| `agentscope` CLI  | Install, configure, inspect, repair, and query AgentScope | `@agentscope/cli`           |
| Harness adapters  | Translate a harness's native hook/artifact model          | `@agentscope/harness-*`     |
| Trace core        | Normalize, redact, queue, and deliver trace batches       | `@agentscope/core`          |
| Reporter plugins  | Send normalized traces to a destination                   | `@agentscope/reporter-*`    |
| Retrieval plugins | Optionally search a destination through the CLI           | reporter package capability |
| Docs and SDK      | Explain configuration and enable third-party extensions   | documentation + packages    |

## Required outcomes

- Capture must fail open: a broken hook, network, or reporter cannot block an agent session.
- Each trace has the best available session, harness, model, timing, usage, Git branch, commit, worktree, and workspace context.
- AgentScope must identify the **effective Git branch** at hook time, including detached-head and worktree cases, and record an explicit unavailable state rather than inventing a value.
- Secrets never appear in hook arguments, spool files, diagnostics, or exported telemetry.
- A user can install one harness, configure one or more destinations, inspect capture health, and retrieve traces when the configured destination supports retrieval.
- The same normalized semantics apply across harnesses; adapters own extraction, not the meaning of a session, turn, model call, tool call, or error.

The architectural decisions behind these outcomes are in the [reporting](/docs/blueprints/trace-reporting), [retrieval](/docs/blueprints/trace-retrieval), and [harness integration](/docs/blueprints/agent-harness-integration) blueprints.
