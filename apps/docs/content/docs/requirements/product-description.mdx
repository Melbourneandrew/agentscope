## Business Problem

Coding-agent traces are fragmented by harness and destination. Developers cannot reliably compare sessions, investigate a failed agent run, or add an observability destination without rebuilding integrations.

## Current State

Agentscope has a CLI-first monorepo, normalized trace model, initial harness adapters, an extensible reporting boundary, and a hermetic test foundation. The public CLI and destination packages remain in development.

## Personas

- **Coding-agent user:** wants session context without manually editing opaque harness hooks.
- **Platform engineer:** wants consistent redaction, destinations, and setup health across machines.
- **Extension author:** wants stable SDK seams for harnesses and reporters.

## Product Description

The overall goal is an agent scope system as a way to capture agent traces from coding agents CLIs and report them to external services like Langfuse. Agentscope installs safe harness integrations, normalizes meaningful events, and routes redacted traces to configured destinations.

## Success Metrics

- Supported harness installation succeeds and is reversible in a disposable environment.
- Every supported harness has hermetic real-executable integration coverage.
- Capture failures do not interrupt a coding-agent session.

## Technical Requirements

- **REQ-OVR-001:** As a coding-agent user, I want one normalized trace model, so that traces are comparable across harnesses.
  - **AC-OVR-001.1:** When a supported harness emits observable activity, the system shall normalize it into portable trace primitives.
- **REQ-OVR-002:** As a platform engineer, I want extensible destinations, so that observability backends can evolve independently of harnesses.
  - **AC-OVR-002.1:** When a reporter plugin is configured, the system shall receive already-redacted normalized trace data.
