## Overview

`agentscope doctor` helps a user find a broken installation without exposing credentials or making unrequested destructive changes.

## Terminology

- **Safe repair:** a reversible, conflict-checked change whose target and prior content are provably Agentscope-owned.

## Requirements

### REQ-DOC-001: Actionable diagnostics

As a user, I want to understand why traces are missing, so that I can repair setup quickly.

- **AC-DOC-001.1:** When `agentscope doctor` runs, the system shall inspect supported harness discovery and version evidence.
- **AC-DOC-001.2:** When `agentscope doctor` runs, the system shall inspect owned hook integrity, executable identity, and duplicate-hook conflicts.
- **AC-DOC-001.3:** When `agentscope doctor` runs, the system shall inspect configuration validity and mutation recovery state without modifying either.
- **AC-DOC-001.4:** When `agentscope doctor` runs, the system shall inspect credential-backend availability and reference resolvability without reading a credential into output or diagnostics.
- **AC-DOC-001.5:** When `agentscope doctor` runs, the system shall inspect bounded pipeline health evidence and destination-declared non-mutating reachability probes.
- **AC-DOC-001.6:** When `agentscope doctor` runs from a Git workspace, the system shall inspect effective Git context without changing the repository.
- **AC-DOC-001.7:** When a finding is produced, the system shall provide a stable code, severity, sanitized evidence, and suggested next action.

### REQ-DOC-002: Explicit repair authority

As a user, I want repair to be limited and deliberate, so that diagnostics cannot damage my configuration.

- **AC-DOC-002.1:** When `agentscope doctor --fix` runs, the system shall only perform documented safe repairs on Agentscope-owned state.
- **AC-DOC-002.2:** When a repair would replace a vendor hook, rotate credentials, or delete user configuration, the system shall require a separate explicit command.
