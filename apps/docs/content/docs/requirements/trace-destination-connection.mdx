## Overview

Users configure a destination once, then install compatible harness integrations that route traces to the selected connection.

## Terminology

- **Connection:** a named reporter configuration and credential reference.
- **Trace Destination:** a configured local or remote trace repository or service. It provides mandatory reporting and may provide retrieval.
- **Native trace source:** a harness transcript, hook payload, journal, or artifact from which Agentscope captures trace evidence.
- **Reporter:** a destination package component that accepts normalized trace batches.

## Requirements

### REQ-CONN-001: Configure a destination

As a user, I want to configure Langfuse through `agentscope`, so that my harness traces reach my selected project.

- **AC-CONN-001.1:** When I run `agentscope destination configure langfuse`, the system shall validate non-secret settings and store the connection under the resolved Agentscope configuration home.
- **AC-CONN-001.2:** When credentials are required, the system shall use a credential store or explicit CI secret reference.

### REQ-CONN-002: Reusable routing

As a platform engineer, I want named connections reusable across harnesses, so that destination policy is not duplicated in every integration.

- **AC-CONN-002.1:** When multiple connections exist, the system shall let a routing policy select active connection(s) without modifying harness-specific extraction.
- **AC-CONN-002.2:** When no connection is selected by the routing policy, the system shall report a stable non-content diagnostic and shall not choose a configured connection implicitly.
- **AC-CONN-002.3:** When routing selects an unknown connection, the system shall reject the invalid configuration before hook-time delivery.
