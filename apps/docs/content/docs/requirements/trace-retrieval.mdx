title: Trace Retrieval
description: User requirements for optional destination-backed trace search.
---

## Overview

Where a destination exposes a query API, Agentscope should make delivered traces discoverable through the same CLI without claiming that every reporter can search.

## Terminology

- **Retrieval capability:** an optional destination package capability that maps portable queries to a provider API.

## Requirements

### REQ-RET-001: Search supported destinations

As a developer, I want to search traces by meaningful context, so that I can investigate an agent session without switching tools.

- **AC-RET-001.1:** When `agentscope traces search --destination <name>` targets a configured destination with retrieval capability, the system shall accept portable filters including time range, harness, branch, model, session, and tags.
- **AC-RET-001.2:** When a supported result is returned, the system shall show destination identity and portable trace summary fields with redaction applied.

### REQ-RET-002: Honest unsupported behavior

As a user, I want clear feedback when a destination cannot search, so that I do not mistake local state for remote trace history.

- **AC-RET-002.1:** When `--destination` is absent, the system shall return a usage result and shall not select a destination implicitly.
- **AC-RET-002.2:** When `--destination` names an unknown connection, the system shall return a stable unknown-destination result.
- **AC-RET-002.3:** When `--destination` names a connection without retrieval capability, the system shall return a stable unsupported-capability result.
- **AC-RET-002.4:** When any destination selection fails, the system shall not fan out to another destination implicitly.
